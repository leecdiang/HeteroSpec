# 普适性、创新性与后续决策

判断日期：2026-10-12。基于固定 PR91 的独立 CPU 审计、PR93 的 B570 审计，以及下列直接相关原始文献。本文是作者决策材料，不是审稿结论，也不构成首创性认证。

## 哪些目标成功、哪些需要收缩

| 目标 | 当前判断 | 论文可用措辞 |
|---|---|---|
| 修复从单一家族迁移 | 明显前进：冻结 scope/k 在 RTX 三家族上全部保持完整参考输出 | 在指定运行栈、三家族和确认面板上验证了同一修复配置的迁移 |
| 所有模型/平台都获得投机净加速 | 被当前观测反例否定：RTX SmolLM2 和 B570 为稳定负例 | 净收益受实际验证几何、draft 工作与单位成本共同限制 |
| 已建立普适修复定理 | 尚未实现 | 输出一致性的有限确认；不是内部数值状态相等或任意输入保证 |
| mask3 是跨家族最小修复 | 尚未证明；旧16-mask factorial 只覆盖原 Qwen 探针 | 保留历史有限搜索中的 inclusion-minimality，不外推新三家族 |
| 可预测的 break-even model | 本轮未完成；计数充分、完成阶段费用不可识别 | 描述性工作量证据与已测费用边界，不称预测模型 |
| 已有足够独立的新方法贡献 | 仍需明确与近邻工作的差异 | 以相位限定 query-layout 修复及其机制证据为候选核心，不能仅靠审计规模 |

因此，普适性之路并未整体失败：修复迁移证据变强，普遍正加速这一更强目标需要放弃。创新性不能由更多正确实验自动获得；如果最终只剩“浮点改变输出”和“高接受率不保证加速”，目前不足以支撑强创新主张。

## 与直接相关工作的实质重叠

以下是有针对性的原文核对，不是穷尽式相关工作综述。仅比较作者实际公开主张，不依据论文标题推断实验优劣。

| 原始来源 | 已有贡献及与本工作的重叠 | HeteroSpec 需要具体交代的差别 |
|---|---|---|
| [Defeating Nondeterminism in LLM Inference](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/)（2025） | batch 变化、reduction order 和 batch-invariant RMSNorm/matmul/attention 已被明确讨论 | 我们在哪些图/相位局部约束 attention，保留哪些批处理工作；不能以发现浮点非确定性为新意 |
| [LLM-42 v2](https://arxiv.org/html/2601.17768v2)（2026） | fixed-shape verifier 加 verify–rollback，将执行状态一致性和数值 reduction schedule 联系起来；保留 fast path | 我们的直接 query-layout/phase 修复与其运行时 replay 调度是什么关系；不能笼统主张首个“固定形状保一致”方法 |
| [Correctness Forensics for Batch Speculative Decoding v4](https://arxiv.org/abs/2510.22876v4)（2026） | 诊断 ragged batch 中位置、mask、KV 同步错误；EQSPEC/EXSPEC 明确同步不变量，仍报告浮点残差 | 本工作的单请求数值执行路径/状态交互与多请求 ragged 对齐故障不同；必须定位新增的可检验命题 |
| [Lossless but Not Free](https://arxiv.org/abs/2607.17283v1)（2026） | 消费级硬件上的多种后端配置有正有负；直接识别串行 verification 和 draft/target 费用差距 | “正确且高接受率仍可变慢”已不足为新意；需要修复机制或更具体、可验证的预测贡献 |

这些重叠提高了创新门槛，但不证明已有方法覆盖我们的全部实现。当前尚无统一环境中的方法间性能比较，不能声称优于上述工作。不同精度、硬件、参考路径和任务的论文数字不能直接排名。

## 应保留的连贯主线

建议将主张集中到：**定位数值执行路径与保留状态的交互，构造相位限定的 query-layout 修复，在保持其他批处理工作的同时验证参考输出，再用匹配目标路径测量投机的真实增量成本。**

已有 RTX 图变换把 query 维从列转成 batch 维，保留 projection/FFN/output 的批处理；四相位 scope 控制修复位置，图复用键区分约束模式。旧局部交叉干预和有限 factorial 提供机制来源，新三家族确认提供冻结配置的迁移证据。它们各自回答不同问题，不能把新确认写成旧机制已经在三家族逐项复现。

B570 可提供另一实现中的边界案例和物理工作对照，不宜包装成相同修复在第二平台上的普遍成功。性能主表应以 R/M 与 M/C 分开呈现：前者含 prefill/path 变化，后者是匹配目标路径上的投机增量。Qwen/Llama 的正结果、SmolLM2/B570 的负结果共同约束使用范围。

这一主线仍有可投稿的系统方法/实证贡献空间，但“可投稿”不等于创新性已经充分，负结果也不会自动提高论文价值。核心是从局部实现中提炼出明确方法、适用条件和可证伪的预测，而非把审计流程当算法。

## 设计是否过度防御

完整输出配对、保留负例、禁止确认后选 k/mask、区分 M/C 与 R/C 都应保留。它们确保研究问题明确；没有证据表明这些判据制造了 SmolLM2 或 B570 的实测慢速。正式请求也没有新增强制同步。

需要修正的是对成本模型的要求：**预测盈亏并不必然要求完整请求 wall 能拆成互斥、可加的阶段时间。** 把这一条件当成唯一准入，会让异步重叠系统中的可用模型被过早排除。已有 lite enqueue 时间仍不足以冒充完成时间，但未来可以选择带显式重叠/关键路径项的模型，或只预测边际请求费用，而不是强求所有阶段精确加总。

观测开销也不应说成已经为零。已有四模式配对是有限工程探针；正式结论针对 counts 通道，不从费用中扣除噪声差值。若要发表低个位数百分比收益，额外的 observer 与独立会话稳定性证据会比更多同一会话重复更有价值。

## 优先顺序与停止条件

1. **现在收尾，不重跑整套确认。** 合入审计证据需遵循仓库既有流程；当前 PR 保持 Draft。论文下次整合替换旧的“仅 Qwen”边界和性能主表，同时保留历史 factorial、局部因果和宽度失败作为其各自实验。最新 Qwen1.134924、先前1.106和历史约1.035不是配对版本提升。
2. **先完成方法差异论证。** 在现有源码和实验上明确局部 query-layout 的适用条件、与全局 batch-invariant kernels / fixed-shape replay 的差别，以及为何保留非 attention 批处理。若只能写出一个已知原则的特定工程实现，就应降低方法创新主张，不能用扩家族数量弥补。
3. **只补对主张有判别力的一条证据。** 若核心是修复方法，优先选能区分本方法与最接近修复方式的同参考对照；若坚持预测模型为核心，才单独设计完成时间/重叠可识别的少量校准，使用未参与拟合的确认集评估方向和误差。不要把已经查看的本轮确认集再称作未来模型的全新盲测集。

不建议为让 SmolLM2 变正而盲目调参，也不建议再增加一轮广泛审计。当前最紧迫的缺口是创新差异和模型识别能力，而非正式请求总数。
