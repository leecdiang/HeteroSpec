论文修订附带的 `POST_REVISION_EXPERIMENT_PLAN.md` 提供了桥接研究问题和一个预算示例。其固定八会话、逐槽 warmup 数等不作为本次工程启动的硬门槛。执行者先核实硬件、已有资料、运行时成本与可用预算，再提交适合本机的确认性计划；正式开始后按该版本执行，不根据效果大小或显著性追加样本。

PR #142 的自然输入分层研究与这里的固定已暴露面板桥接是不同研究。保留其缺覆盖/预算阻塞，不让它阻塞本轮独立任务，也不借本轮结果宣布其完成。PR #143 已补齐 B570 prefill 时延结果，旧稿的“尚无完整 timing”不再用于决定是否补跑。

## 每个平台的最低交付

1. 可定位的源码/补丁、构建命令、工具链与实际加载模块身份，说明历史完全匹配或新构建重新资格两种状态。
2. 至少一个真实 Q/K/V/mask 阶段样本及期望输出，一个完整请求样本及端点/停止状态；同时提供重放命令与实际原生回执。
3. 一个干净目录的复制/哈希校验和原生复现结果；完整权重、构建产物、批量原始张量按仓库现有数据政策存储，Git 中保留恢复方法与校验值。
4. `RESULT.md` 写明完成、失败、未执行三类事实；`RESUME.md` 给出准确的下一步。RTX 另交桥接的冻结计划、全部请求、配对统计和不确定性。

完整 GPU 发布材料的身份与执行资格分别验证。文件哈希通过只能说明传输完整；真实重放通过后才能报告原生复现成功。
