# History producer and resident-cache source audit

This is a read-only source/receipt audit for the PR224 successor. It executed no native model binary, forward, model/GPU context, placement action, GPU request, or historical experiment. No N runtime was built or qualified here. No current resource permission, running process, actual native head, or free-generation trace is inferred from these files.

SOURCE_AUDIT.json records seventeen source objects, fifty-eight exact source fragments with one-based inclusive line ranges, full-source SHA-256 and byte counts, two historical B2 receipts, and four ELF identities independently hashed as files. Each excerpt file is the exact bytes of the stated source lines, with no added line labels. Full source files and ELF/model bytes are not included. The real server root appears only in PRIVATE_PATH_MAP.json, which must not be published. All public paths use the HS_ROOT placeholder. No credential, GPU UUID, or foreign-job information was collected.

## What actually exists

The original Linux reference frontend is bound by its unchanged full-file SHA in the JSON. Lines52–53 hard-reject n_ctx other than1024. Lines69 and83 clear memory before every case/input. Lines86–92 stop at EOG or cap with the last sampled token recorded as pending rather than decoded. This is not a C4096 independent sequential conversation reference; changing a JSON field cannot establish one.

The existing original-stage04 and later M2/B2 service wrappers accept complete pretokenized prompt_ids. Their resident mode retains model/context allocation but resets KV at the start of every request: original-stage04 worker lines152–156; M2/B2 worker lines152–157. M2/B2 worker lines172–175 start that complete prompt at position0. There is no next-user prompt constructor, canonical history serializer, raw-token history store, or natural multi-turn episode state machine in these inspected entry/service paths.

The M2 entry is explicitly k3/k7, reserve8 and draft/replay/producer scoped (lines38–41). The B2 entry instead restores state/frontier before q4pair/q8 equal-work operations. Its historical PLAN records16 workers,64 warm and64 measured operations, all8 requested outputs and identical_state_restore_before_every_operation=true. Neither should be described as deployed natural multi-turn reuse.

B2 ADMISSION_02.private.json hashes to f59d9372ff646fb785ea80e3ed37e8b7ecc79b85f1c6ab91a4141d0d737101eb; PLAN.json hashes to9a9b9fc3366a4fc32a2eacc3e31a5220e702ceb1f937d9694546b77f95d703e6. ## A, B and C are different contracts

A is the frozen supplied-history, canonical-template, common-full-rebuild contract. Its existing negative N0 evidence is not modified by this audit. Under the fixed nonthinking template, the next canonical past-assistant rendering omits the previous generation prompt's empty-think stub. A full-prefix mismatch does not by itself prove that every legal prefix before the first difference is unusable.

B would retain actual generated token IDs and required serialized fragments as the next input. No B conversation producer is implemented by the inspected HeteroSpec experimental entry/service paths. However, parsed text history alone does not imply that a runtime discards the actual generated tokens or KV. The pinned upstream tools/completion/completion.cpp is a real source-existing general incremental producer: it formats a new message through common_chat_format_single and stores the message text (238–245), decodes into the same ctx/session_tokens (643–647), holds each actual sampled ID for subsequent decode (668–677), stores the assistant text at interactive EOG (778–792), then tokenizes and appends the newly formatted user suffix (867–887). This can preserve a resident raw generation history even though the parallel semantic message history is text. It is not built, deployed, configured or qualified as HeteroSpec N.

That helper's common_chat_templates_inputs defaults enable_thinking=true (common/chat.h261), and common_chat_format_single does not override thinking or pass chat_template_kwargs (chat.cpp653–679). Therefore a B prediction under the exact nonthinking N0 flags remains a new, unimplemented adapter contract. Keeping the old empty-think stub changes A's canonical next input tokens. No A-equivalent reference result or request semantics can be assumed from B's cache preservation.

The separate modern tools/cli path posts all JSON messages to /v1/chat/completions (cli-context.cpp350–365), storing parsed assistant content and optional reasoning_content (626–633). On the server those messages are rendered as a full prompt (server-common.cpp1337–1341). The server retains its previous prompt/token/KV state after normal release: release calls reset (server-context544–565), but reset does not clear prompt or seq KV (369–407); prompt_clear is a separate operation (334–340). Thus the modern CLI can reuse raw cached state through token LCP despite its JSON history, rather than constituting proof that no resident cache exists. It is a different producer flow from the legacy completion tool.

C has an actual upstream source basis for canonical token-LCP reuse with tail truncation. The pinned server computes the token common prefix when cache_prompt is enabled (server-context.cpp lines3201–3203), retains only that prefix (3398), and removes later KV positions (3423–3428). If the new prompt is wholly cached it backs up at least one token to obtain logits (3387–3389). This allows exact canonical next input IDs to be retained while recomputing the changed suffix, rather than preserving obsolete template tokens. It is source-supported behavior, not an already built, deployed, configured or qualified HeteroSpec N server.

The pinned source identity from pins.json and SOURCE_LOCK.json is ggml-org/llama.cpp commit0cae43063cf15170e91a2ff4d034da0ecef4a1b2. Original cached source files were hashed directly; the official repository's raw bytes were not independently downloaded in this audit. The SOURCE_LOCK itself says SOURCE_PORTED_NOT_BUILT and native_build=NOT_RUN. Those source availability statements must not be promoted into a deployed service claim.

## Required source-level flag and stop distinctions

The pinned common defaults are cache_prompt=true, n_cache_reuse=0, ctx_shift=false, n_keep=0 and use_jinja=true (common/common.h453,571,626–638). Server task defaults agree; server-schema515–529 copies global settings then evaluates request overrides (535–547). These are source defaults, not observed deployed configuration. A C design must freeze explicit cache_prompt, slot selection/identity, number of slots, cache save/eviction/checkpoint settings, n_cache_reuse, ctx_shift, n_keep and template/parser/thinking options. Slot selection can save/load/clear prompt cache (server-context1600–1655); unified-cache pressure can clear an idle slot (1667–1689). Context shifting and chunk reuse are separate optional algorithms, not part of the simple LCP proposal: context shift trims and changes positions (2893–2954); n_cache_reuse can move later matching blocks (3209–3275). Do not silently enable them.

The HeteroSpec reference/target-only service code samples finite argmax and stops on vocabulary EOG or the input cap, with no stop-string parser or reverse-prompt injection in the audited source. The later shared service's relevant lines are worker124–128 and176–182; the original service's k0/no-draft loop is168–174. Full-file lexical checks for antiprompt, additional_stops, stop_strings and find_stopping_strings are recorded, all zero. This statement concerns those service routines, not the separate upstream tools' behavior; the M2 entry itself requires draft=true and is not a new k0 N runner.

The upstream server has additional producer semantics: server-common.cpp1150–1163 handles client stop strings and1335–1357 appends the template's additional_stops; server-schema483–499 falls back to server antiprompt when no effective stop is supplied. Its generation loop can also stop for context capacity and configured prediction/time/other limits. The legacy completion tool has reverse-prompt and interactive EOG/EOT handling (completion772–795,878–887) and optional context shifting (545–594). These policies must be explicitly declared rather than imported as though they were already the HeteroSpec EOG/cap contract. A modern server supports an explicit enable_thinking=false kwarg (server-common1308–1319); the old completion helper inspected here does not pass that override.

## Pending, trim and output ownership

M2/B2 worker lines176–182 sample and commit a token before deciding whether another decode is needed. Its terminal receipt records output IDs, EOG/CAP and final KV bounds (214–215). The final sampled token can therefore remain unmaterialized. In upstream server source, process_token records sampled (1833–1841); only the next iteration's handle_last_sampled_token batches and appends it (504–540). EOG stops immediately (1952–1956;3869–3875). A raw response token list is not the materialized cache.

The existing Context::trim(int keep) is exactly worker line130: llama_memory_seq_rm on sequence0 from keep to the end, with a failure check. It does not itself update a future conversation's message history, pending ownership, reference producer or output-frontier validity. A new N adapter needs those rules explicitly. PhaseContext copies requested full vocabulary outputs into owned vectors (lines40–52) and checks actual append placement/extent (55–56); this is useful machinery, not proof of the unimplemented multi-turn lifecycle.

C must reuse at most the actual materialized matching prefix, remove invalid suffix before appending, and materialize any needed pending/template tokens once. Exact canonical input IDs do not prove numerical/state equivalence across different call histories. Any future reference and all four candidates must use the same predeclared producer, trim/rebuild/reset and output rules; verify full vectors, all active KV/frontier and pending/state, not just argmax or terminal tokens. A convenient cold replay cannot replace the independently frozen sequential R.

## Strong whole-rechunk is not a fixed32 outer caller

PhaseContext receives ids and position directly, derives per-row append requirements (lines20–31), and uses maximal refplan::plan(rows,32) for SIMPLE (35). LOCAL retains fixed32 projection groups with local attention handling (36). Current M2/B2 service passes the complete prompt directly (worker174), so it must not be described as first cutting every prompt into fixed32 calls. A future N adapter still must show that it passes the whole legal append into the strong rechunk planner. Actual native append heads, physical extents, C4096 placement and trim behavior remain unobserved for N.

The common_chat_format_single helper (common/chat.cpp653–680) returns a text substring at the previous rendered byte length; it does not prove a token-prefix invariant. The C chat-template API (llama.h1207–1225) explicitly does not use the Jinja parser and supports recognized predefined templates. Neither is a verified replacement for the pinned N0 Jinja/tokenizer pipeline.

## Scope of the next CPU comparison

It is legitimate to report a source-backed, unimplemented canonical-LCP-trim counterfactual against frozen A and a separately labeled raw-history B prediction. Supplied-history/teacher-forced predictions are not true free-generation streams. None of the supplied bodies, EOS choices, predicted cache heads or reconstructed schedules establishes actual native execution or full-reference compatibility. CPU geometry can identify a question worth qualification; it cannot qualify N1 or authorize its GPU budget.

The exact source bytes, line locations, hash checks and historical receipt identities are in SOURCE_AUDIT.json. Run node verify_audit.js for CPU-only local fragment/integrity verification. This rechecks the delivered excerpts and recorded binding equality; it does not rerun tokenization, full original-source reconstruction, models or GPU checks.


Full-file digests and excerpt digests are different fields: full_file_sha256 binds the complete cached source; fragments[].sha256 binds only the delivered exact line-range bytes. The local verifier can recheck the latter, while independently checking the former requires the original cached source or a verified identical upstream file.
