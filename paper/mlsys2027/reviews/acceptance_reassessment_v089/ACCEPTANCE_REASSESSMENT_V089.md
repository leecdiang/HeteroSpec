# HeteroSpec v0.8.9 接收门槛复评与优先建议

日期：2026-10-03。结论：**Share with caveats；接收竞争力仍需修订。复评 Complete within stated scope，非完整独立复现。** 本轮仅新增审稿意见和既有记录分析，没有修改稿件、编译新版本或执行模型/GPU实验。

## 1. 当前结论

**目前不能称为“有把握 accept”。证据支持程度已比较扎实，主要瓶颈是系统贡献的分量和用途。** 两个独立模拟视角在相同冻结稿件上形成不同判断：

| 视角 | 推荐 | 置信度 | 决定性理由 |
|---|---|---|---|
| 系统贡献 | 3/6，weak reject | 4/5 | 完整轨迹预测真实，但尚未充分展示它如何改变一次具体调试、修复或复现任务；容量级 UB2 挑战者较弱。 |
| 证据与结论 | 4/6，weak accept | 4/5 | 对有限诊断主张的前瞻测试、完整数组和成本边界足够支持；没有发现推翻当前主张的有效性错误。 |

这不是实际委员会意见，也不是两个独立机构的复现；两者使用相同模型体系和材料。不得将分数平均为接收概率，或把旧版本五份弱接收意见算作本轮票数。两份意见在未阅读旧审稿结论的情况下形成。分歧应保留，不能靠继续收集模拟票数消除。

**最强接收理由：** 基本正确性门禁只能回答是否兼容，不能解释不兼容输出会是什么。B570 的冻结、无 draft 预测程序预测了完整非参考输出；RTX 在相同提示集合上区分两个总分相同的候选，保留了可成功复现的更丰富描述。成本研究随后约束可行优化方向。这是一篇有实证支持的有限系统诊断论文。

**最强拒绝理由：** 数值/批形状敏感性、正确性排查和完整成本约束已有近邻工作；冻结预测增加可信度，却不会自动增加机制新颖性。B570 使用同一目标数值栈，RTX 成功 replay 保留了相近的状态机；失败的 UB2 容量标签并没有匹配实际 occupied forward 历史。当前可以说“这些执行描述够用或不够用”，但不能说已经得到最小描述、唯一原因、可移植方法或实际修复收益。

## 4. 优先问题与具体改法

### P1：把“足够的描述”变成可以执行的诊断任务

位置：主稿 §4.1/§4.3、§7 和 Table 6 前两行。问题不是结论错误，而是读者尚难看到执行描述能省掉哪些复现依赖、支持什么排查动作。

**Fix (Proposed)：** B570 行明确写“在该冻结栈上，复现这组 capped native 输出可去掉 draft 加载、proposal 生成与 native speculative 外层，保留已测试 UB1 target-only 路径和完整数组校验”；RTX 行明确写“该容量级 UB2 程序不够，保留顺序 proposal tape、自己计算的目标决策与 KV reconciliation 的 replay，作为已验证复现器”。分别列出输入、保留/移除依赖、输出校验以及下一步允许的排查动作。不要编造调试耗时节省或宣称 native drafting 因果无关。

### P1：主文提供一个完整预测/候选鉴别的紧凑实例

位置：主稿 §4、Figure 1、Table 2；附录 A7/A18 及实际留存 tape/events。

**Fix (Proposed)：** 用一条 B570 非参考轨迹及 RTX /15、/18、/25 的对照展示输入→首差异→剩余输出范围→完整 endpoint equality；加入上表的失败程度。若实际 V4 留存 event/tape 包含相应字段，再展示一个 proposal/accept/correct/bonus 转换，标清 replay 自己计算目标决策。无法从记录确认的 forward shape、KV 细节不能当成观测补写。当前附录 V2 /17 的例子不能直接充作 V4 个案。

这项改动应占用主文空间，不能继续把决定接收价值的信息放到附录。官方 CFP 明确评审不必读附录。

### P1：把负结果组织成优化机会预算

位置：主稿 §5.2、§6.2、Table 6；附录 P。

**Fix (Proposed)：** 加入 358H 与 headline 同单位的条件上界及 16.28%/15.52% target-work 预算；突出 M4 仅 0.069% 的两固定模式机会。正文回答“下一步要改变哪个成本/进展前提，才值得继续”，而非继续加总失败率和 scope 声明。RTX 0.677351 属于带日志的 post-prefill 边界，不能借此声称 logging-free 性能。

### P1：明确独有贡献，减少用证明材料代替系统价值

位置：摘要、§1、§7、§8/Table 7。现有贡献顺序和输入合同已经改善，不建议再次整稿做抽象重排。

**Fix (Proposed)：** 以一个首要贡献统领：前瞻完整非参考轨迹预测用于检验具体执行描述；成本预算作为后续工程方向的约束。近邻差异强调“完整未来输出 + 候选鉴别 + 具体复现用途”。不要把 shape 数值变化、正确性门禁、成本测量、observe/diagnose 工作流本身说成首次发现。正文压缩不改变结论的历史过程/重复 provenance，保留每项主张旁的一次关键边界；详细账本继续在附录。

## 5. 若目标是“大幅”增加把握，最有价值的新证据

上述现有材料改法能使接收理由更具体，但**不能保证从边界到稳接收**。如果改完后最强拒绝理由仍是“预测没有带来足够额外系统知识”，最有价值的扩展是**一次能证明诊断用途的决定性对照**，而非增加更多提示、GPU、模型或又一个弱挑战者。

推荐的首选方向：用已验证的简化 reproducer 隔离一次真实差异或候选修复，展示它能指导定位/回归检查，并在 native 路径重新确认。收益在于证明“复现描述改变了一个工程任务”，不要求最终得到更快 decoder。没有现成真实差异/修复案例时，不能人为制造成功故事。

另一方向：预先定义真正匹配实际 occupied forward/状态历史的 RTX target-only 挑战者，与 proposal-conditioned replay 比较。先写清允许输入、冻结规则、轨迹端点和判别结果；先验无法区分就不值得执行。不能在看到答案后挑一个候选再称为前瞻测试，也不能仅用相同 UB 容量冒充 trace 匹配。

**B570 是否进一步做：当前有限主张不需要补实验。** 若明确转向因果机制，才考虑在旧四条 H1 分歧轨迹的首差异状态上匹配 prefix/KV/proposal/sampler，单块干预后使用共同 continuation；旧新队列的第 64 位 fork 与持续 UB128 continuation 不回答这一问题。此协议能有区分力之前不要启动。正结果、负结果或仍不能区分都必须允许；不保证获得 causal witness。

以上都是新增研究，不是当前结论的逻辑修补必需项。本轮保持 B570/RTX/358H/M4 CLOSED。logging-free RTX 成本只有在生产性能成为核心主张时才优先；独立模型/栈只有在可移植性成为核心主张时才优先。不建议同时启动三个扩展。

## 6. 下一轮的验收目标

先完成一次基于既有材料的成批改稿，再编译/验收，按下面问题检查是否真正增强贡献；不要用反复模拟投票代替这些证据：

1. 读完主文，读者能否准确写出 B570/RTX 各复现器的输入、可去掉的依赖和成功判据？
2. 一个 worked case 是否让读者看到完整未来输出预测比 reference gate/首差异签名多提供了什么？
3. 358H/M4 是否分别给出同单位、条件明确的优化机会/最低改变预算？
4. 对四篇最近邻的差异，是否落在具体系统知识而不是冻结记录严谨性本身？
5. 如果仍无法回答“它改变了哪一次工程诊断”，是否选择一个预先有区分力的用途对照，而非继续局部补证？

这轮完成后再看最强拒绝论点是否被实质削弱。若主要差别只在文案更精确，接收风险依然存在，不能报告为稳 accept。
