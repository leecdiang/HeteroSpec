# B570 next study: pay for speculation with actual target parallel savings

## 0. Research decision

Separate two hypotheses:

**T-PARALLEL:** reference-compatible target execution is useful with or without a draft.
**D-PROFIT:** after target optimization, verification savings exceed draft and all
state/lifecycle costs relative to an equally optimized ordinary M.

PR64/82 already attempted resident phase binding. Residence, fixed arithmetic,
contracts and extra checks are not new contributions by themselves. A prospective
contribution is a reusable, structure-driven execution mapping with demonstrated
cross-structure capability and useful complete-cost efficiency over SIMPLE.
LOCAL is not required to win. A strong simpler result changes the implementation.
Do not turn a null result into a success by adding evidence volume.

Base is PR187 `b01040d3b303abfc31c5ce2dbcb100cac7490b27`. Preserve #175 null AUTO,
#187's six-arm negative and Qwen capacity failures, #64/#82 historical outcomes.
Do not alter the running RTX #188, old references, arXiv or repository visibility.
No rental, third-platform study, automatic PR merge or new model download.

## 4. Stage C: make real target parallel work, not just larger logical calls

SIMPLE: boundary-aware/re-aligned whole-graph execution with the strongest available
reference-compatible Vulkan arithmetic paths. LOCAL: local compatible attention
groups while retaining wide compatible projections/FFN. Both use the same fixes,
resident lifecycle and valid graph reuse. There is NO CUDA loop4 transplant by name.

Read actual dtype/strides, head dimension/mapping, precision choices, cache
occupancy/physical extent and original phase-specific arithmetic. Reuse PR165's
F32-activation mapping and PR169's d64/p021 or GQA AV mapping only when that
reference phase actually requires it. A scalar continuation contract does not
imply every reference prefill uses the scalar arithmetic path.

First establish q2 (k1 verification) and q4/q32 known-token prefill as applicable.
No universal width sweep. Count unique occupied target micrographs and rows,
logical verify calls, accepted tokens, rollback and actual graph rebuilds. If q2
still executes two width1 micrographs, record that fact; do not infer target
amortization from acceptance or caller width. Inspect the bottleneck before
adding natural samples. Do not global-cap LOCAL prefill at four rows for convenience.

Development uses the four fixed exposed controls plus source-required edge cases:
physical extent boundary and adjacent no-crossing, tail1/2/3, accept-all bonus,
first and later rejection where k permits, rollback, cap1/cap128, EOG, reset and
post-rollback continuation. k1 cannot exercise j1 rejection within a cycle; use
an explicitly separate synthetic/protocol k3 test if needed, never claim natural
k1 coverage of that branch. No arbitrary forced proposals in the clean workload.

Full conditional vectors include off-greedy proposal prefixes where they are
actually verified. Derive committed prefix independently from emitted endpoints
and transaction branches. Keep the requested logits/frontier before graph reuse
can overwrite them. Never compare only candidate-derived history to itself.

## 5. Small economic pilot and decision

Default resident pilot: all six `S_M,L_M,S_D1,L_D1,S_D4,L_D4` on four fixed
exposed roots, two counterbalanced blocks, each with immediate same-arm warmup:
48 measurements +48 warmups. D1 uses the stronger H1 whole-prompt/UB1 draft
caller, not just the weaker token-at-a-time baseline. D4 uses caller4/UB4 and
legal2+1 tail. Keep a C4U1 caller-only development check after lifecycle changes;
if changed overhead is material, retain it as a named additional frozen control
rather than crediting the combined gain solely to physical width.

Keep k1, target mapping, resident history and full service definition fixed while
changing draft. Proposal/acceptance variation is reported, not hidden.

For comparable diagnostic windows, compute

  M_service - D_service
    = (M_target - D_target) - (D_draft - M_draft) - (D_other - M_other).

This is a descriptive identity of observed work, not a counterfactual proof.
The primary decision uses CLEAN complete service including reset/sync, phase
bind/reserve, dispatch, state maintenance, sampling and response completion.
Model load and offline qualification are separately disclosed; genuine online
checks/fallbacks are inside service. Both M arms receive all common legal fixes.

- A numerically qualified candidate with provisional net service opportunity can
  enter a new frozen confirmation. Check both total and equal-root directions;
  report the exposed nature of this gate. No mandatory 3%/5% publication threshold.
- Target method useful but all D slower: pursue T-PARALLEL only; freeze a small
  target-only comparison if it tests new capability, not duplicate earlier results.
- Resident D slower and measured draft dominates: close D-PROFIT for this candidate.
  Write a concrete new draft hypothesis/budget before any change; no automatic
  k/width/cache/overlap/MMA sweep within this protocol.
- Numerical failure: repair from actual mechanism and requalify development;
  do not call a candidate impossible solely because its first implementation fails.

No frozen-panel continuation until the candidate, all strong controls, complete
cost window and common policy are operational. Normal engineering is autonomous.
