# Independent pre-execution safety scope

The frozen #227 CPU preparation and #226 reference contract were read before running any test executable. The ancestor lifecycle tests define only a local mock backend, compile against the standard C++ library, and include no model, CUDA or native-runtime headers or shared libraries. The Python budget/writer/source-gate tests use local synthetic files; writer interoperability invokes only the pure Node raw-byte comparator. This inspection does not qualify a source-bound native implementation.

No real-linked executable may be launched here, including `--help`, a default-deny path or a selftest. Dynamic-loader constructors can run before `main`, so source-level permission checks alone do not make such execution safe. Native-linked objects and binaries may be compiled/linked and inspected with static tools such as `nm` and `readelf`; only separately linked, inspected mock executables may run. No backend init, model load, context creation, placement or forward is permitted by this CPU task.

The native denial must happen before constructing a native backend object or invoking backend initialization, model/context creation or placement. The ancestor Session constructor's virtual `is_mock()` check occurs after the caller has already constructed the backend; it is not itself an adequate native factory gate. Writer synchronization and active-KV capture also need the admitted context/operation gate rather than a hidden alternate entry point.

Every actual placement, context/worker start, request and decode callsite must be covered by the durable controller budget. Charge/reserve before mutation, preserve failure consumption, and poison after an uncertain/partial decode or failed trim. Only a prospectively named caller-injected no-mutation fault may exercise common rebuild. An unexpected native failure cannot silently retry by reset/rebuild. A crash or uncertain journal/writer transaction must prevent reentry, not merely retain numerical counters while allowing a new operation.

Original reference identity and arithmetic remain essential. The frozen original frontend uses `n_ubatch=1` with a whole-prompt API batch; it must not be described as an original caller issuing one `llama_decode` per input token. A separately frozen C4096 descendant must retain the audited reference arithmetic and document any checkpoint/API-call organization change. The modern producer runtime is not a substitute for that reference backend. Compilation or successful source hashes do not establish resident/cold numerical equivalence.

All 261 frozen checks must map to actual new code and evidence without changing the original requirements: 162 aligned-state checks, 27 resident prior-terminal-to-next-retained-prefix checks, 36 ownership checks and 36 individual empty resets. Cold sessions have no prior-KV-retention check. Retention must compare previous real active K/V bytes against the next prefix using the correct original stride; matching heads or two newly produced paths is insufficient. Every native check remains NOT_RUN until separately authorized truthful captures exist.

Current resource admission must use a fresh target-host snapshot and the actual new writer's byte/file bounds. The historical cloud snapshot, the earlier conservative storage calculation and a prior resource window are not present host admission. This review grants no GPU request, placement, model operation, native numerical qualification or timing authority.
