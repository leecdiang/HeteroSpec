# R1：系统贡献与工程决策独立评审（v0.8.7）

**评分：3/6，弱拒绝。置信度：4/5。**

我认为目前写出的有限实证结论基本成立，未发现已证明的中央有效性错误（P0-V）。弱拒绝来自系统贡献的接收门槛判断（P0-C）：新增知识确实超过事后观察一次 argmax 翻转，但主要仍是特定实现、特定候选与有限工作集上的预测和排除结果；其对系统设计的新增影响，比论文的实验和证据管理复杂度小。这里不把新算法、成功优化、独立数值内核、唯一根因或跨硬件普适规律当作此类测量论文的必要条件。

## 我理解的贡献

这是一篇围绕“可预测的轨迹、指定参考的直接 ID 兼容性、可获利的完整执行”开展的有限系统测量与诊断论文，三者不是同一个性质。

1. B570 在发现集选择无 draft 的 target-only UB1 假说，随后冻结 72 个完整预测数组，再观察 24 个保留 prompt 的 live speculative 输出。全部预测匹配，包含四个预先预测的非参考轨迹；UB128 参考仅匹配 60/72（正文第 1、5 页，§5.2、图 2；附录第 5–7 页，§J、表 A6–A7）。
2. B570 新队列上的同状态分叉改变分数，但不改变采样检查点的即时决策；持续 UB128 续生成在另一端点上改变部分完整轨迹。RTX V4 则在同一组 19 个 prompt 上前瞻性比较 UB2 target-only 与 proposal-conditioned replay：前者 51/57，后者 57/57（正文第 6 页，§5.2–5.3、表 3；附录第 12–13 页，§Q、表 A18）。
3. RTX V4 对同组 prompt 新执行三路径成本研究：batched 因 ID 不匹配被阻断，serialized 57/57 合格，但记录的含 instrumentation 的 post-prefill 延迟仅得到 0.677× 加速比（正文第 7 页，§5.4、表 4）。358H 给出完整成本分解与固定进展/target 工作的零 draft 上界；M4 Guard 经直接 ID 资格检查并获利于 target-only，却慢于固定 Always-Spec（正文第 7–9 页，§5.5、§7、图 4、表 5）。

## 优点

**最有价值的科学增量是可失败的完整轨迹预测，而非再次报告路径敏感。** B570 在 live 前冻结全部 ID，后来任何位置、长度或端点错误都能推翻预测。四个参考分歧 prompt 尤其有信息：它们使“预测只是复制参考”无法解释成功。发现集与保留集、假说冻结与数组冻结被分开，这是比事后挑选一次 token 翻转更强的证据。它支持该无 draft 程序在该队列上具有预测充分性，不等同于 draft 在 native live 中因果无关。

**RTX V4 修复了一个有意义的比较缺口。** 同组 target-only UB2 竞争者失败，两个 replay 程序成功；/25 与 /18 的不同失败还说明相同的 51/57 汇总值不能把 UB1 参考与 UB2 预测器视作同一输出路径（正文第 6 页；附录第 13 页表 A18）。这确实排除一个事先指定的有限假说。稿件同时明确程序/API orchestration 独立与共享 llama.cpp/GGML/CUDA 数值例程的区别，没有声称独立数值实现。

**成本与资格终于在一个 RTX 三路径研究中相遇。** 统一计时可执行文件、相同工作集、每个条件均占据每个顺序位置 19 次，以及同研究的完整 ID 检查，使表 4 有别于把历史 proxy 和新资格门混成一个交易曲线。serialized 没有任何 prompt 获得加速，是明确的有限工程失败；batched 不合格的时间没有冒充可用优化。

**负结果的解释较克制。** 358H 的不等式给出一个具体必要条件：在当前实测进展与 target 工作不变时，减少 draft 和残余成本仍不足以实现总时间 parity。M4 对 Always 的比较说明“比 target-only 快”不能证明 Guard 有增量价值，且 fixed-mode oracle 的机会极小；没有把 fallback 频率包装成有益决策比例。分叉实验也没有把 0/72 即时改变写成整段生成无影响。

**证据边界披露充分。** 历史 text-path、直接 ID、预测、采样即时效应和持续续生成效应被明确分开。重复相关、曝光条件化队列、日志开销、省略二进制、匿名时间顺序的能力边界、M4 元数据恢复和失败 V3 均在正文或附录出现。这些披露增强可信度，不能代替我未进行的原始证据审核。

### P0-V：未发现

我没有找到使当前中央有限结论不成立的已证明前提失败。特别是：

- 预测成功没有被转换成 reference qualification；RTX 57/57 replay 也没有被转换成“history 必要”。
- B570 延迟差异来自持久 UB128 后续策略，正文明确不能归因于单个检查块，且该队列不是旧 H1 四个分歧 prompt。
- RTX 计时明确含条件相关日志；0.677× 被限定为记录的 instrumented post-prefill request boundary，未推算生产吞吐或无日志性能。
- 358H 零 draft 上界被限定为总时间算术、固定 baseline/进展/target 工作，未冒充 prompt-GM 或持久化优化实验。
- M4 policy-freeze 字段错误被披露为元数据记录缺陷和恢复过程；PDF 未提供可信外部时间，不因此自动推断科学策略被重调。

### P0-C：新增诊断约束的系统重要性尚不足以明确跨过主轨门槛

定位：正文第 1–2 页贡献列表，第 7 页 §6，第 10 页 §8–10；附录第 13 页 §Q.3–Q.4。

最强的新知识是“B570 的这个 UB1 target-only 程序足以预测保留轨迹”与“RTX 的这个 UB2 程序不足以预测另一有限队列”。但 B570 的部署否决已经由 reference/live 失败给出；完整预测进一步提供的是诊断表征，而不是新的可用路径或更有效的定位步骤。RTX replay 按 proposal-conditioned 验证语义运行并共享数值例程，它排除了完整应用编排必须相同的解释，却没有把必须重现的状态/执行历史缩小到一个经过判别的工程集合。这个局限不使 57/57 无效，但限制其新增解释价值。358H 与 M4 各提供有用的有限排除，却与前面的轨迹预测没有构成同一个被检验的设计命题。

因此我的疑问不是“为什么没有一个普适原因或正向优化”，而是当前有限结果是否让一个系统工程师能做出比已知的直接资格检查、完整成本测量更有区别的下一步选择。§6 列出的多项否决是正确的，预测研究实际改变了哪项调查优先级、排除了哪项原本合理的工程解释，仍不够显眼。多个有效小研究的并列，尚未使合并后的新增知识重量与篇幅相称。

**请求改变：** 用现有结果重写贡献与 §6，把“已有失败门本来就能决定的事项”与“完整预测/同组判别才新增的约束”逐条分开，并说明这种约束为何对该系统问题有独立价值。可以缩短不直接服务这一增量的历史 case inventory，把核心判别和实际工程后果放在前面。此举不需要新执行；它会帮助判断价值，不能保证解决重要性上的分歧。

### P1-2：给 RTX V4 本身一个绝对成本尺度，保持 instrumentation 边界

定位：正文第 7 页 §5.4、表 4；附录第 12 页表 A17/§P.4，第 13 页 §Q.4。

正文只显示 V4 比率，附录的绝对 prompt-median 表 A17 却属于旧 30-prompt 成本研究。请从现有 V4 B 时间记录增加 target/serialized 的绝对 prompt-median 分布或一个简洁范围，具名为 19-prompt V4，并把 request 数、EOG/cap 组成与 timer 边界邻近呈现。不要把旧 A17 作为新 V4 的绝对时长尺度。这样读者能判断 47.6% 相对延迟损失在记录的系统边界中意味着什么；无需新计时。

当前没有测出日志的总成本，所以不能声称 logging-free serialization 也一定更慢。稿件已经基本保持了这个限制；建议 §6 的“reject measured serialization”始终紧邻“within the instrumented boundary”。绝对时间补充改善工程解释，不消除 observer 开销限制。

## 评审规则 A–E

**A．最强结果在回顾性观察之外新增了什么科学推论？**

B570 在发现阶段确定的 UB1 target-only 程序能在 live 前给出 24 个保留 prompt 的完整 capped ID 轨迹，包含四个指定非参考轨迹。这是对一种有限预测表征的前瞻性验证，排除了“只有看到 live 后才知道偏离”及“复制参考就足以解释成功”。它没有证明唯一数值根因或 native draft 因果无关。RTX V4 加上另一个被否证的有限推论：在这 19 个 prompt 上，指定 target-only UB2 不能充当完整 live 轨迹代理，而 sealed proposal-conditioned replay 在共享数值例程下可以。

**B．在有限范围内可以做哪些具体决策？**

| 结果 | 有限工程决策 | 不能据此决定的事项 |
|---|---|---|
| B570 H1 72/72 P、60/72 Q | 不把该 live 路径当作 UB128 lossless 替换；可优先用 UB1 target-only 轨迹作为该次诊断的预报基线。 | 不能断言所有 draft 交互无关，或从预测成功推出性能/参考资格。 |
| RTX V4 UB2 51/57、replay 57/57 | 放弃该 UB2 作为这组完整轨迹的充分代理；保留 proposal-conditioned replay 作为该路径的复现工具。 | 不能要求所有 target-only 假说失败，或证明 history 必要/最小。 |
| RTX V4 batched blocked、serialized 0.677× | 该三路径集合没有已测出的快且合格方案；当前 instrumented 边界中 serialized 不值得作为延迟优化。 | 不能给无日志部署或其他 batch/draft 配置作性能判断。 |
| 358H 固定条件 B/T < 1 | 只减少 draft/残余成本不足以达总时间 parity；还需改变 target 工作、进展或相应基准条件。 | 不能断言持久化没用、NPU 本质不行，或 target 改变后仍满足同一上界。 |
| M4 Guard/Always > 1 | 不能宣称 Guard 带来增量收益；在此记录的聚合目标下固定 Always 更好。 | 不能把两固定模式 hindsight oracle 当作任意切换策略的下界，或宣布自适应控制一般无效。 |

**C．当前写出的结论是否逻辑上必须新增执行？若是，哪项前提失败？**

**不必须。** 我没有找到依赖缺失的新执行才能成立的当前中央前提。我的拒绝建议不以 rerun 为条件，也不以补一种算法、模型、硬件或生产吞吐实验为条件。若作者要把 RTX 0.677× 外推为 logging-free deployment 性能，则缺少 observer 成本可移除/可忽略的前提，才需要相应新对照；当前稿件未作此强主张。

固定包要求不让 fan policy 阻断研究。附录第 13 页 §Q.2 的原 strict-host stop 与 predictor 记录、live 前授权的 amendment、同一 228 个 predictor 观察复用等披露应保留。我不以该 amendment 要求 rerun，不把它认定为数据污染；同时也不宣称 fan 的物理影响已被独立证明无关。

**D．既有材料修改是否可能足够？哪些？重要性是否仍属判断？**

足够修复上述 P1：从 V4 B 现有时间给绝对尺度，明确新旧 cost study 身份，列出预测成功/失败实际改变的诊断约束，压缩重复历史和限制叙述。现有数据也足够保留所有已写的有限结论。是否足以被主轨接收仍是重要性判断：不能把材料更易检查等同于新增发现更重要，我目前仍偏弱拒绝。

**E．当前版本有哪些阅读摩擦或缺乏支持的措辞？**

主要是 H/Q/P、UB128/UB1/UB2 参考、旧 0.646/新 0.677、多套 timing 边界与失败历史的密集切换。表 A9 的旧“matched cost”名称、旧绝对时间表与新 cost study 的距离、贡献里的较宽“causal and transfer”表述是最具体可修事项。摘要与结论已避免“预测即资格”“replay 证明 history 必要”和“Guard 有增量优势”等大幅过度主张。我未发现必需通过扩大任务数才能修复的 unsupported 中央措辞。
