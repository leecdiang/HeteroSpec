Two cases are fixed by `freeze.py` from the existing four development episodes: first predicted equal partition and first predicted unequal partition. Neither case is selected from numerical or timing results. Sources and exact token sequences are in MANIFEST.json. These are supplied-history/teacher-forced trajectories and source-token continuation, **not real free-generation outcomes**. The old first-user canonical prompt is prefetched with original sequential reference arithmetic, then the supplied assistant body is materialized incrementally in the same context. Its terminal EOG is logical pending, not a fabricated materialized token. The next canonical request is unchanged. Retain the actual materialized LCP, trim its tail, discard the old pending and invalidate the borrowed frontier, recompute the entire canonical suffix, then materialize the same eight fixed continuation tokens. Reset only between episodes.

The first executable chain is R → independent process repeat R → independent cold canonical. Each owns one model and one C4096 context; no candidate may start before these strict gates. R/repeat compare every requested full F32 vocabulary vector and every captured active F16 KV byte, including initial prompt, old history, trim and continuation states. Cold independently computes the canonical prefix and suffix. At the post-trim boundary resident frontier is invalid: compare active KV there, then compare every full suffix/continuation vector, Q-end KV and each continuation KV. Do not compare stale resident logits against cold prefix logits. All36 layers, K/V,8 heads,128 dimensions, dense seq0 positions are captured. Native finite checks and independent full raw-byte comparisons are mandatory. Token identity alone is insufficient. Trim preservation is checked with proper old/new tensor-head strides.
