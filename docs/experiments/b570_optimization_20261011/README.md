# B570 自主核验与正向优化方案

状态：**设计及 CPU 工具已交付；本 PR 没有执行 B570 推理，也没有确认 B570 可加速。**

目标是在 Intel Arc B570 10 GB 上找到输出正确、能胜过较快普通推理的实际配置，并提交可复核的方案。允许根据探索结果改进实现、选择配置；选择后用独立新题确认，保留全部负结果、失败和搜索成本。

本方案继承 [PR #83](https://github.com/leecdiang/HeteroSpec/pull/83) 的第三家族研究背景，**是新的优化研究，不执行其六日期或全部 Q8 pair 固定规则**。不覆盖 [B570 #82](https://github.com/leecdiang/HeteroSpec/pull/82) 和正在运行的 [RTX #84](https://github.com/leecdiang/HeteroSpec/pull/84)。两会话可在同一天连续完成。

先做 Qwen3-8B Q8 / Qwen3-0.6B（Q8 或 Q4_K_M 草稿）；Llama 8B Q8 / 1B 草稿作为独立第二项，仅在实际显存核验通过时推进。保持目标模型 Q8，草稿量化是显式探索变量。先验证平台，再做有限探索，只有有希望的候选才进入正式确认。

阅读顺序：[研究依据](RESEARCH.md)、[协议](PROTOCOL.md)、[机器规则](POLICY.json)、[资产](ASSETS.json)、[交给 B570 的执行提示词](EXECUTION_PROMPT.md)。[工具说明](../../../scripts/platform/b570_optimization_v1/README.md) 提供静态核验、机器计划、候选选择、确认分析及防错测试；实际推理驱动由 B570 执行端依据恢复的 native 程序实现并冻结。

平台核验或有限探索结束后，执行端必须先提交一份带证据的 **B570 可行方案 Draft PR**。通过门槛可继续自动执行已冻结的正式研究，并更新该结果 PR；未通过则交付具体阻塞或无收益结果。无需 AI 每分钟轮询：本地控制器负责预算、断点、日志和完成状态，AI 只在工程决策、封存和最终交付介入。

## 已知证据

- B570 #82 的 SmolLM2 完成 560 个请求，普通 R/C 为 0.54614，C 比普通推理慢约 1.83 倍。它仅通过 endpoint 比较，N/C 有 raw suffix 差异；不把这一旧结果改成正向或完整原始输出等价。
- RTX Qwen 第一会话四轮的中途观察：R/C3_K3 = 1.55621，M3/C3_K3 = 1.10052，24 题完整输出一致；匹配路径比较有 6 题变慢。第二会话及其他家族尚未完成。RTX 的 R 使用 UB1，此值不能证明 B570 上胜过 UB128 普通推理。详见 [固定中途快照](RTX_INTERIM_CONTEXT.json)。Qwen 优先级受到这项已查看结果影响，新的确认题必须排除当前 RTX 全部题目。
- Llama Q8 pair 文件总量约 9.18 GiB，加 KV 和工作区可能超过 10 GB。静态估算只作警告；是否全 GPU 可运行必须由 B570 的实际同进程显存、加载与工程峰值证据决定。草稿 Q4 也不保证适配。

所有正式结论以完整实际记录为准。没有正向结果也必须提交报告；不得通过弱化基线、选择较快题目、删负结果或事后裁剪输出来制造收益。
