# 待另行批准的最小 A/B/C 数值及配对计时方案

本页没有执行许可。当前用户授权仅覆盖一次 B1 无模型 bootstrap。B1 成功也只建立加载、runtime 可见 UUID 和有限观测链的证据。

## 输入和参考前置条件

首个算子描述符固定 Q8_0 权重、F32 activation、q=8、g=2、K=M=4096、无 padding、无 IDs/fusion、连续布局、graph 关闭。A 采用两次原 backend-loop4 四列 grid；B 采用原 packed 两个四列组；C 采用同 CTA 内两组独立四列 accumulator，保持原算术及归约顺序。

真实当前 q8 operand 及其原 backend 输出仍是第一轮的硬前置。启动前须冻结权重字节、完整 8×4096 F32 activation、量化后 activation、全部 8×4096 F32 输出、producer/描述符/stride/设备及原始捕获身份。模型无需常驻在配对算子进程，但生成该真实捕获的操作需要独立授权。

现有 recovered_operand 的权重 SHA 为 822086ad0b394e3f032f5a95a0193df9a6f2f628f58cee4b2d2c44ba4bb26b5e，input_q8_from_q32.bin SHA 为 3f8eb688eaa3fb2bd7f64ef60dde87ba29ae5a6e4494a8e28856b08a14e40694，历史 loop4/packed 输出 SHA 均为 34d684384e6d090a7f841ff38c00004ea1540d86040af361e7ed6e1b8d1ba767。这份输入来自旧 q32 的前八行，不能充当新的真实 q8 捕获。它保留为历史诊断资料；本方案不会用它补齐原门槛。若尚无合格 q8 捕获，算子实验保持 NOT_RUN，先提交单独的最小捕获合同。

## 数值门槛与停止

每臂运行两次，每次执行共同 quantizer 后做该臂投影。保存全部量化字节和完整输出，独立读取并逐字节比较原 backend oracle、重复运行和 A/B/C。检查输入尺寸/stride、未覆盖输出哨兵、guard 与真实 arm 标识。任一差异、非有限输出、错误设备、未知模块、丢失活动或异步错误，立即停止，禁止进入计时。该一个描述符的通过不能替代 66 格资格。

## 单次拟议预算

采用独立的算子合同、账本和一次性 attempt，零自动重试，只有一个子进程。模型、请求和 forward 为零。拟定 120 秒进程墙钟，110 秒停止新工作，末 10 秒清理；到期请求终止自有 Job。设备仍为 B1 的唯一 UUID。批准应写明具体当晚可用时段，以实际就绪状态为准，不预订。

数值检查每轮 A=3、B=2、C=2 个显式 kernel（共同 quantizer 每臂各一次，A 投影两次，B/C 一次），两轮共 14。数值检查通过后每臂一次相同 warmup，共 7。计时采用 6 个平衡顺序块 ABC/BCA/CAB/CBA/BAC/ACB，每块每臂 8 次，分别测 kernel-only 和 complete-operator。kernel-only 每臂每块仅在测量段前量化一次，再在 event 段内连续投影 8 次，共 6×(3+8×4)=210；complete-operator 为 6×8×7=336。加数值检查与 warmup 后，明确显式 kernel 提交上限为 567，单次量化/投影前原子消费额度，耗尽前停止，并从开始预留清理资源。最终编译的分支/循环必须静态核对该计数。

CUDA event 对每臂连续 8 次的批次计时，完整算子含共同量化及同步，另记 host 完整批次成本。报告六个配对块的原始值、比值和离散范围，不以六块承诺稳定的 5% 或通用收益。首批判断为存在位差则当前 C 停止；正确但相对 B 方向不稳定则 INCONCLUSIVE；正确且各块有一致可解释改善才建议进一步采样，任何扩样再获授权。

上述 567 只硬约束已审查的显式应用 kernel 提交。DLL/driver、分配/传输、事件、CUPTI 及异常清理的隐式物理工作仍无可信全生命周期上界，不能将此数称为原 4096 合同。对旧生产默认拒绝无修改。若继续要求原 4096 硬上界，则本方案不可运行。

输入张量的显式设备缓冲以实际权重文件长度+131072 字节 activation+量化输出长度+131072 字节输出计算，另保留哨兵。拟限应用自行分配总计 64 MiB，捕获上限 4 MiB，受控日志 64 MiB、Job commit 2 GiB。CUDA/context/库自己的分配不包含在显式缓冲数内。沿用 B1 的显存入场/停止水位、身份锁、单一 runner、设备采样、ETW 与 CUPTI 丢失拒绝；物理 launch/显存峰值及设备卡死后的清理仍只可有限观察。完整驱动/库身份和实际调用清单需随最终算子二进制另行冻结、审查与批准。

最终 GPU 调用范围须在源码审查后列出并批准，至少包括设备属性、一次显式 context 首次使用、四组缓冲分配/释放、两个输入 H2D、量化和投影提交、完整结果 D2H、stream、event 与同步。任何额外校准、profiling kernel、模型或 fallback 都需改提案。当前未实现该新 runner，也未运行这些调用。
