# 最新研究路线评估：PR #57–60

审阅日期：2026-10-05。作者侧审阅与派生数据复算；不是外部同行评审，也不是多位独立审稿人的意见。当前决定：暂停后续合并，保留 v0.11.0 为覆盖 #53–56 的完整基线草稿；最新方法实验继续独立推进。

## 结论

**支持有边界地继续投入。#59/#60 已明显强于旧论文的“复现、诊断与负结果”贡献，但尚未建立普适的新方法。** 最有希望的主线是“真实状态/当前路径交叉诊断 → 按模型角色与执行阶段选择数值约束 → 保留其余批量计算 → 在固定参考下验证净成本”。新贡献必须落在可迁移的约束选择、实现和失败边界上；“验证器负责正确性，草稿可以更自由”本身已有先例。

v0.11.0 的旧路线评审不能直接当作 #59/#60 的录用判断。尤其 #56 的 NO_GO_NEW_METHOD 只针对当时两个离线选择候选；它没有否定后来出现的原生局部修复。

## 哪些结果真正增加了研究价值

1. **不再只是相关性。** #59 的 48 次真实状态/当前验证路径交叉包含 24 次同路径控制。/15 在两种 donor 下均呈当前路径效应，/25 呈状态与路径交互。它支持把状态构造和当前调用分开研究；四个自然检查点不能代表整个轨迹，也没有唯一定位所有分歧的算子。
2. **有可以运行的修复。** query 维移到 batch 维的局部 attention 实现保留投影/FFN 批量计算。它在暴露的 19 任务上恢复原始参考，且严格匹配、关闭观测开销后仍有增量投机收益。相比全局串行后变慢，这是实质进展。
3. **范围消融提供了可检验的结构。** #60 的 16 组合在四探针、两轮中通过集合恰为 3/7/11/15；有限集合内最小 mask3 只约束 target prefill 和 continuation。A2 扩展到原 19 任务，A3 成本面板三条件各 114/114 通过原参考。它是固定改造家族中的有限充分性结果，尚不是全局最小性定理。
4. **负门槛被保留。** 去掉 draft 约束并没有带来达到预设门槛的新 decode 加速。报告没有用整次请求收益替换这个失败判断，这有助于可信度。

## 创新性：已有原则与尚可能成立的贡献

| 拟议贡献 | 当前判断 | 需要补齐的证据 |
|---|---|---|
| 浮点执行路径会改变 greedy 输出 | 已有领域认识 | 作为动机，不作为首创 |
| 固定验证路径、保持 KV 一致、允许 fast path 自由 | 与 LLM-42 明显重叠 | 正面比较方法假设和机制，不仅引用名字 |
| 固定 attention 的归约/分块 | 与 batch-invariant inference 重叠 | 证明 query-batch 实现及约束范围选择的具体差别 |
| 真实状态 × 当前路径诊断能导出可迁移的约束配方 | 有案例，尚未建立迁移 | 冻结流程，事前预测第二合同中的必要范围和失败边界 |
| 只约束 target 两阶段已足够 | 当前四探针/19任务成立 | 未用输入、更宽计算几何、第二模型或后端；保持失败 |
| 更小范围获得额外 decode 效率 | 当前不成立 | 新的预先设定、独立验证的改善；不能把同一面板重跑到成功 |

[LLM-42 全文](https://arxiv.org/html/2601.17768v2) 使用固定形状验证、回滚与 KV 修复，并允许快路径采用不同数值执行；还讨论位置一致性和 attention。它与当前两个不同模型的投机方案并不完全相同，但覆盖了“将确定性集中到验证”的核心原则。[Thinking Machines 的原始说明](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/) 已讨论跨 batch 与缓存分段的 attention 归约一致性。因此，仅把已有原则移植到 llama.cpp，创新压力仍然很大。

可争取的更强贡献是：**一套依据真实状态和执行几何选择约束的流程，以及其可迁移的预测、成本和失败规律。** “没有写新 CUDA kernel”不自动取消方法贡献；但“用了既有算子且跑快了”也不自动建立新颖性。当前实现没有证明所有 logits 位级一致，输出一致不能代替这种证明。

若补理论，应把目标写成条件性充分性：验证决策及继续状态等价于固定参考、KV 对齐/回滚与提交端点正确时，草稿路径的自由度不必改变已提交输出。随后明确哪些条件由实现保证、哪些只由有限实验支持。这种归纳论证是正确性支撑；不能将已有投机验证原则重新命名为新定理。

## 下一阶段：按照减少不确定性的顺序投入

**第一优先：完成 Stage B 暴露审计并锁定新输入。** 旧 RTX 账本排除了 145 个 HumanEval 任务，剩余 19 个现在也已执行。因此不能直接承诺存在 24 个未用 HumanEval。必须区分仅下载、执行/看过输出、未知暴露；未知不能当未用。若数量不足，在生成任何新参考或候选前修订面板/数据集并固定抽样规则；记录原计划为什么不可行。协议已允许事前缩减或标为 unsupported，这应直接执行，不能先跑再挑成功任务。

保持 mask3 配方与实现冻结。新任务一次完整 mismatch 就应按冻结门槛失败；保留所有时间，后续诊断另开清单。完整参考应以付费原生运行获得且不供候选使用。这个阶段能证明输入迁移；它仍不能证明模型/硬件普适性。

**第二优先：Stage C/D 检验边界。** 长度、KV 几何、验证宽度和图复用比继续刷原19任务更有信息量。先执行已冻结的 anchor，再扩大到原保护范围之外。现有 guard 只覆盖 Qwen3、FA-off、query≤4、单 KV stream；更宽投影/FFN 可能改数值路径，不能直接解除 guard 后宣称支持。保留每个宽度的输出与端点，不报告挑选出的最佳 k。持续驻留要验证 phase reset、graph reuse 和无缓存请求顺序；单槽结果不能替代多槽吞吐。

**第三优先：冻结第二数值合同和直接方法对照。** 至少选择一个能有效区分假设的新模型/后端合同，事前说明预计约束哪些阶段、何处会失败。同一家族另一尺寸主要支持尺度迁移；不同家族或后端提供更强压力测试，同时需要新的适配资格。第二合同可有自己的、独立冻结的参考，不能用候选输出建立方便的参考。

方法对照优先包含：输出合格的普通 target-only、匹配 target-only、全部约束版本、所提局部版本；再对最接近的固定形状或 batch-invariant 方案做同合同实现/可复核组件对照。不能只比较不符合参考的快模式，不能只比较被人为串行拖慢的基线。query-batch 对逐 query lowering 的贡献需要共同关闭观测包装的成本面板，旧的混合 prefill 面板不足以独立量化它。

## 继续或收束的判断门槛

- 新输入及至少一个有区别的数值合同中，冻结配方保持完整输出与端点，且相对强合格基线有稳定净收益：可以据此重构成方法论文，再评估 MLSys 等去向。
- 迁移有明确失败边界，但诊断流程能在看到候选完整输出前预测所需约束：仍可能形成有价值的系统方法/实证贡献，必须报告成本与适用范围。
- 只在已暴露19任务成立，跨合同需要按输出不断修补，或优势来自基线过弱：贡献更接近单实现工程案例，应降低普适性主张并考虑系统应用期刊。

目前属于第一条的候选阶段，不是已达成阶段。建议继续 B/C 的高信息量验证；不建议把主要预算投到 draft 约束的细碎删减，也不建议现在冻结投稿版本或给一个无法校准的接受概率百分比。
