This experiment continues [PR #59](https://github.com/leecdiang/HeteroSpec/pull/59) and the current manuscript. The Phase 1 finite RTX chain is closed: native diagnosis, real state/current-path crossing, local attention candidate, complete-output qualification and matched-prefill costs. It does not yet establish a minimum constraint, unused-task transfer or wider-width/long-output validity.

The completed first tranche finds a **sufficient target-only scope within this exposed cohort, but no practical additional decode advance**. On all19 original tasks, target-only attention constraints, all-on constraints and the matched target-only control pass114/114 qualification requests. The separate six-repetition cyclic cost panel passes342/342 complete original references.

## Reproduce the current tranche

Set `HETEROSPEC_PHASE1_ROOT` to the preserved Phase 1 workspace with its exact generated source, qualified binaries and historical reference inputs. Defaults support the sibling local `continuity-state-v1` workspace; configure it explicitly for a repository checkout. `HETEROSPEC_ASSET_ROOT` and `HETEROSPEC_RTX_STUDY_ROOT` retain the prior configurable asset/source roots. No toolchain/model installation is performed. Source bindings include the immutable input and old build identities.

1. In a fresh isolated directory, run `python base.py`, `python scope_patch.py`, then `python build.py`. Preserve any preparation failure. Freeze code/configuration in Git before inference.
2. Run `python engineering.py`. All8 old/new all-on CLI arrays must match original R. Eight selective resident requests and4 warmups verify actual multi-query graph coverage for masks3,12,5,10 and phase reset across requests. Timing is diagnostic only.
3. Freeze implementation and execute `python run_panel.py a1`:128 complete resident checks plus32 excluded warmups. Run `python analyze.py a1`. This generates an A2 selection manifest using output agreement and inclusion-minimality in the finite sentinel panel, with no timing selection. Commit it before dependent inference.
4. Run `python run_panel.py a2`, then `python analyze.py a2`. All19 tasks remain exposed, not a holdout. Commit A3_SELECTION before running cost; a `NO_NEW_SCOPE` gate stops the new reduced-scope cost comparison.
5. Only for a qualified reduced-scope challenger, run `python run_panel.py a3` and `python analyze.py a3`. Three or four conditions get six or eight cyclic repetitions, respectively. Cost conclusions require the full output gate and the predeclared practical thresholds. Both speed-positive and speed-negative results are retained.

All runs retain exact commands, source commit, binary/model/runtime bindings, full token arrays/EOG boundaries and cache0 evidence. Native service generation timers include the elapsed drafting/verification phase; full requests also include prefill, cleanup and response. Resident loading/teardown and warmups are excluded and counted separately. References/proposal tapes are offline evidence, never online candidate inputs. Normal service logs suppress detailed loader placement/UB messages; the separate CLI qualification parses these.

The scripts fail instead of automatically retrying an incomplete run. Analysis generates summary CSV/JSON from original records. Do not manually edit measurements or overwrite prior results. `generated/` and `runs/` are ignored; raw evidence is delivered as a separate local archive. Source commits are in the isolated experiment repository, not the manuscript Git history.

## Interpretation

The four-flag factorial can identify an observed sufficient scope and interactions within this fixed recipe family. It cannot prove a globally minimal numerical constraint or unique attention causation. A passing smaller scope may be slower because proposal quality and graph organization also affect cost. Qualification comes before speed, and adding constraints is not assumed monotonic.

Unused-task B requires a historical exposure audit and a manifest frozen before reference/candidate generation. Unknown history is excluded, not treated as clean. C requires a wider-graph bridge; unchanged attention alone may fail when projection kernels change at width>4. D tests persistent single-slot requests; the current one-KV-stream guard is not a multi-slot throughput implementation. No functional code accuracy, venue success or unmeasured transfer is claimed. Related fixed-verification/KV-consistency and batch-invariant-inference work from #59 remains relevant; this study tests diagnostic constraint selection, not first/unique novelty.
