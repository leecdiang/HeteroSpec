6小时，最后45分钟交付，一个 GPU worker。优先有信息量的核心，允许部分结果。

## 目标

回答三个问题：
1. 图重放能去掉多少宿主提交成本，QB/QH 的差异是否仍然存在？
2. 1024邻界在三种映射中同时变快，是否有对应的真实执行路径变化？
3. compact Q 的收益，在实际计入转换与上传后是否仍保留？

不预设 QH 必须胜出、不再拟合 selector，也不把本轮当硬件收益验证。

## 执行顺序与自由度

1. **CPU 检查与能力确认。** 运行 `python -B -m unittest -v test_cpu`。
   阅读已安装工具/驱动/后端信息。PR121 明确关闭 CUDA Graphs；本轮 ON 必须
   有实际捕获/实例化/重放证据，不能只改环境变量就写“已启用”。初始能力
   准备限45分钟，最多12个额外 GPU 能力宿主，每宿主总图评估不超过64次。
   在已有安全监督器内工作，不重建全机监管系统。
2. **时钟通道。** 保留旧异常，新查询放新 UUID。检查原始输出、字段/单位/
   locale/设备选择，条件允许时和 NVML 或 profiler 交叉核验。无法解释就保留
   UNKNOWN，禁止猜单位缩放。不能用无效时钟归一化；它也不自动否定所有 QPC
   完成成本。冻结实际可信的环境门槛，端点空闲不等于持续独占。
3. **计划与参考。** 运行 `python -B plan.py --graph dual --out <新目录>/plan.json`。
   核心6几何×2值模式：q2的1023/1024/1025、256的permuted/compact Q、q1-short。
   输入复用 PR121 对应坐标的完整字节或按原方法重建后核验哈希。重新生成
   两次独立serial-q1参考；不要混入旧结果来填新任务。按stage/optional/requires
   调度，不能无条件顺序执行全部任务。
4. **图模式与数值资格。** 各模式×12输入×PQ/QB/QH_C×两新宿主，2warmups+32次。
   保留全部输入/输出字节、实际 CUDA 归属、模块身份和同步。能力探针另做
   同一持久buffer内两模式输入值交替检查，防止图捕获后读到旧数据；它不代表
   自然请求资格。ON证据覆盖实际图签名，profile可与资格宿主复用并只计一次。
   ON不可用时可在正式计时前生成 `--graph off-only` 新计划；旧能力收据保持
   原身份。部分ON失败则保留完整dual计划的缺失，不挑成功点算完整面板。
5. **核心 clean 计时。** 每个input/block分别执行OFF与ON四arm子块：PQ、QB_A、
   QH_C、QB_B；QB_A/B调用同一QB实现。使用计划里的平衡顺序，两个实际session
   各完整4块。每宿主8warmups+30测量，稳态ON不混入捕获/重建。逐调用readback、
   完整检查和保留输出；文件/JSON移出循环。QPC完成图、readback、冷启动、分配、
   upload及capture成本分别列出。ON未核实就标MODE_UNVERIFIED，不当快样本使用。
6. **有限机制追踪。** 最多24个profile宿主（含已追踪资格宿主）、每宿主最多64次；
   profiler准备上限45分钟。先取实际CUDA timeline，聚焦长度三点及Q布局对照，
   判断提交、kernel、copy和同步发生了什么。只在支持时补深入计数器。trace数据
   与clean计时分开；没有trace就给条件成本结果，不为安装重构平台而卡死。
7. **可选完整Q转换事务。** 有预算再做P0：q2/q4各两值模式，从相同permuted
   host Q起算，比较QB/QH消费permuted或显式转成compact的四条路径。KV/mask常驻，
   预分配buffer；单段实际计时覆盖CPU copy/transpose→Q上传→计算完成→ordinary
   readback。这次不能把分别测得的CPU和GPU均值相加冒充连续事务。所有转换字节
   与参考核验；q4新增16个serial参考宿主，四路径新增32个资格和128个计时宿主。
   生产端本来产生Q的成本仍未知；不宣称实际模型可免费直接输出compact。
8. **分析和封存。** 用紧凑收据运行 `analyze.py --plan ... --receipts ... --out ...`。
   按几何、值模式、session和mode报告绝对成本、ON/OFF、QB_A/B、因素边与遗漏。
   分析器只验证收据格式/配对，不替代真实数值与模式证据审计。小效应可能仍
   未解决；P0没有相同路径重复arm，不能冒用B0的A/A来认证其精度。

## 交付边界

核心dual设计956宿主/34124次图调用；可选P0另176宿主/5968次。能力/trace额外
工作另计，复用宿主不双计，捕获过程中的图评估也计入。预算不足可完成第一组
4块后交付描述性结果，不声称完成两周期。对超时或不安全清理停止相关GPU工作；
对纯CPU格式/归档问题从保留raw修复，不重跑科学坐标。

你可以修改CPU helpers适配实际接口，但要在正式数据前冻结科学条件并重跑必要
检查。不同DLL、observer、采样/边界不能混成同一个队列。新后端构建不是完成
本任务的前提；若必须换数值栈，保留原OFF，另列可选cohort并独立资格。

输出实际代码、命令、能力/模式资格、分项表、trace摘要、RESULT.md、失败与资源
记录，推送本PR并保持Draft。raw留本地并提供哈希/位置/恢复状态，不要求远端raw
或外部审查，不把自查称独立第三方验证。完整输出可用CAS+发生记录保留。

最终说明：图重放是否改变结论；1024和compact-Q机制得到什么级别证据；转换
成本计入后是否仍值得；还有哪些系统相关性未知。继续保持硬件HOLD，除非未来
独立工作证明强软件基线之后的物理瓶颈与系统关键路径。本轮不启动自然decoder、
actor/W1、不下载权重、不改B570/论文/main、不做RTL/FPGA、不自动合并或发布。
