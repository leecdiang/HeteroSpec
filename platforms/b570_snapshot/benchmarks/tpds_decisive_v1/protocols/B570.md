# B570: actual caller/physical-width intervention under target compatibility

## Scientific base and purpose

Working base PR175 `cd5f542a851d192e21187bc00566de0f685e2383`; speculative numerical deployment comes from the previously working PR165 Qwen k1 C1024 study and its strict original R, not PR175 target-only C4096. The q32/double-context capacity failures in PR169 remain failures. A smaller target-verify q2 k1 allocation may have different admission; measure it correctly, do not assume pass or failure.

This is Vulkan, not CUDA. Do not port the CUDA-specific four-column MMVQ loop merely to make the two PRs symmetric. B570 supplies independent backend evidence about reference/producer integration and the strongest ordinary draft prefill, while RTX tests loop4 versus packing.

## A source-level issue the experiment must isolate

The old B570 driver explicitly uses singleton draft prefill callers. Physical UB4 with one-row callers is still one-row work. Therefore use these **five** arms:

| Arm | Draft prefill caller | Draft physical UB | Draft output reserve | Purpose |
|---|---:|---:|---:|---|
| M | no draft execution | original context policy | original | strongest matched target-only control |
| C1U1 | 1 | 1 | 1 | unchanged speculative implementation |
| C4U1 | up to4 | 1 | 1 | caller-only consolidation control |
| C4U2 | up to4 | 2 | 1 | extra physical batching |
| C4U4 | up to4 | 4 | 1 | full four-row prefill opportunity |

Only draft prompt calls change; preserve native final-prompt output flag, subsequent singleton DRAFT_SYNC/PROPOSE, target producer/verification, k1 acceptance/correction/trim, weights, KV precision and reference. Ordinary wide draft is a baseline opportunity, not a novel speculative algorithm.

`stage_sources.py b570-draft` implements the candidate constructor and caller schedule changes plus actual-UB checks, bound study/slot fields and recorded policies. Observer derivatives use the already available `boundary()` exporter to copy the retained-prefix row separately from serialized KV. Target constructor/reserve remains untouched. No new shaders are part of this experiment.

## Admission and bridge

Start with zero-forward admission for original M/C1U1 and each new physical width, with signed memory checks and actual original F32-activation/p021 libraries. Keep original R completely unchanged. M retains the same dual-resident model context policy initially so that target-only does not receive an artificial placement advantage or penalty; disclose the real lifecycle. C4096 target-only results are not reclassified as successful dual-resident k1 execution.

Use original/observer R, trained-model full target values and active KV/frontier on actual candidate proposal prefixes, plus independent free R. Both reference trajectories use the actual original target producer caller and flags. Reusing a source stager does not grant numerical qualification. Profile and module/ABI binding are actual host work.

If only C4U4 fails capacity/numerical eligibility, retain the failure and freeze the supported roster before new outputs; C4U1 cannot be removed because it is a strong simple control. If M/C1U1 itself cannot run safely, do not weaken admission or unload models mid-study. Close the Qwen lane with exact failure evidence, then inspect the already available Smol deployment as a **separate** originally referenced family, or stop. No model download/rental to rescue a negative result.

## Development and new natural confirmation

Four exposed development roots: compare actual caller histograms, physical microbatch and draft F32/logit behavior, target committed/conditional values, prefill speed and complete service. Preserve all EOG/cap stops and any absence of a natural rejection branch. Synthetic branch tests do not count as trained-model samples.

If the whole implementation is eligible, twelve new roots ×five arms ×five counterbalanced sessions =300 measurements +300 immediate warmups. The odd-arm design uses forward/reverse orders across paired roots and balances positions within each root. Same complete-service window includes context creation/destruction as in the original Vulkan study; model load and preload remain separately charged.

Main comparisons: C4U1 versus C1U1 (caller effect); C4U2/4 versus C4U1 (physical width effect); each versus M and C1U1 (actual speculation value). All fixed contrasts and both total-service and root-log metrics are reported. No new AUTO or continuation-threading change. A faster prefill but slower complete service is a valid negative result.

## Strong-baseline interpretation

If ordinary caller/UB tuning obtains the gain, retain it as the strongest fixed implementation and do not attribute it to numerical-contract metadata. If it still fails to beat M, stop building cache/overlap machinery on the assumption that the missing benefit will appear. Any future new kernel/packing proposal must face this fixed baseline and complete costs.

Record a result even if capacity ends the study early. This platform does not wait for RTX's freeze or import its output oracle. Cross-platform results are mechanistic replications with different hardware/lifecycle, not a GPU speed ranking or a pooled sample size.
