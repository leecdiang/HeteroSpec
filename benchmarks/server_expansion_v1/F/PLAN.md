# F — bring the existing Llama family into the final Linux method

## Why this family rather than a fourth architecture now?

Project history already contains Qwen, SmolLM2 and Llama, including original-GPU
Llama repair/confirmation in PR162/163. The final native phase-plan transfer and
recent strong-baseline service evidence concentrate on Qwen/Smol. This is a gap in
**final-method coverage**, not proof that TPDS requires a particular family count.
14B Qwen and Q4 Qwen do not add families. Do not call this first-ever Llama support.

Use the historical Llama8B target/1B draft Q8 assets by exact SHA/size in models.json.
Acquire only from approved licensed existing storage or the documented original
publisher. No unverified same-name community GGUF replacement. The acquisition URL
is deliberately null until original lineage/license is resolved, rather than guessed.
Native metadata, template, full vocabulary/EOG identity and model-pair compatibility
must agree with the archived specification. Do not pair by model-name similarity.

## Freeze and attempt transfer

Bind a source/rule freeze from the qualified Linux Qwen/Smol runtime **before any
new Llama candidate outputs**. Rebuild under the same declared toolkit/device,
then freeze a separate pristine Llama deployment reference at C1024/F16KV/noFA.
The old Windows and Vulkan references remain unchanged; cross-backend bytes are
not required equal. A different family must not inherit another model's cached R.

Run the retained CodeContests/valid/108 witness and archived controls as development,
then finite q1/4/8/32 inside/crossing/tail geometry and natural EOG/cap/reset cases.
Examine actual normalization/RoPE/attention graph requirements and dispatch, not
only head counts. Apply the same generic planner and arithmetic recipes first.
Full original requested vectors, committed active KV/frontier and pending/trim
checks must correspond to the independent Llama reference.

`transfer_check.py` compares frozen rule/backend manifests. It distinguishes
UNCHANGED source transfer from EXTENDED_NEW_VERSION. Source equality is not binary
identity or numerical proof. If a general new structural recipe is needed, retain
the first failure, repair it in a new version, requalify old Qwen/Smol controls and
label the result an extension. No model-name/output-position exception.
