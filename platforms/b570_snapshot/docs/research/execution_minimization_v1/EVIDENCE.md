# 证据支持什么，为什么有限投入这一方向

本文件把研究判断与已经完成的科学观察分开。所有计数由本 PR 的 `audit.py` 从 #56 已封存且哈希绑定的 normalized arrays 重算；没有新 inference。其原始来源和 normalization 合同由继承的 INPUT_SNAPSHOT_BINDING 指定。本次不是完整原始日志的新独立审计。

## 输出等价关系

| 有效比较 | 三次全部相等的任务 | 完整数组+边界相等的重复观察 | 判断边界 |
|---|---:|---:|---|
| RTX19 U2/N1 | 19/19 | 57/57 | ordinary target-only 覆盖指定干预的完整输出 |
| RTX19 U2/N0 | 17/19 | 51/57 | ordinary target-only 不能覆盖所有原生条件 |
| RTX19 H1/N1 | 19/19 | 57/57 | 已有复杂程序准确，但在这个目标上被U2覆盖 |
| B57024 T0/N0 | 24/24 | 72/72 | 手工draft-free程序有效，不能称ordinary U2结果 |
| B57024 T1/N1 | 24/24 | 72/72 | 手工draft-free程序有效，仍有prefill/sample/state边界 |
| RTX MBPP24 H1/N1 | 24/24 | 72/72 | 已暴露补充数据；U2全部72单元未知 |

RTX19 的 N0/N1 完整输出在17/19任务相同。/15 的首个分歧为位置15、长度25→28，并恢复参考；/25 为位置4、长度75→75，并产生新参考偏差。/18 同为69-token EOS偏差；/31 是同为128-token cap的匹配控制。前者支持选择行为改变案例，后者提供稳定控制，不能作为新的验证样本。

B570 的四个修复和RTX的相反变化说明指定干预结果不同；由于硬件、backend、研究条件与cohort一起变化，不支持“硬件类型决定修复方向”的规则。67任务上下文和1005记录均分组报告。

## 机制与实现可行性

selected RTX N0/N1 初始 state/logits相等并不证明后续live state相等。UB是容量，observed occupied graph shape是观测，kernel dispatch/operands仍是更强且缺失的证据。当前不能从这些字段得到参考恢复方向。

绑定的 `native_observer.h` 与 `worker.cpp` 已提供同步、context state导出/恢复、位置、pending处理、sampler clone及图维度观测。这降低了新增hook的实现起点成本。源码静态检查和初始handoff资格，**没有证明后续checkpoint的恢复资格或新2×2矩阵可行**；第一阶段因此是技术资格门槛。

## 方向比较

| 选择 | 现有依据 | 为什么暂不优先/为什么选 |
|---|---|---|
| 自动选择参考恢复干预 | #56 P1缺行动信号，P2与简单基线同结果且增加probe | 维持NO_GO，不以更多旧样本重复重启 |
| 立即扩大模型/硬件矩阵 | 可以增加现象覆盖 | 尚无冻结规则，先扩矩阵很容易只得到更多案例 |
| 找到唯一kernel原因 | 没有runtime operand/dispatch对齐 | 当前实现与证据缺口大；不是本有限用途的必要条件 |
| 执行简化的等价边界 | 两栈已有draft-free实例，RTX U2/N0已有失败 | 用很小的真实状态/路径对照辨别解释，再决定是否值得迁移；选择这一方向 |

选择是研究投入判断，不是已证明最优路线。最近工作已经有大部分通用数值与缓存现象；所以只有新增复现范围、可迁移合同或可辨别机制成立时，才继续扩大投入。没有承诺新方法、部署收益或期刊录用。
