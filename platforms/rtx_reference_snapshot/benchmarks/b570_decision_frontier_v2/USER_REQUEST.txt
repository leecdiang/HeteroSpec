一、复现并闭合 registry 故障，不只修一个字典键

从实际 PR105 PLAN、DONORS、首个失败 REQUEST/RESULT 独立复核：
- PLAN 应有56个逻辑 cell = 4 tasks × 2 recipients × 7 states。
- 原 task|state registry 丢失 recipient，28个 recipient A cells 与计划不符；这些不是只有一个 EMPTY 条目。
- SLOT 内 mixture_spec 被预检，实际发送的 KV 却通过 controller100.Worker.request 对 DONORS 再次查找。两条输入路径必须交叉核对。
- 请提交真正用于生成 registry 的完整、可运行纯函数，不能依靠未归档的临时 shell/Python 片段。

registry 逻辑主键至少包含 (task, recipient, state)；明确 donor = other(recipient)。
例如 legacy lookup label 可用 state+'@'+recipient，使 task|EMPTY@A 与 task|EMPTY@B 不冲突；实际形式可以不同，但整条构造/序列化/校验链必须一致。
recipient initial logits 单独绑定 (task, recipient)，同一 recipient 的七种状态使用相同完整 logits bytes。
CAS 的相同 payload 可以去重，但相同物理 bytes 不能作为删除逻辑 cell 的理由。
重复插入同一逻辑键一律报错；禁止以最后写入者覆盖前项。

实现 validate_registry_against_plan，遍历完整56 cells和168 requests：
1. task/recipient/donor/state、方向、slot id、mode/repeat/stage 都匹配；
2. 实际解析后的 KV path/bytes/SHA256 与该 slot 的 mixture_spec 一致；
3. 实际解析后的 initial-logits spec 与该 recipient 的 initial_logits_spec 一致；
4. EMPTY 的 state bytes 等于 recipient 自身；ALL 等于 donor 全 KV，同时仍保留 recipient logits；
5. 五种子集与固定 PR103 的对应 mixture bytes 相同；不得新采 donor；
6. 没有 missing、extra、duplicate、last-write-wins；相同 SHA 允许不同逻辑标签，但来源关系仍分别记录；
7. 序列化写盘后重新读取 registry 和请求，再执行同一检查；使用拒绝重复 JSON keys 的加载器审计输入。

三、审查 POSITION 双方向的坐标等价，避免把换符号当新机制

已提交 FRONTIER_ANALYSIS 中 /1248 t=47：
B->A: (r,u)=(220,832), I=-0.09655952453613281
A->B: (r,u)=(832,220), I=+0.09655952453613281
两方向 full-vocabulary residual 文件声明相同 SHA256：
b14c62a171fe89118c85ba7d07bbb1a1672442b9ea338f9dc627a688dc5d9c98
这是要从实际 bytes 复核的等价性线索，不是授权假设所有观察必然相同。

prefix和tail是全部KV数值位置的互补划分。写成 A=(A_P,A_T), B=(B_P,B_T)：
recipient A 的 EMPTY/P/T/ALL 为 AA、BA、AB、BB；
recipient B 的 EMPTY/P/T/ALL 为 BB、AB、BA、AA。
在相同 token 前缀、数值执行条件以及相同四个实际状态行为下，完整向量四格残差对这个换位不变；若 (r,u) 互换，标量 I 会变号。

新增零 GPU 的 canonical-position audit：
- 对全部已采 POSITION 比较，读取实际 mixture、FP32 arm vectors、共同前缀、第一token、sampler契约和残差文件；核对源哈希，不只读报告数值；
- 验证 EMPTY↔ALL、prefix↔tail 的反向映射；不同初始logits必须保留，不能只凭相同KV假定所有上下文均等；说明本契约中初始logits是否仅用于同一个t0 greedy选择；
- 对每一组可比较的两方向固定同一 token pair，例如将既有无序pair按token id升序规范化，不重新挑选效果较大的token；
- 保留原始relative donor指标，另外报告规范坐标结果、字节等价组和共享数据依赖；
- 标明什么是实际独立进程重复、什么是同一四格的另一种坐标表达；两者都不增加独立输入数；
- 对不同前缀、不同token pair或源状态不对应的坐标，标为NOT_COMPARABLE，不能强行去重。
这不是删除原始双方向观测，也不否定L0的背景依赖。L0之外的其余层仍可能随recipient改变，不能把POSITION恒等关系无条件套到L0。
不要把(+I,-I)自动描述成“协同机制与拮抗机制在反向互换”。
