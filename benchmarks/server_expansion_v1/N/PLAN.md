# N — reference-compatible resident conversation append

## First decision: does real geometry distinguish the methods?

The earlier OASST snapshot study and AUTO null result remain unchanged. This study
uses the final resident phase interface and full sequential conversation history,
not file-backed snapshot transfer. Residence alone is not new, nor is a natural
crossing automatically an opportunity against WB-rechunk.

For dense append, when q divides physical padding P, a rechunk caller that restarts
full q groups after a boundary needs at most ceil(A/q)+1 whole-graph calls for A
appended tokens. That is only a geometry bound, not an arithmetic/performance
proof. Use actual cache observations; do not assume every backend's extent is
simply round_up(logical_tokens,P).

## N0: inexpensive census

Use a version-pinned OASST1 conversation corpus with supplied conversation history
for the first tokenizer/geometry census; preserve the original root identities,
roles and templates. Reuse the prior source snapshot if legally available, record
its hash, and distinguish this purpose from the old timing panel. No private company
conversations. Do not select favorable offsets, crossing cases or long sessions.

`census.py` accepts effective head and append length, cache/padding and
source/tokenizer hashes. A zero-forward dense-token prediction is explicitly
labelled PREDICTED_HEAD_REQUIRES_NATIVE_CHECK; only native cache observations
may be labelled NATIVE_HEAD. It reports exact ordered whole-fixed, whole-rechunk and
local outer schedules. Provided-history tokenization needs no model generation.
Reference-generated development histories are also allowed but are explicitly
labelled exposed; they are not retroactively outcome-free observations.

Keep non-prefix, capacity-limited or unsupported sessions in the census denominator.
A live cache is reusable only for actual token-prefix identity, not string LCP.
If every relevant path coalesces or the strong rechunk control removes practically
all distinct work, deliver that opportunity analysis and integration findings;
do not run a large timing panel merely to create a new percentage.

## N1: real sequential state semantics

Use existing Qwen8B Q8, fixed C4096 deployment and a separately frozen R. No new
quantization or draft method. Begin with four exposed conversations. The reference
follows the declared sequential producer/caller history for each turn, with native
EOG/cap128, template boundaries and pending token materialized exactly once.
It is not a fresh whole-prefix replay substituted because it is easier to match.

Native implementation must handle the template suffix, true prior token-prefix
check, phase switching, output masks, frontier, pending and reset at session end.
When retokenization invalidates prefix reuse, a predeclared same-reference rebuild
path may be applied to EVERY method and charged in full; it cannot be dropped from
natural service. This is dense single-sequence work, not paged/continuous batching.

Compare equally optimized whole-rechunk+loop4, whole-rechunk+packed, local+loop4,
local+packed. Keep the old fixed-chunk control as optional mechanism-only context,
not the only competitor. All strategies receive the same legal lifecycle fixes.
Qualification compares original requested vectors and state at turn boundaries,
plus relevant local rejection/stop controls if the reused frontend contains them.

## N2: conditional natural confirmation

Only after a useful supported distinction remains, freeze16 independent conversation
roots before candidate outputs, with four arms/four sessions. Complete episode
wall/service (initial prompt, every append/response and required state work) is the
primary unit; per-turn/append time is secondary. Two separate exposed primer
conversations precede each resident worker. The plan has256 episode observations
and32 primer episodes, **not256 logical requests**: reserve the actual number of
turn requests and transient decoded rows before each worker. Protocol cap is
3072 logical requests/12M rows. Prospective source-only admission may limit the
number of turns; do not truncate after seeing costly or failing model behavior.

Matched fixed-reference history replay isolates execution but is labelled teacher-
forced replay. Natural free sessions test the actual chain and compare with their
independent sequential R. Do not count the two as independent tasks or mix their
clocks. Sessions that stop early remain. Root-cluster analysis resamples whole
conversations, not turns. Cohort growth, improved caches and new policies require
new versions, not additional samples in the old panel.

## Useful closure

The result can be supported natural resident value, conditional geometry value,
or no distinct opportunity against simple rechunking. Complete normal integration
work even if one performance branch closes; do not rebuild a cache framework to
rescue a neutral result. No AUTO, model padding, shared prefix service, multitenant
server or network endpoint. Preserve PR196 and submit an independent results PR.
