## 贡献与优点

1. **预测与资格分开，且有可以失败的预先预测。** 主文第 1、5 页 §5.2/Figure 2，附录第 5–7 页 §J/Tables A6–A7 中，H1 在暴露发现集上选择后，冻结保留集的全部 72 个完整数组。四个非参考轨迹使成功不能仅归结为照抄参考；但 60/72 的参考门仍阻止 lossless 替换。相比事后发现一个 argmax 差异，这多了有限的完整轨迹可预测性结论。
2. **V4 补齐的是同队列判别与同研究成本，而非回溯借用门限。** 主文第 3、6–7 页 Tables 1/3/4，附录第 12–13 页 §Q，分别交代 228 pre-live + 57 live 的 A、171 个新 B 条件，以及 19 个共享提示。UB2 和 UB1 都是 51/57，却失败于不同提示；论文没有用同一总计替代比较对象。B 自己完成 direct-ID gate，只对 qualified serialization 形成速度比和 CI。
3. **统计单位和估计公式正确且可复算。** 新 RTX/M4 成本均先取每条件三次时延的中位数，再形成 reference/candidate 比值及提示 GM；不是三次配对比值的中位数，也不是所有运行总时长之比。V4 配对 bootstrap 按 19 行提示、固定顺序/seed 和线性分位数重采样。论文明确重复与事件相关，不把 456 个条件当独立样本（主文第 3 页 §3.1–3.2；附录第 13 页 §Q.4）。
4. **负结果有明确、有限的决策价值。** 358H 的上界是固定测得进展、target work 和 baseline 的总量恒等式；不伪装成提示 GM、持久状态加速实验或 NPU 能力定律（主文第 7–8 页 §5.5/§7.1；附录第 11–12 页 §P.3）。M4 的 hindsight oracle 限于两种已测固定模式，且 Guard 的劣势明确呈现为 post-study paired secondary，未用 fallback 活动率代替有益决策率（主文第 9 页/Table 5；附录第 3–4、10–11 页 §H/§P.2）。

## 弱点、分级与请求

**P0-V：未发现。** 目前没有证据表明当前中央分母、数组比较、median-ratio 估计或固定条件成本上界错误。未独立认证原始 chronology 不等于已证明 chronology 错误；共享数值例程也不使明确限定的 application/API orchestration independence 无效。

**P0-C：我不设置当前接收阻断项；最强潜在拒稿理由是重要性。** 主文第 10 页 §8–9 自认数值路径敏感性、成本核算和自适应控制已有先例。B570 有效非参考案例为四个提示，V4 为两个参考分歧提示；同例程 replay 的完整复现并不给出可迁移的最小状态或新机制。严谨地验证这些有限事实是否已足以支持主会，仍需程序委员会判断，不能由“验证器 PASS”自动推出。我的判断是其预先轨迹判别与配套成本门有足够但有限的系统知识增量。

**P1：把 bootstrap 的推断对象再写明确。** 位置：主文第 3 页 §3.1–3.2、第 7 页 Table 4；附录第 12–13 页 §Q.1/§Q.4。V4 使用全部 19 个剩余曝光审计提示，这些提示不是从目标工作负载总体随机抽样。当前“95% CI”已经有 prompt-bootstrap、曝光条件及 session 排除说明，但还缺少一个直接回答“它针对哪个随机对象”的句子。固定这 19 提示和已观测中位数后，0.67735 是该有限集合的确定统计量；重新抽取提示行的区间不认证该确定值，也不覆盖 HumanEval 总体、曝光选择机制或新的运行会话。请求在 §3.2 或 Table 4 caption 补一句：该区间条件于已选曝光队列、已观察时延及冻结配置，按经验提示分布重采样；不作为总体或独立会话置信保证。无需换公式、重算主结果或新增执行。

**P2：让中心主张与证据入口的能力对应更细。** 位置：主文第 3 页 §3.3；附录第 11 页 Table A13、第 13–14 页 §Q.3–Q.5。目前入口总体说明准确，但 arrays/timer 的可复算性与 freezes、原始 endpoint parser、tape allowlist、KV clone controls 的原始可检查性要跨多页拼接。可在既有表中加“紧凑包直接重算 / 完整 capsule 查原始记录 / 仅保留 reported chronology”列，尤其区分原始字节证据与导出的状态布尔值、拒绝见证摘要。完整包已被精确索引；我不声称它们不存在，也不要求本轮读取禁用材料或独立可信外部时钟。

**已披露范围限制，不是 P0-V，也不据此要求重跑：**

- V4 的 145 项曝光排除（包含 V3 七个提示）及全部剩余 19 项使“未见过”严格条件于可审计记录；不能估计总体失败率。V3 的有效前缀和两个失败记录未进入 V4，不能被当作失踪的 V4 样本（主文第 3 页；附录第 12 页 §Q.1）。
- B 在 A 后已见过相同提示，适合冻结配置的匹配成本测试，不是新的 unseen prediction 验证集；global UB 同时影响 draft，因而不是 isolated target-only causal intervention（主文第 7、10 页；附录第 13 页 §Q.4）。
- QPC/chrono 共用 Windows oscillator；empty clock-call probe 不测全部 logging cost，observer 只检查 ID。条件相关记录开销可能不抵消，因此 0.677 只支持带记录执行边界内的判断，不能证明未记录生产执行也慢相同比例（主文第 7 页 §5.4；附录第 9、12–13 页 §N/§P.4/§Q.4）。当前措辞已遵守这个范围。
- B570 即时 fork 的 0/72 只对每次抽样的一个 common-prefix block 成立；216 分数行与 195 reachable decisions 不是独立检验。后续 UB128 持续执行并使用自己的新历史，18/72 延迟差异不能归因于抽样单块，也不能解释原 H1 的四例（主文第 5–6 页；附录第 6–8、10–11 页 §L/§P.1）。
- cap128/first inclusive EOG 是明确端点，未覆盖完整无上限生成或 HumanEval 功能正确性。没有必要为有限 direct-ID 结论加 pass@k。

## 协议顺序与修订

附录第 13 页 §Q.2 保留了 predictor capture 后的原 strict-host stop、继续执行授权以及 pre-live 修订，且写明复用同 228 个 predictor observations，不称为新未曝光复现。我的可见紧凑包只提供 freeze roles、数组和 post-study projection，无法独立验证原 F0/F1/F2、远程 retrieval、first-live 的绝对先后；论文也没有把 hash/Git 或匿名序号冒充可信外部过程时钟。M4 freeze-hash 错字段的恢复同样只能以附录第 4 页的叙述及完整包作为此处的依据，我未用时延重算冒充元数据恢复验证。

按本轮明确指令，我不把 fan-policy 影响作为 blocker 或重跑理由，也不把它说成篡改。应保留已披露 amendment；我没有独立证明该策略在物理上无影响，也不会补上这一断言。这里需要维护的是“修订发生在 live 前、预测未改”的限定陈述与证据角色，不能声称原 strict-host 协议无偏差地完成。

## Rubric A–E

**A．最强结果超过回溯观察增加了什么推断？** B570 冻结 draft-free UB1 的完整未知 live 数组，正确覆盖四个非参考轨迹，证明它对已测试路径/保留队列的经验预测充分性。RTX V4 在同队列检验两个预定义候选，发现指定 UB2 target-only 候选失败而 proposal-conditioned replay 全部一致。它们增加了可被任一后续 ID 推翻的轨迹级判别；不证明唯一数值原因、历史必要性、所有 target-only 假说失败或跨栈规则。

**B．有限范围内具体决定是什么？** 拒绝 B570 已预测但不兼容的 lossless 替换；RTX B 的 batched 不通过参考门、serialized 虽通过但在该带记录边界内不作为 latency 优化；358H 在固定 progress/target work 下只省 draft/residual 不足以达 parity；本 M4 held-out 条件优先固定 Always 而非声称 Guard 带来增益。这些决定不排行硬件，也不提供生产性能承诺。

**C．已写主张是否逻辑上必须新增执行？** 否。没有查到 exact failed premise 要由新模型执行修复。19 提示全余项、A/B 共享、共享 numerical code、instrumented timing、cap128 和修订均已纳入现有 claim 边界。CPU 检查能支持有限数组与估计一致性，不能替代真实 GPU 复现，但当前稿件也未声称做过独立 GPU 复现。

**D．现有材料修改能否足够？** 能。上面的 P1 可用一句明确 estimand 的说明处理；P2 可用现有 evidence index/capsule 角色改善可读性。无需新算法、万能 kernel 原因、更多硬件或成功的优化来维护现有结论。修改能提高评审可判断性，但不能把有限案例自动变成更重要的工作；主会重要性仍是判断问题。

**E．阅读摩擦或无支持措辞在哪里？** 主要是 §5、Table 1 与附录 J–Q 的多批 study 身份、freeze 层次和两种 median/GM 公式要来回核对。主文第 1 页的“sufficient for this path”应连同 24 提示、cap 与已测试 stack 阅读，不能脱离这些限定；主文第 6 页 Table 3 的“Independent P/R”由紧邻文本限定为 orchestration independence，宜保留该限定。未发现把 51/57 写成 Q、把 57/57 prediction 当 reference 恢复、把 score change 当即时决策改变、把 0.6µs probe 当全 logging overhead 或把 post-study secondary 当 preregistered 的现存错误。

## 必须与可选实验

**本轮必要的新实验：无。** 不要求新 decoder、独立数值实现、唯一 kernel 定位、fan-policy 重跑、普适目标或生产 benchmark。

可选扩展应由更强的未来主张触发：若要论证部署 latency，则需要可靠的低记录开销/记录开关对照；若要论证可迁移预测规则，则需预先冻结后在新任务/新栈验证；若要论证 proposal/history 必要或最小，则需针对替代候选及状态消融的判别实验；若要论证单 fork 的持续因果效应，则需单块替换后恢复原策略的控制。这些不属于当前有限论文的逻辑欠账。

## 最强接收、拒稿与最终理由

**最强接收论证：** 有完整且可反驳的 pre-live 轨迹预测，非参考案例证明预测信息；V4 同队列失败模式显示匹配总数不能替代候选身份，并以自己的新成本观察关闭资格/成本错配；358H 与 M4 的负结果给出明确实施取舍。数字可由 CPU 重算，作者对旧失败、捕获修复、协议 amendment、元数据缺陷及未识别原因有明确披露。这符合有边界的实证系统测量论文。

**最强拒稿论证：** 增量主要是极少量有限轨迹的预测复现与严格范围内的负成本结果；没有证明一般可用的 predictor 或产生新的机制性原理。即使所有有限数组都真实且统计正确，委员会仍可能认为它相对文中既有 numerical-path sensitivity/full-cost measurement 的增量不足。这个拒稿理由是 P0-C 重要性判断，不是 P0-V，也不能被包装成必须再跑一批实验才能修复的有效性错误。

**最终维持 4/6、置信度 4/5。** 从本评审的实验严谨性角度，已写有限推断可以成立，新增执行不必要。我的保留集中在 bootstrap 推断对象的直述、精细证据角色及主会增量价值，而不是错误分母或无效中心前提。
