# Existing-model producer facade: compile/link preparation only

`producer_facade.cpp` factors the operational render/token-piece/task-parser/final-response/safe-JSON/history path from the frozen `N/n1a_lifecycle_20261112/producer/producer_bridge.cpp`. It contains no main, model load, vocabulary-only model creation, backend initialization, context creation, placement or forward. It does not own or free the supplied model. It is intended to link the already factory-owned reference model with the same pinned common/server parser source; a newer CPU-only numerical library must not replace the fixed reference/loop4 core.

The constructor takes an existing `llama_model*`, a concrete final `ProductionGate&` and accounting. The gate is checked before any model/vocabulary/template access. It permanently rejects in the current build. Therefore these operational functions are compiled/linked, not executed as a new producer experiment. The constructor's future pure frontend setup is not a second model-load reservation; the actual factory remains responsible for the original guarded model/context/placement boundaries.

After separately approved admission, `initial(messages_json,request_id)` or `advance(complete_generated_ids,stop,cap,next_user_json,request_id)` must run inside the driver's already charged lazy request builder. Accounting's mutation hook requires that active request. An invalid producer request remains charged, poisons the attempt and does not fall through to a decode. Repeated initial calls, reuse of the previous request ID and unsupported routes are rejected. A separate facade instance starts a new episode while reusing the factory-owned model; it does not imply resetting native KV, which remains an explicit lifecycle operation.

The fixed subset is basic text messages with actual Jinja renderer, thinking=false, DeepSeek reasoning format, no tools/media, nonstream output, parse_special=true/add_special=false and no explicit client stops. It validates the exact4,100-byte GGUF template SHA256, vocabulary151,936 and the full six-ID EOG predicate. It does not insert an artificial EOG at cap. Visible EOG pieces, effective active template-stop strings or tool/media output block the request; no text is silently trimmed to obtain compatibility.

Complete generated IDs pass through actual token-to-piece policy, `task_result_state`, `server_task_result_cmpl_final::update`, the actual OAI final response and `safe_json_to_str` before the assistant JSON history is stored. The next user message then passes through that same renderer/tokenizer. Return values include exact canonical IDs, prompt text, wire history, opaque runtime parser configuration, wire response and parser-input bytes as hex. The facade owns semantic message history; the separate Session owns actual materialized KV/head/pending/frontier. Token serialization does not certify numerical/KV equivalence.

No facade-linked binary has been executed during this preparation. Its source-level compatibility and retained linkage are distinct from numerical qualification, a live free-generation observation or GPU authority. The standard-only component/session mocks do not load or run this translation unit.
