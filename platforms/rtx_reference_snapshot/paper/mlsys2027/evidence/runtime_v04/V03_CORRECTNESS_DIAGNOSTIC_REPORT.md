**Verdict: `UB2_INTRINSICALLY_BLOCKED_IN_TESTED_STACK`.** This is a correctness-only diagnostic of the frozen Qwen3-8B Q8_0 / llama.cpp b10839 / Vulkan0 stack, with `n_ubatch` 1 or 2 and the frozen tokenizer, formatter, greedy policy, and 128-token cap. It starts from frozen v0.2 commit `503c98f4511a4909f9e433d88e821c442634addc`. The frozen R1 observation source has SHA-256 `c2ba5ff4574df61d0a01d4ad6fc7105e19e969954674196e77eed9af3814a1c5`.

The diagnostics used AC power and preserved the Phase-3 target verification semantics. They are marked `DIAGNOSTIC / INVALID_FOR_PERFORMANCE_CLAIMS`. No R1 or R2 was run in v0.3; no timings or speedups were evaluated. The full local raw JSON traces are under `runs/358h/runtime_codesign_v03_diagnostics_20260924/`; [`runtime_diagnostic_v0_3_evidence.json`](runtime_diagnostic_v0_3_evidence.json) records their hashes and the compact token-level findings.

## HumanEval/54: target-only UB1 versus UB2

The shared-model reproducer exactly matched frozen R1 in all three repetitions for each context. UB1 and UB2 first differ at output index 26: token `73594` versus `151645`. The token-level trace matched the same frozen sequences. A new context was prefilled with the *same* prompt and UB1 reference output prefix at each index 22–27. At index 26, UB1 again selected `73594` (top-2 `151645`, top-1 margin `0.017153`), while UB2 selected `151645` (top-2 `151668`, margin `0.018255`). Both contexts had the expected KV end position.

The four execution orders `UB1→UB2`, `UB2→UB1`, `UB1→UB1→UB2`, and `UB2→UB2→UB1` all reproduced the frozen outputs after request reset. Separate UB1-only and UB2-only processes, each with its own loaded model and context, also matched frozen R1 3/3. These controls rule out the tested order, reset, and shared-model contamination explanations. The classification is **`UBATCH_NUMERICAL_PATH_DIVERGENCE`**: identical exact tokens in a fresh prefix produce different greedy top-1 tokens with `n_ubatch=1` and `2`. UB2 is therefore not exact-output admissible for this frozen target stack.

## HumanEval/48: proposal playback and state isolation

The playback harness fed the three frozen `LEGACY_NPU_UB2` proposal ledgers to the unchanged target verifier, without NPU draft inference. UB2 matched every frozen round and the full 128-token output in all three repetitions. UB1 matched rounds 0–39, then first differed at round 40 / output index 100. Round 40 has proposals `[33975,25]`, `accepted=0`, and a correction: UB1 committed `151668`; UB2 committed `32313`. Before that round, committed tokens, acceptance, logical histories, and KV end positions matched in all three repetitions. The first discrete internal difference is visible in the logits **after round 39**: UB1 top-1 is `151668`, UB2 top-1 is `32313`, even though round 39 committed the same `[63,729,1939]` and both ended at state position 193. The top-1 margins at that point were `0.084602` and `0.086468`, respectively.

A new context prefilled through output index 100 and given round 40's exact proposals selected `151668` under both UB1 and UB2. Thus round 40 alone does not reproduce the frozen divergence. A fresh prefix at index 97 followed by the exact frozen round-39 proposal also did **not** reproduce it. In a separate forced test at index 98, UB2 did produce `32313` as the all-accepted bonus for `[729,1939]`, whereas the target-only oracle and UB1 produced `151668`; this is an independent example of batch-path sensitivity, not a proof that the original trace began at that fresh prefix.

Fresh-tail playback locates the needed earlier execution history. Starting the frozen UB2 proposal tail at round 27 / output index 75 reproduces the round-40 divergence; starting at round 28 / index 76, or any later tested start, does not. Round 27 originally rejected two proposals. A controlled rerun replaced only that round with one rejected proposal or with a target-only step. All three shapes committed `151643`, had **identical recorded top-2 logits after round 27**, and still reached UB2 top-1 `32313` after round 39. Therefore the round-27 rejected-suffix rollback is not necessary for the observed divergence. Building one token incrementally from index 75, rather than pre-filling the longer prefix from index 76, is sufficient in combination with the later frozen verification path.

The forced rollback suite covered prefixes 96, 98, and 100, UB1/UB2, accepted counts 0/1/2, repeated rejection, and next-round predictions. UB1 passed 21/21; UB2 passed 19/21. The only two failed cases were the same index-98 UB2 full-accept bonus divergence, once alone and once as the first step of a longer pattern. The rejection and repeated-rejection cases passed. The inherited verifier decodes candidates at `before` and `before+1`, deletes from `before+accepted` on rejection, decodes correction or bonus at that position, and asserts `llama_memory_seq_pos_max == len(history)-1`. Playback and stress found no position drift or off-by-one witness.

The /48 classification is **history-dependent target numerical-path divergence under different prefill/decode and verification partitions**. The tests isolate it from live NPU draft inference and do not establish a specific erroneous rollback boundary or a line-level implementation fix. The exact floating-point or backend operation responsible remains unproven. No target verification code was changed.

## R2 gate and closure

The v0.3 protocol fixes `r2_authorized=false`. The R2 entrypoint now checks that flag and a frozen registry with an explicitly recognized, correctness-qualified intervention pair **before creating any formal output**. A baseline-only registry, an unrecognized pair, a blocked pair, or a UB2 pair without qualified `TARGET_UB2` is rejected. The hardware-independent gate test includes a real entrypoint invocation and verifies that no output directory is created.

The v0.2 registry remains `formal_conditions=["TARGET_UB1"]`, with no identifiable Section 7 intervention effect. **v0.2 R2 was never executed; no formal performance data exist; v0.2 remains qualification-closed.** No v0.3 R1 or R2 was run.
