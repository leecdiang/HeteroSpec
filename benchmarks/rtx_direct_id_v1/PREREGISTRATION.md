# RTX direct generated-ID qualification replication v1

This is a **prospectively frozen direct-ID replication**, a new study in the same family as the separate Arc B570 replication. Known historical observations informed its design. It does not reopen a closed campaign.

The starting main is `483c4cbd6cd72ae1cdcdbba4534a62fc1786f885`, verified after fetch, checkout main and pull --ff-only with a clean worktree. The branch is `experiment/rtx-direct-id-qualification-v1`. The exact frozen source HEAD and tree are resolved in `runtime_freeze_manifest.json` after the preregistration/source commit; the next manifest-only commit is the formal execution HEAD. This avoids a self-referential commit hash. Every execution records that execution HEAD and all frozen asset hashes.

The only question is whether serialization changes qualification of the tested RTX speculative path under full direct committed/generated token-ID sequence equality. Primary outcomes are independently classified for `RTX_BATCHED_K2` and `RTX_SERIALIZED_K2`: exactly 90/90 pairs means **QUALIFIED**; anything below means **BLOCKED**. A wholly exact prompt has three exact repetitions. Missing/failed operational records make an attempt incomplete and do not establish a qualification outcome.

`protocol_v1.json` is the authoritative machine-readable contract. It records the exact 30-task list, three repetitions, three conditions, all command templates, the complete 270-execution schedule and seed **2026092801**. Task order is numeric; conditions are shuffled within each task/repetition block using Python 3.11 `random.Random`. No observed equality enters scheduling. All executions are retained and mismatches never stop the run.

The Qwen3-8B Q8_0 target SHA-256 is `408b955510e196121c1c375201744783b5c9a43c7956d73fc78df54c66e883d6`; the Qwen3-0.6B Q8_0 draft SHA-256 is `9465e63a22add5354d9bb4b99e90117043c7124007664907259bd16d043bb031`; HumanEval.jsonl.gz SHA-256 is `b796127e635a67f93fb35c04f4cb03cf06f38c8072ee7cee8833d7bee06979ef`.

The runtime is original llama.cpp b10839, commit `0cae43063cf15170e91a2ff4d034da0ecef4a1b2`, CUDA 12.4 distribution, Clang 20.1.8 for Windows x86_64. The new host has Windows 11 and RTX 5070 Ti Laptop 12 GB with driver **616.92**. The historical driver was 616.56; the new environment is explicitly frozen, rather than represented as the historical host state. `build_manifest.json` and the freeze record identify every executable/DLL by SHA-256. No binary is rebuilt or replaced.

The original CLI already exposes direct committed IDs through `process_token` debug messages. Ordinary generation passes its sampled ID to this function; speculative generation passes accepted IDs in order and stops at EOS or the output budget. This is the exact same CLI execution path as the historical runner, with verbosity 5 and a native log sidecar. No response-only server substitution is made. Only integer IDs in these commit events are compared. Prompt-token and draft-proposal messages are excluded. Sequential n_gen=1..N, remaining budget 128-n_gen and final runtime generation count are asserted. A committed terminal EOG ID is included. The instrumentation patch is empty (SHA-256 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`), because no source instrumentation is necessary.

Decode semantics are greedy, temperature 0, top-k 0, top-p 1, min-p 0, seed 123, speculative k=2, cap 128 committed generated tokens, context 4096 and flash attention off. CUDA0 and full layer offload are explicit for target and speculative draft. TARGET_REFERENCE has no draft and target n_ubatch=1; RTX_BATCHED_K2 has target n_ubatch=2; RTX_SERIALIZED_K2 has target n_ubatch=1. Other semantics match. Each execution uses a fresh single-turn CLI process, cache-ram=0 and no warmup, with the historical prompt template and enable_thinking=false. The pinned CLI removes exactly one terminal LF when loading a prompt file. No AUTO/fallback device is allowed.

R0 must pass before freeze: all six specified sanity tasks, all three conditions, with native-ID capture versus original verbosity-4 runs, plus a replay of the first task after the remaining sanity tasks. Assertions establish prompt exclusion, contiguous output events, EOS/cap termination, zero cached tokens, real CUDA0 binding and full target/draft offload. Raw token pieces are checked against the CLI transcript solely as auxiliary integrity evidence; no piece or text is re-tokenized for correctness. R0 results cannot serve as formal pairs, select a condition or change ubatch. `R0_REVIEW.md` records the actual review and development failures.

After the source/preregistration commit, a manifest freezes source hashes, patch, original binaries, models, dataset, host state and exact commands. Its manifest-only commit precedes any formal execution. Formal output starts in a new destination; the runner prohibits overwrite, resume and rerun. No source/package/runtime/branch/parameter change is allowed after freeze. A mismatch is retained and execution continues. An operational failure is persisted and stops the incomplete attempt. A semantic repair invalidates formal status and requires preserving the old attempt, increasing protocol version and a new committed freeze before restarting.

Analysis compares each candidate array against the TARGET_REFERENCE array in the same task/repetition. Exact pairs are the sum of 90 full-array equality indicators. Exact prompts are the sum of 30 all-three-exact indicators. Divergence uses zero-based generated indices; for a strict prefix, the divergence is the shorter length and the missing token is null. Descriptions may include mismatch prompts, divergence positions, sequence lengths and within-condition repeat stability. Timing is operational only and is not analyzed for performance. No threshold/subset/reference/parameter search is allowed.

An independently implemented checker recomputes all 180 comparisons, first divergences and statuses, re-extracts IDs from retained runtime events, and validates count, membership, schedule, source/asset hashes, command consistency and device evidence. A content-addressed archive retains all formal arrays, native logs, stdout/stderr, prompts, source scripts and frozen evidence. The offline verifier does not require a GPU. Model weights, downloaded dataset and runtime binaries are excluded under repository policy; their byte hashes can be independently rechecked with --asset-root. An archive alone verifies their frozen identity consistency and explicitly cannot rehash omitted files.

Historical scope: cheap batched verification and a captured numerical divergence were known. The historical serialized 90/90 count used parsed CLI text followed by re-tokenization, **not a direct generated-ID certificate**. No formal outcome is assumed. Any conclusion stays scoped to these tested paths and this frozen environment. A serialized qualification can support “serialization restored qualification on this tested RTX path”; it cannot establish a universal guarantee. A mismatch does not establish semantic output failure.

All old manifests, logs, analyses, mechanism captures, manuscript evidence and figure data remain immutable. The MLSys manuscript and Figure 3 are excluded from this PR. Cross-platform integration with B570 requires a separate reviewed PR. This PR remains draft and is never automatically merged.
