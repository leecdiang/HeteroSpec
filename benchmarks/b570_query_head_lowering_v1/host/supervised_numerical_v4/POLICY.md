# v4 supervision and numerical policy

This registration is prepared at review base 02ac1d7313cb9d29617cda122c4c7556c7f2289e. It is CPU-qualified preparation, awaiting separate exact-F0 GPU authorization. No experimental host, GPU query, Vulkan/CUDA load, graph compute or model request is performed during preparation. The separate metadata program loads only ggml-base and allocates metadata with `no_alloc=true`; it never executes a ggml graph. A build does not execute the numerical host.

## Storage lease

Before each child launch, arm ReadDirectoryChangesW recursively on the two nonoverlapping v4 source/output roots, then take a complete byte/file inventory. Do not clear pending notifications. This snapshot cost belongs to complete-slot and controller engineering time; it is outside native lifecycle time. It is repeated once per slot, not at every resource sample. The previously completed slots, preparation, tests and builds remain charged in the snapshot. No prior v3 tree is a v4 storage root.

During the child lifetime and identity/output audit, permit writes only beneath the current slot. Any modification, creation, removal or rename outside it invalidates the lease. This is a fail-closed change detector, not an operating-system immutability claim. Notification API errors, zero-byte overflow/lost events, invalid records, stalled/dead watcher threads and failed cleanup stop the panel. Reparse paths and hard links are rejected. CPU-test-only top-level control files are the only test exception; production cannot supply fault/virtual-clock fields.

Runtime directory reads inventory only the active slot. At most 256 files and 33,554,432 logical bytes are allowed. Charge the entire 32 MiB active reservation, in addition to the prelaunch baseline, regardless of observed growth. Export reserve is baseline run bytes +32 MiB +(baseline run files +256)*1024 +1 MiB. The duplicated baseline bytes already in the active slot are intentionally conservative. Unknown/deleted/racing files never become fabricated zero-size observations; they invalidate or discard the read as appropriate. Snapshots and full post-exit output scans still check actual bytes. The next slot cannot borrow an old budget.

The current source has finite vector/input writes derived from actual CPU graph descriptors. Control/event logs grow while the slot exists and are subject to the same cap; the cap is a monitored limit, not a filesystem quota or a guarantee against arbitrary external malicious writers. Unexpected sealed writes invalidate the run, and the full output audit remains mandatory. No claim is made of continuous GPU memory measurement: only the inherited registered device checkpoints run inside approved hosts.

Resource and directory streams retain the unchanged strict 1,000,000,000 ns coverage definition: first completion minus launch; every read duration; next completion minus previous read start; live and terminal time minus last admitted read start. All must be <= the limit. The resource reader continues real RSS, available RAM and disk-free checks. Two controller watch threads additionally journal each notification poll start/completion and conservative effective interval; their live heartbeat, read/parse time and interval must also remain <=1 second. Scheduling is not guaranteed: a future overrun still stops the run. A CPU qualification is not advance approval of any future monitoring receipt.

Record actual launch, sample start/end, first confirmed exit, post-exit audit start/end and receipt commit. All intervals use monotonic_ns, with no rounding. OS creation/exit FILETIME is separate lifecycle evidence. A read racing exit is discarded without values. No post-exit sample repairs runtime coverage. Module hashing, raw parsing and complete output scans are still performed in the auditor and count toward engineering time; they cannot expand the terminal runtime interval.

## Fixed panel and admission

One complete 80-description support census, zero graph computes, followed by 68 independent numerical hosts. Sequence: A all eight q1 controls; B ten q2 anchors; C ten q3 boundary slots; D forty q4 slots. Within each geometry: repeat0 modes in declared order, then repeat1 modes in the same order. Each is a new process/PID+creation identity, one graph call. QH_C remains the main candidate.

The original sixteen exposed synthetic input files remain bound; eight geometries occur in the targeted numerical subset and all sixteen occur in the census. Inputs, dtype, precision, Q0 shape/stride, original K/V and mask ownership, PQ independent slabs and source-mask retention, QH_C CONT, QH_D REPEAT and REPEAT4 real KV copies/output restoration are unchanged. Native host.cpp is byte-identical; only the single fixture run-id literal changes. Numerical DLLs and the frozen backend are unchanged.

The inherited v2 RULES.md, independent analyzer and scalar FP64 reference remain the numerical rules. Full four-stage logical order is (query, logical head, element); PQ parts and folded heads must be restored independently. Input pre/post bytes, mask slab source and original KV ownership are mandatory. Compare independent repeats bitwise and q1 common controls bitwise. For q>1 retain all finite cross-mode differences, absolute/relative/ULP errors, zero-reference cases, nonfinite counts and first divergent stage. No new requirement that MQ equal every representation, no tuned tolerances, no selected QH version, no inference that ordinary FP64 rounding is a GPU failure. The planned comparison inventory is 124 within-run cross-mode pairs, 34 independent repeats, and ten descriptive q2 v3 anchors; old anchors do not qualify any v4 sample.

Stop subsequent slots on crash/assertion, unsupported actual node, wrong device/binding, changed input, nonfinite output, q1 mismatch, same-implementation repeat mismatch, identity drift, failed monitor/auditor/watcher, resource/space/timeout/engineering-budget error. This panel has no expected failures, probes, warmups or retries. Pre-spawn failure is retained as a failed registration/attempt with no native PID, not invented as an experimental process. All unstarted/invalid coordinates remain explicit. Neither successful v4 nor old v3 results constitute a completed 160-graph panel.

## New ceilings

69 experimental hosts; 68 graph calls; 138 separate monitor/audit CPU processes and one main controller; two sampler threads per monitor and two storage-watch threads per active slot in the controller. No claim these are all system/build/delivery processes. Entire future controller <=900 seconds; each complete slot <=180 seconds including prelaunch snapshot, launch, runtime, workers, audits, comparisons, cleanup and receipts. Separate native observed lifetime and post-exit audit durations; engineering time is not graph latency. All v4 prepared/built/test/runtime files plus export reserve <=1,073,741,824 bytes. BUDGET.json gives the newly derived output sizes, real CPU tests and reserved overhead. Inherited RSS <=8 GiB per observed worker, available RAM >=8 GiB, free disk >=4 GiB; device checkpoints >=512 MiB. These are proposed v4 ceilings, not authorization or reused historical balances.

Original S1, seven diagnostics, v2 and v3 identities, raw files, failed slots and accounting are immutable. v3 stays 117 started /116 admitted (1 census +115 numerical) /1 invalid /44 unstarted. S2/S3, actor, performance/profile, RTX, paper, main, release, automation and RTL are outside scope.
