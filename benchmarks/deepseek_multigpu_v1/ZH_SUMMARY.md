# 八张 A5000 上的主流投机解码扩展研究

## 目前可以确定的结论

这个方向值得继续，但需要把三个问题分开：模型能否装下并运行；新框架能否保持要求的数值与缓存状态；在成熟投机基线上能否取得有代表性的端到端收益。当前 PR 完成源码研究、可实施方案和 CPU 预检，没有启动服务器实验，没有完成多卡后端，也没有新加速比。

1. **不把 DeepInfer 作为唯一入口。** 当前官方版本面向 SM100/Ascend 950 和 DeepSeek-V4.1-Flash；A5000 是 SM86。V4.1 的 552B backbone 即使理想 4bit 也约 257 GiB，尚未计入额外组件，已经超过八卡总计的名义 192 GiB。更换 CUDA 版本不能解决架构与显存这两个独立问题。
2. **优先选择 vLLM，SGLang 做独立主流对照。** 先用 DeepSeek-R1-Distill-Qwen-14B 验证双卡，再推进 32B 的四卡、八卡。它们是 DeepSeek 发布的 Qwen 架构蒸馏模型，不是完整 DeepSeek MoE。后续若要验证 MLA/MoE，可单独研究 V2-Lite。
3. **八卡不等于八路 NVLink 共享显存。** 必须读取实际拓扑、P2P、每卡空闲显存与 rank 映射。vLLM 的自定义归约在超过两卡且非全互联时可能停用，不能只设置 batch-invariant 开关就宣布八卡逐位一致。
4. **旧 HeteroSpec CUDA 内核不是现成的 vLLM 插件。** 原 Q4_K/Q6_K 参考、激活量化、scalar-dot 顺序和 dense KV 条件不能直接覆盖 BF16、分页缓存与 TP 集体通信。需要建立明确的新框架参考，保持旧参考和旧结果不变。

## 超过 5% 应当怎样定义

最终目标是一个能嵌入主流投机解码框架、在代表性适用范围内产生实际端到端收益的新方案，而不是一个挑选出来的算子或很窄的配置。

这里把超过 5% 定义为：完整 resident 请求耗时相对同等投机强基线降低超过 5%，即新旧耗时比小于 0.95。完整成本包括 draft、target verify、采样、回滚/提交、调度、通信和同步。进程加载与冷启动另报，不能偷换成同样改善。

这只是可检验目标，不是保证，也不是丢弃负结果的门槛。若优化影响的阶段只占请求很小一部分，即使该算子明显变快，也不足以推高整体收益。必须先测真正的阶段占比，再决定值得改什么。

## 最值得核验的研发方向

- **SM86 小矩阵执行。** 当前 vLLM invariant GEMM 的专门调优表没有 SM80/86，A5000 会落入默认 tile。可以对真实 TP 分片形状尝试更合适的调度，但要证明原有累加/舍入语义不变。这首先属于通用后端优化，必须同时给强基线使用，不能把全部收益记成 HeteroSpec 的贡献。
- **请求与阶段感知的验证计划。** 把 query 所有权、真实页式 KV 可见范围、数值执行条件和集体通信计划明确传递，寻找可以安全复用的元数据与可以合并的执行。必须先用 trace 证明主流框架仍有重复工作，而不能假设它们没有优化。
- **独立研究联合控制器。** 若固定投机策略下机会不足，再研究把合法分组、页边界和 TP 关键路径成本纳入 horizon/plan 决策。普通自适应 k、acceptance 校准和成本感知调度已有大量原生实现，不构成新意；需要与成熟原生策略比较，并用控制器×执行器的 2×2 消融拆开贡献。
- **固定顺序归约的系统实现。** 在必须采用新 ordered reference 时，可比较不同通信分解的完整成本。它同样属于应共享给所有臂的通用优化，不能通过更换参考后宣称保持了 stock NCCL 的逐位结果。

目前没有证据证明上述组合已经形成新方法，也没有证据证明它能普遍超过 5%。[反例与竞品核查](COUNTEREXAMPLES.md) 给出需要主动挑战的条件。

## 实验怎样从小到大推进

第一层是工程与数值资格：原生框架不改代码能运行；独立保存参考；定位 scalar/batched 的首个数值差异；验证完整 logits、所有 active KV、接受/拒绝、pending、bonus、EOS、容量和 rank 失败；最后才进入 clean timing。

第二层是初步规模面板：14B 双卡及 32B 四卡/八卡，保留 target-only、原生投机、共同优化和新方案等必要对照。初始方案共 944 个请求、40 个模型 worker，包含 warmup/primer，不包含其他资格与失败成本。这是工程阶段，不足以支持广泛结论。

第三层才是独立代表性确认：vLLM 和 SGLang、三模型并包含第二架构、代码/数学/问答/对话、短长输入、单请求与并发、独立重启会话，并纳入实际可用的 learned proposer，而不只测 n-gram。当前拟议确认层为 6912 次测量，总计 14040 个请求、108 个 worker；必须先根据实测成本冻结模型、输入、设置、资源窗口与完整预算，当前没有启动。

所有结果都要保留，包括失败、变慢、低 acceptance、图模式不兼容、任务截断和不存在增量收益。不能把同一任务在不同 GPU/轮次上重复测量当成新的独立样本，也不能把跨 TP 产生不同输出后的耗时差直接称为同工作量加速。

## 当前交付与下一步

已交付可运行的 CPU 显存/支持性规划器，16 项测试在普通与优化模式下均通过。示例故意不填写服务器实测数据，因此不会返回运行资格。它区分不可避免的权重容量失败与包含预留项的条件预算超限。

下一步应取得实际八卡拓扑和干净资源窗口，固定 vLLM、模型、tokenizer 和依赖版本，完成双卡原生 smoke 与参考保存，再决定第一个真正需要实现的 backend/plan 改动。完整方案见 [可移植方法](PORTABLE_METHOD.md)、[集成设计](INTEGRATION.md) 和 [实验协议](PROTOCOL.md)。
