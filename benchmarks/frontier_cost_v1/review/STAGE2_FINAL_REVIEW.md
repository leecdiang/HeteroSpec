# Stage 2 independent review

## Release decision

**Publish the new research findings, finite host implementation and experiment preparation as a draft research update. Do not merge them as a demonstrated decoding optimization or admit a production performance claim.** No new model request, native executable or CUDA API was run by this reviewer. The local production work compiled against CPU libraries; compilation is not a successful production request.

The research direction is now more precise: seek a numerically legal execution/frontier transformation with enough net complete-request value after the strong shared baseline. Generic adaptive length, a Bellman equation, a STOP action, more provenance fields, lazy-tail repair and renaming the existing phase executor do not independently establish novelty. The evidence does not establish an additional, broadly useful 5% service reduction.

The lifecycle negatives reject a complete-plan label with only two processes, a capture pair after an extra attempted process, and a record from a different run. The budget check separately accounts for a 151-token draft prefill as one API call and 38 physical microbatches. The all-accepted deferred tail is restored, while an unneeded tail is omitted.

The policy case demonstrates the concrete p4 frontier obligation: four inputs `[seed,p1,p2,p3]` can validate p4 while target KV ends at p3. A terminal accepted-p4 branch lacking its required materialization price is unavailable. This is an existing contract issue applied to the new model, not a newly discovered decoding theorem. The model has a separate physical-target frontier for a terminal inside an already wider call, so it need not invent another q1 when p4 is already materialized.

The causal checks also verify suffix censoring, duplicate-observation rejection, explicit future-field rejection, and the cost of abstention. Missing evidence, an old summary, a macro relabeled as eligible and a `SyntheticModel` all leave the real runtime interface in `ABSTAIN` with actuation disabled. The finite recursion is a local surrogate, not a proof of optimal remaining-request time. Synthetic positive decisions demonstrate software behavior only.

The final independent component audit contains twelve checks. In addition, this reviewer executed the author's fifteen policy tests and ten production-protocol tests independently; both suites passed. These test counts overlap in concepts and are not counts of independent model observations. The internal controller watchdog covers its decision span; complete controller overhead must be measured by an outer caller that also includes return/ledger work. Neither a host microbenchmark nor synthetic prices authorize deployment timing extrapolation.

The finite recursion also merges matching routes by the scalar frontier `at`. That is a synthetic Markov/equivalent-state assumption, not a demonstrated physical-state theorem. Two routes with the same tokens/frontier can have different graph reuse, cache conditioning or allocation history. A nonempty `Price.postcondition` string does not prove those states equivalent. A future real implementation must retain every cost-relevant state difference or establish a valid equivalence; the current runtime remains closed to real actuation.

`TRACE_FORECAST_AUDIT.json` independently reconstructs all 287 forecasts from the original session-0 k7 receipts, without calling the author's diagnostic function. Both forecasts precede the current observation and are scored on the same 281 observed first-four labels: 153 true, 128 false and six earlier terminal outcomes censored. Only 1,301 observed prefix trials update the position counts. The position-Beta Brier score is 0.25756736, versus 0.25185203 for the simpler past-first4 frequency baseline. Their initial event probabilities differ, 1/16 versus 1/2, despite both using component Beta(1,1) counts. Initialization and the exposed order therefore matter; this is a descriptive negative result on sixteen already exposed roots, not a family-level ranking. It is not held-out validation, an alternative trajectory, a probability of continuing past CAP/EOG, or a latency result.

## Research judgment

The newly rechecked paper facts support the main report's distinction between the application gain and the independent increment. The fixed draft-policy packing increments are around 1–2% against backend-loop4; ordinary speculative service versus target-only is a different comparison. Natural boundary splits are rare in the cited 8B panel. The 32B approximately 5.6% grouped result uses a graph-level scalar-column comparator, while its grouped speculative path is slower than the fastest target-only arm. Vulkan append-window gains also do not establish complete speculative service gains. These facts were already in the fixed draft; this round verifies their relevance to the user's target.

The existing ordinary serial k7, q4→q4 reveal story does not win the old workload-count comparison against the common-cap k3 baseline. This defeats a simple “fewer target calls/rows” explanation for that specific design and panel; it does not prove that every conditional strategy or legal backend transformation is impossible. The CPU q2 failure is likewise specific to its backend/history/shape. The q1 diagnostic reference has not been bridged to historical R, so that failure does not disqualify all possible q4↔q8 actions against a separately declared original reference.

The earlier 4.498 ms condition is a **particular displayed-route proxy**, not a measured fixed launch cost or an upper bound on all strategies. Its per-block coefficient 151 becomes 1,208 over eight blocks, and the overhead term must be aggregated consistently. Proposal and draft-sync work are separately priced. B2's `0.05/(1-r)` illustration assumes the same replaced operation count, representative ratio, unchanged remaining work and no added overhead. B2 ratios must not be multiplied by the separate RTX service fractions.

The remaining credible opportunity is an actual legal execution difference: enough shared target work, rejected-suffix avoidance, or another measured architecture-dependent mechanism to exceed extra passes, synchronization, control and state convergence. It should first survive a strong short-draft/adaptive baseline with the same generic optimizations. A causal policy is useful only if this net opportunity exists and is predictable from information available at the decision point.

The next observations that would change the judgment are therefore concrete: qualification relative to an explicit R; clean costs at the actual reached frontiers, including every outcome and STOP; then frozen full-request comparisons on new root-level confirmation inputs. Controller × executor comparisons should separate scheduling from lowering. “Approximately 5%” should retain its preregistered complete-request denominator and uncertainty; generalization should name and test its support domain, including negative configurations.

The final TPDS follow-up correctly anchors the design response to the supplied PR222 draft while preserving the existing S3 plan/status boundary. Its recipe table separates manuscript premises, runtime guards and actual tested domains; it does not certify unreviewed guards. Proposed long-prefix/C4096 strata, modern-runtime comparisons and platform reporting are future designs, not additions to the current fixed execution profiles. The primary future estimand is now the ratio of cohort total times, with equal-root geometric ratios secondary and preregistered. The remaining supplementary-page visual check is explicitly open. This reviewer audited that response's claim scope and design; the parent owns the live PR/Actions retrieval, and no separate PDF visual inspection is claimed here.
