# RTX reference-compatible lowering and native execution envelope

## 1. Question, pins and immutable history

PR104 `f997262d6b0accb126a1217c9356745cc8bbf708` is closed scientifically with finite evidence, not universal support. C-path T_PQ/T_QB=1.031614/1.065803/1.029114. E1 PQ/QB QK-softmax-AV agrees72/72, but all tensor key extents are256 and visible keys only reach109/130/127. PR110 `dae5aea9f9009a686196dd89981c0ae9699ae612` deliberately aliases five mapping names and supplies no new hardware comparison.

This study tests a concrete alternative software lowering and actual costs before further hardware claims. It does not rewrite these results, retry old slots, change their1.02 threshold, or borrow unused budgets. PR112 `7864716787fabb17cb613ed7125c180736c133ef` is a design source for QH, not successful Vulkan or CUDA evidence. No edits to B570 execution, main, PR102, release, arXiv/Zenodo or automations.

Hypotheses: H1 alternative lowering preserves operands/masks and finite reference behavior; H2 representation affects actual backend execution/structural costs; H3 qualified gains transfer to new natural inputs and larger visible context; H4 any remaining bottleneck warrants a specific hardware mechanism beyond strong software. These hypotheses can fail independently. No requirement to increase acceptance or obtain positive speedup.

## 2. Concrete representations; no five-name alias experiment

Use inherited MQ and real PQ/QB implementations from PR98/104, not the PR110 arithmetic simulator. Preserve original numerical CUDA DLLs, precision flags, Q/K/V/mask values and ownership. New source changes are isolated graph/actor/observer glue with explicit hashes. No shader/reduction rewrite, quantization/weight/sampler change, online softmax, zero-skipping, or arbitrary DAG invention.

QH comes from the fixed PR112 design: for original Q[d,q,H,1], define r=h*q+j and Q'[d,1,H*q,1]. With g=H/Hkv, floor(r/(q*g))=floor(h/g). Original K/V remain shared objects; model heads do not change. q1 must execute the actual common original chain. All native q>1 variants must have genuinely distinct source-bound graph constructions; a label alone is not an implementation.

QH_C uses mask[n,1,q,1] with validated backend head modulo r%q; QH_D repeats the exact query mask to[n,1,H*q,1]. Compact Q can be reshaped only if addresses permit it. Permuted/noncontiguous Q must be explicitly packed; restore AV[dv,1,H*q,1] to[dv,q,H,1], permute to[dv,H,q,1], then ordinary output. Include all CONT/REPEAT/output storage and execution. No free mask/Q preparation outside measured graphs. Canonical output comparison restores logical query/head indices before bitwise comparison.

Inherited single sequence/KV stream, non-flash and supported family graph constraints remain. Exclude head-dependent bias/ALiBi, sinks, softcap, MLA and unsupported K/V strides. D=64 for SmolLM2 and128 for the other inherited families are both required. q1..4 is this study's scope; do not extend to q8/tree/multiple requests by changing a label.

For native request candidates, retain PR104's target-phase mask3 and actual family recipes. Do NOT import B570's prefill-MQ/reference128/bulk512 policy into RTX: that would change another factor. QH replaces attention only in the same active target phases; draft phases and speculative k3 transaction remain inherited. Recover exact ordinary-R settings from source/manifests rather than guessing them. Each family has its own deployed reference, not a cross-device universal token stream.

## 7. Hardware/paper decision and implementation obligations

The new native evidence may yield: REFERENCE_COMPATIBLE_LOWERING_SUPPORTED; PORTABILITY_ONLY_NO_COST_GAIN; CANDIDATE_NOT_QUALIFIED; or MECHANISM_UNRESOLVED. Hardware recommendation remains separately SOFTWARE_FIRST/HOLD/PROPOSE_BOUNDED_MECHANISM. No automatic new simulator, RTL, GPU budget or hardware purchase.

A hardware proposal needs a concrete residual cost under the best actually implemented same-reference software path, a changed capability with charged overhead, and a falsifiable reference condition. A rejected backend representation is software evidence, not proof of missing silicon capability. Reproducing the same simulator under five names does not test five architectures. If software already achieves candidate schedules, report it rather than remove baseline sharing. No need to prove software impossibility universally before a small hypothesis test, but distinguish measured bottleneck from abstract assumption.

PR104 is strong enough for its narrow paper claim now; this optional extension must not rewrite or delay its acceptance. QH is an alternative lowering, not declared original or universally better. Final paper claims depend on actual support/placement, full-reference outputs, new-condition coverage and complete costs. No LLM task-accuracy improvement or higher intrinsic acceptance claim.

Host must implement genuine native replay/actor, complete actual support registry, per-node device/ownership evidence, robust inputs/malformed descriptor handling, exact request/command serialization, independent raw reconstruction, source/model/loaded-module provenance and lifecycle watchdogs. The supplied helpers verify algebra/budget arithmetic only. Keep zeros, failures and unknowns explicit; enforce ceilings before each attempt. Retain failed source/transport receipts; a byte transport recovery is not permission to retry science. No raw credentials, private tokens or model weights in Git. Seal a compact result, all necessary data and fresh-restore reanalysis; do not generate duplicate long administrative reports.
