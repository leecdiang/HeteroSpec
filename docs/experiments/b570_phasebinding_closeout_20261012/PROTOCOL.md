# B570 — Phase-binding / reference-boundary / physical-work closeout (design only)

**Purpose:** close the independent Vulkan design case without claiming it implements RTX query-batch. The testable loop is **reference-difference localization → state/recipe-controlled intervention → exact full-output check → measured physical verification work and honest cost boundary**. Existing negative economics and immutable reference failures are scientific evidence, not objectives to tune away.

## 1. Scientific questions and falsifiers
**B-MECH:** Why do R_stock and the production/matched/candidate group make different *complete native outputs* on two tasks? Is this reproducible by a **prefill-only** execution recipe change, a continuation-only change, retained-state difference, or inseparable whole-recipe interaction? Demonstrate with physically executed, verified phase settings—avoid saying "UB alone caused it" when reservation, sampler, synchronizations or KV state also changes.

**B-WORK:** Why does high draft acceptance fail to lower cost? Does physical verification really stay at occupied width1 with no target-graph amortization, while proposal+catchup work is paid? Compare absolute counters and same-output cost, without inferring hidden GPU stage time from enqueue timestamps. It is an implementation boundary, **not** a claim that the GPU or Vulkan universally cannot accelerate speculation.

**B-STATE:** Which pending token, sampler, KV, output reservation, synchronization and graph/placement semantics must remain owned by the same target context across prefill→continuation? Can own-path shams validate state restoration at selected cuts? If a changed prefix or state cannot be faithfully restored, say NOT_ISOLATABLE.

Negative or NULL is an acceptable terminal result. No claim that original reference correctness is worse or model answer accuracy changes.
