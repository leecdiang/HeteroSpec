# Registered primary queue and explicit branch boundaries

The user prioritizes complete PR205 actual EOG/native qualification, then PR206
natural qualification, and only then assessment of formal performance panels.
This supersedes the previous D14 continuation's direct `--run-panel` launch.

The active native queue waits for the real PR205 completion receipt and checks
all its referenced native proofs, actual graph/physical and bad-option gates.
It then starts the new PR206 continuation automatically. Complete native jobs
from the priority handoff are revalidated/reused; failed/partial jobs are not
admitted. New reference branches and unstarted D4 controls remain native work.

`primary_evaluate.py` waits for both actual qualification scopes to complete.
It holds the same scheduling mutex for bounded clean-service pilots, then
writes `FORMAL_PANEL_ASSESSMENT.json` before any formal launch. The pilot uses
all six controls on the original exposed development roots, two primers, one
fixed worker order and one observation/root/arm. It compares complete endpoints,
transactions, physical work and actual module/residency bindings. Pilot clocks,
memory samples and failures are preserved. These data have no population effect,
confidence interval or new-blind-root claim; they do not replace finite internal
state checks or formal performance measurements.

D14 already has an immutable prospective24-worker/384-measurement/48-primer
deployment-transfer plan. If both native gates and pilot checks pass, its full
request/row allowance and conservative wall-time estimate must fit the remaining
declared envelope before the queue launches that exact panel. A favorable speed
sign is not an admission criterion. Every fixed control remains; attempted
native formal slots are never selectively retried.

F's new12-root formal confirmation additionally requires completed prospective
ID/text/token exposure exclusions and registration. Existing development roots
cannot replace that cohort, and an availability-only dataset listing is not an
execution-exposure audit. This queue records F's formal scope as not admitted
while that prerequisite is absent; it does not pretend a new-blind panel exists.
The completed F finite transfer and bounded exposed-root pilot remain useful
separate evidence. A later registered F confirmation needs its own source/job
freeze and explicit continuation stage.

Archive/readback follows terminal primary scopes, including retained failures
and complete actual costs.32B download partials remain preserved and paused
through the primary pipeline. M2 physical-q8 and Q4 numeric-type GPU experiments
are not auto-launched merely to keep the card busy; their next priority is judged
from the primary evidence and remaining time. No driver/device reset, foreign
task signal, model substitution, manuscript edit or automatic merge is allowed.

The scripts advance registered success transitions without another chat prompt.
A new numerical, resource or native formal failure is an explicit retained
terminal state with stage/slot information, not permission to skip a gate or
silently repeat selected formal outcomes. Repair/requalification uses a distinct
source/output epoch; a script cannot promise to repair arbitrary unknown errors.
