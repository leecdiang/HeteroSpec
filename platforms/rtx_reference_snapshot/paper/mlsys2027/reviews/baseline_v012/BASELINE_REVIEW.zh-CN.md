# HeteroSpec v0.12.0：合并、科学基线与自审

审阅日期：2026-10-08。范围：本轮开始时全部未合并 PR #57–66、最新 RTX 普通参考 CPU 闭环、当前全仓库证据与新稿。身份：作者侧单次系统审阅，不是外部同行评审或多名独立审稿人的投票。本轮零新增模型运行。

## 本轮决定

**全部十个 PR 已审阅并合并，研究证据基线为 `f9b9457fe528a343dd0b01614dcce017801913db`。新的论文科学版本为 v0.12.0。** 其标题为 *State and Cost Limits of Reference-Preserving Speculative Decoding*，正文、补充材料及可编译源包位于 `paper/mlsys2027/baseline_v012/`。该版本取代 v0.11 的当前科学结论；旧版本、原始实验目录和失败结果保留。

推荐主线：**真实历史数值状态与当前执行路径的交互 → 有限范围的目标路径约束 → 输出资格和验证摊销分别验收。** 主贡献是可核对的系统实证证据与一个 RTX 正向实例。目前不成立的主张包括通用新解码算法、全局最小约束、唯一 attention/kernel 根因、四平台机制一致、第二模型家族验证、普遍无损加速。

## 科学基线必须保持的数字与边界

全部 speed 为 baseline/candidate；先按任务/条件取绝对耗时的跨轮中位数，再取任务比值几何均值。

| 证据 | 输出/面板 | 生成 speed | 驻留请求 speed | 支持的结论 |
|---|---|---:|---:|---|
| RTX 24 任务：普通 R / 候选 C | 四条件各 96/96；完整已保存响应与端点 | 1.170124 | 1.741569 | 有限普通参考收益；R 为测过的 mask0/UB1 前端，不是全局最快普通解码器。 |
| 同 campaign：匹配 M / C | 同上；M 为 mask3/UB4 无 draft | 1.169238 | 1.035071 | 投机在匹配目标路径上的增量；请求 17/24 更快，第二轮 0.940220。 |
| 同 campaign：R / M | 两者都是无 draft | 1.000758 | 1.682560 | 大部分 R→C 请求优势已在无投机路径出现；不能全部归因投机。 |
| RTX 固定 UB4：k3 / k7 | 28 暴露资格任务；另开 capture-off 成本会话 | 0.829442 | 0.889868 | 更长草稿仍输出合格，却比 k3 更慢。 |
| 匹配 target / RTX k7 | 同一固定 UB 成本面板 | 0.997404 | 0.950353 | 通过资格不保证验证摊销优于 target-only。 |
| B570 普通 R / 修复候选 | 15 新输入、两轮；R/M/C 各 30 完整 | 0.282588 | 0.201290 | 有限端点修复成立，普通参考性能失败；E 保持 119/120。 |
| B570 旧 N1 / 修复候选 | 14 完整任务对 | 3.99309 | 2.63394 | 仅说明改善旧原型；一个请求轮次仍反向。 |
| M4 target / Always | 前瞻 60 输入；Always 180/180 | 1.346894 | 不在本行混用 | 该研究的真实 post-prefill 正结果；Guard 比 Always 慢 2.71%。 |
| 358H target / CPU、NPU draft | 各 90/90 | 0.733915 / 0.351663 | 保持原研究 timer | 本实现的条件性去开销上界仍低于 parity；不是异构解码不可能定理。 |

RTX 请求比较有逐任务及 GM 恒等式 `R/C = (R/M) × (M/C)`；它不是组件成本分解。generation 为原 `predicted_ms`，排除 prompt/第一 sample 和部分末尾 bookkeeping；request 为驻留 HTTP 响应 host wall，包含 prefill、生成、传输/解析，排除加载、预热、关闭，可能不含异步响应后清理。R→M 同时改变 prefill 和 continuation；B campaign 未启用状态移植分支。不能从代码存在推断执行了 transfer，不能从 request−generation 推断 attention/draft/KV 份额。

最新复核独立重算 #66 384 行、4,320 个派生表值、12 组 GM/轮次与 PCG64 10,000 次 task bootstrap，全部通过；新的构建 verifier 另检查 384 行 qualification hash join、24 个稳定参考、48 个逐任务与两个 GM 恒等式。这个范围是公开派生数据审计；原始完整数组和私有档案认证继承原执行机审计。本轮没有独立重开私有 CAS/ZIP，也没有硬件复现。

## 创新性查重：能争取什么，不能争取什么

以下是检索原文后作出的贡献重合判断，不是穷尽全部文献的优先权认定。

| 最近邻 | 已经覆盖的概念 | 本稿可能保留的增量 | 对接受预期的影响 |
|---|---|---|---|
| [LLM-42 v2](https://arxiv.org/html/2601.17768v2) | 固定形状验证、保持 KV 一致、快路径自由、复用现有 kernels、选择性确定性。 | 自然状态×当前原生路径矩阵、Qwen3 局部布局/有限 phase mask、两个强度不同的 draft-free 对照与失败边界。 | 重合强，不能以“只约束验证器”或“没有新 kernel”作为首创。 |
| [Stage-Replay v1](https://arxiv.org/html/2607.28495v1) | 同前缀状态差异、构造桥接、双向 KV 移植及 checkpoint 复验。 | 将当前执行 recipe 作为另一个实测因素，并连接有限修复、输出与成本门槛。 | 状态移植本身已不足为新颖性；我们的自然边界案例更少。 |

最可守住的创新是**一组将自然数值状态、当前路径、有限修复和真实摊销连接起来的可核对系统证据**。它比旧稿的诊断/预测/负结果拼接更完整，也有新的 RTX 正结果。但从这些数据推导一个架构无关理论、自动修复器或全局最优方法，仍会超出证据。四平台的普适性应解释为研究问题及验收流程的复用价值；同一修复 recipe 跨四平台成立并未得到证明。

## 文字重复检查

方法：对新稿摘要及正文去 LaTeX citation/label 等标记，转小写，只保留英文词，扫描至少连续八词的精确重复。外部覆盖七项代表性原文窗口及 Performance or Illusion? 的已成功读取官方摘要；内部对照 v0.11 主文来源，排除参考文献/模板和历史附录。按最终稿重新运行，记录覆盖字数、重复位置数和最长连续段于 `TEXT_OVERLAP_CHECK.json`。

最终稿扫描 3,772 个归一化英文词 token，外部八个窗口共 3,879 个，旧稿对照 5,042 个。在这些有限语料中未发现达到门槛的连续重复；没有发现需要因照搬文字而替换的段落。**这不是全文文献库查重，更不是 Turnitin/iThenticate 0% 报告。** 精确词串扫描不检测改写、翻译、未检索文本或思想重合；接受风险更主要来自上表的贡献重合。v0.11 与 v0.12 是同一工作的版本关系，不能独立重复发表。

## 完整自审：以 MLSys research 门槛判断

**总体判断：仍偏 Weak Reject，但明显强于 v0.11。** 这里没有可校准的录用概率百分比。新版已经有一个真实正向实例、输入扩展、可操作实现、两基线和保留失败的证据链；因此不能说此前扩大创新的努力完全失败。也不能说这些增量已经跨过高创新门槛。

优势：问题明确；自然状态与当前路径不再混为一谈；RTX 生成阶段对两个付费对照有约 1.17× 加速，即约 14.5% 时延下降；宽度扩展反例和 B570 普通参考负结果能防止选择性叙述；统计和成本身份较清楚；公开数据可 CPU 复算。

主要弱点及本轮处置：

1. **独立创新增量偏窄，严重。** LLM-42/Vosti/Stage-Replay 与核心概念接近；没有同合同直接方法对照。已增加明确的重合段落并删除首创/通用表述，但文字无法代替方法增量。
2. **跨模型普适性缺失，严重。** late repair 主要为 Qwen3。B570 是不同有限修复且性能失败；历史 M4/358H 不具备同等级机制证据。新稿明确区分诊断问题的可迁移性与 recipe 的不可直接迁移性。
3. **强普通基线仍不穷尽，重要。** M 本身是 output-qualified draft-free 路径，已经有 1.683× request 优势。剩余 speculation 增量仅约 3.5%，且一个轮次变慢。未测最优普通执行，也未做所有最近邻方法的直接对比。已把两种对照放入摘要、主表与图，不主打“投机 1.742×”。
4. **因果覆盖有限，重要。** 四 RTX 探针、三个 B570 任务，选定边界且重复。交叉支持 local interaction，不唯一定位算子，不证明 full counterfactual trajectory。/72 duplicate columns、/229 continuous vs argmax 的差别均保留。
5. **性能外推有限，重要。** RTX 24 短代码任务、128 cap、单槽/独立条件进程、笔记本未锁频；task bootstrap 不是独立机器/日复验。新稿报告 22/24 与 17/24、第二轮反向、timer 与 session 限制。
6. **独立复现材料不完整，重要。** 本轮重算 public exports；私有 raw/weights/runtime 仍不在新源包。保留证据身份与继承审计，不宣称独立 GPU 复现或匿名全量可运行 artifact。
7. **表述和版面，已修复本轮问题。** 旧“尚无正结果／B-C-D 尚未执行／暂停合并”改为历史；统一 ratio/timer/endpoint 语义；改用避免同名冲突的标题；删除模板误示“已 under review”的页脚；正文、表和图零溢出/未定义引用。

按当前证据，合理投稿定位是**有正向实例的系统实证论文**。若坚持以通用高性能方法稿投 MLSys，接受预期仍不高；更匹配实证/系统软件案例的期刊可另做官方范围筛选。不能把工业 track 当创新性不足的捷径，当前没有大规模生产部署证据。

## 后续顺序与冻结纪律

本轮先冻结证据和主张，不继续 RTX/B570 的同题硬件搜索。后续编辑以 v0.12 为输入：强化问题与最近邻差异，精修图表/语言，准备匿名可核算材料，再由作者核对全文与相关论文并确定去向。若仍要争取通用方法级接受，只应考虑能够直接区分核心假设的跨家族/最近邻对照；它是新的研究选择，不是本轮用文字能补齐的事项。

禁止在不留版本记录的情况下改变参考、去掉失败任务、把 post-hoc CPU 复算算作新试验、用短输出换速度、将 endpoint match 改写为 raw equality、把 matched 和 ordinary 的分母交换，或用跨 campaign 成本合成一个新收益。

v0.12 的完整编译、公开数据 verifier、干净解包构建、匿名 PDF 文本与页面渲染检查结果随版本记录。官方 [MLSys 2027 call](https://mlsys.org/Conferences/2027/CallForResearchPapers) 本轮核验采用 2025 style、10 页正文和独立附录；它强调 novelty/quality/impact。格式通过不是接受判断。当前未投稿。
