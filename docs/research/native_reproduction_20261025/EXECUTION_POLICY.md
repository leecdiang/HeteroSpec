# 执行与续跑规则

目标是持续推进可完成的工作，并保持每项结果可追溯。这里不要求固定盘符、特定终端、某个历史 wrapper 或一次性完成所有阶段。

## 可以自主调整的工程事项

- 搜索既有本机目录、下载缓存、已认证 archive 和源码 capsule；用内容哈希识别，不因路径或文件名变化直接停止。
- 在隔离目录修复路径、依赖、构建命令、适配器、结果导出、观察开关和清理逻辑。优先复用可工作的现有脚本；修复后运行受影响的检查。
- 原工具链不可得时保留原记录，可构建替代环境并重新资格。将其标为新运行时复现，不冒充历史二进制完全重建。
- 可选 profile、kernel 名、Graph 计数缺失时继续源码整理、阶段/请求资格与可独立完成的成本比较；对应机制解释保留为未解决。
- 已确认的旧成果可以直接恢复和审计，不为了生成新时间戳重跑。无法恢复的具体 fixture 可在合格环境重新采集，并清楚标记新采集身份。

## 正式运行前固定什么

冻结影响解释的项目：源码/二进制/数值库和模型/tokenizer 身份、设备、输入及格式、参考、sampler/停止规则、布局与 k、context/KV 配置、计时边界、warmup、配对顺序、分析、总预算和技术重试政策。执行者可以在可行性阶段形成这些选择；用户已授权常规实现与运行，无需为每个工程决定重新询问。

若两种 k 或布局需要不同参考才通过，先报告这个事实，不能换参考后继续当作同合同对照。失败单元的时间可作诊断，不能算合格 speedup。实现或合同发生实质变化时创建新版本，从受影响的资格阶段继续；不同版本不混成一个正式结果。

## 断点与局部阻塞

使用持久的任务/请求台账，每项含 run_id、协议/源码身份、platform、cell、input、arm、session、attempt、状态及证据路径。状态至少区分 pending、running、complete、failed、blocked。

- 恢复时先核对已完成回执的身份和哈希，再执行 pending 项；不要覆盖原始记录。
- 上次 running 但没有完成回执的项记为 interrupted。按冻结的技术重试规则决定是否重跑整个配对块，使用新 attempt ID，保留旧尝试和排除原因。
- 允许因设备/进程/传输等技术失败续跑。不能仅因某次较慢、方向反转或未显著而重跑或换输入；耗时超限也按预先定义的技术规则处理。
- 同一配对块若中断，避免将中断前后的不同主机状态拼成一对；保留未完成块，必要时用新完整块重试。
- 某一阶段阻塞，只暂停其依赖项。RTX 的资料恢复可独立于桥接运行；B570 的阶段复现可独立于大规模服务计时；一个平台可独立于另一个推进。
- 不以重复等待替代交接。确实需要用户提供硬件、访问或不可恢复的文件时，列出准确缺项及已完成部分，保存 RESUME.md 后返回。

## 运行与观测

明确选择 CUDA/Vulkan 目标设备，不静默回退到其他设备。复用或修复现有进程管理，只管理本任务创建的进程并核对 PID/创建身份，退出时等待回收；不按名称终止无关进程。已有历史资源偏差继续保留，不因旧回执不完整而否认有证据支持的旧科学结论。

模型加载、预热、资格、诊断和正式计时分别记账。计时内外的工作明确记录；观察器有额外同步或读回时，分开记录 clean timing 与 diagnostic，不通过减去 profile 时间构造加速。

预算在可行性结束后固定，并保留时间/资源余量；会话次数、预热策略和间隔由本机可行性与研究目的决定，不机械继承旧活动的 worker 上限。预算耗尽后交付现有结果，不无限重试。需要另一轮时创建独立协议版本，说明原因。

## 结果与交付

分别报告：材料完整性、原生数值资格、输出/状态资格、成本结论。哈希校验工具不为后三项背书。每个数字都指向原始记录和生成脚本，保留 A/A、反转、失败和缺失，不手改 CSV 或填补缺失结果。

在平台分支提交源码、便携配置、分析脚本和小型来源/结果记录；大模型、凭据、整机 profile 和批量本地运行目录不进入 Git。原始证据保持持久可恢复，并写明实际存放位置、哈希和恢复命令。私有仓库 PR 不等于公开发布数据。

RESULT.md 用简短结论和证据表交付；RESUME.md 记录准确下一命令。先把可执行部分做完，再提出剩余阻塞。不要把工程中断写成科学负结果，也不要把未通过实用增益门槛写成“增益为零”。
