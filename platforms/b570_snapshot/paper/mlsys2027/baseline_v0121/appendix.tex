\section{RTX Expansion: Statistics and Timer Boundaries}
For each task and condition, take four absolute generation or request times and compute their median. Compute the baseline/candidate ratio from those medians, then its unweighted geometric mean across 24 tasks. Do not take a ratio of cross-task median times, pool repeated requests as independent inputs, or switch numerator direction to make a speedup.

The primary descriptive bootstrap uses NumPy Generator PCG64, seed 20261008, 10,000 task resamples of 24 indices, with one common index matrix across comparisons. The interval uses linear/type-7 quantiles. Historical intervals from Python \texttt{random.Random}, seed 20261005, 4,000 draws and sorted indices 99/3899 are reproduced separately. Differences between the two conventions are not new measurements.

The scalar reference uses mask 0/UB1 without draft. The matched condition uses mask 3/UB4 without draft. The two speculative conditions use mask 3 or mask 15 with $k=3$/UB4. All conditions use the same frozen private server and retained CUDA libraries. Formal request capture is disabled. Each round uses four separate resident processes and one warmup per process; condition order and task order rotate. Actual recorded cache reuse is zero. The response's \texttt{tokens\_cached} field describes the final slot prompt length in this source; it is not the cache-hit count.

Generation time is the retained server \texttt{predicted\_ms} field between its prompt/first-sample boundary and its last generation update. It charges drafting/verification within that interval, excludes prompt work, and can exclude later final-token bookkeeping. Resident request time is the client wall time around complete non-streaming HTTP response receipt and parsing. Process startup, model load, excluded warmups, boundary telemetry and server shutdown lie outside it. Post-response asynchronous cleanup is not certified to be inside it.

No cost fractions are inferred from \texttt{prompt\_ms + predicted\_ms} or request minus generation. The state-transplant helper is conditional in the source, but its activating environment variable is absent in this expansion. A dormant branch cannot be charged as an observed transfer. The ordinary-to-matched difference changes prefill microbatch/attention and continuation capacity jointly. Only separate component instrumentation could establish an attention, transport or transfer decomposition.

\section{State Crosses and Scope Interpretation}
Natural donors are reached with native proposals rather than a recorded proposal stream supplied to the candidate. Equal committed prefix and valid cache ownership are checked before crossing. Own-path shams test manipulation fidelity. Selected-boundary studies are deliberately informative about known sensitivity; they cannot estimate how common the effect is among arbitrary requests.

In the first RTX cross, /15 changes with the current call under both donors, /25 changes only in one donor/current combination, and /18 and /31 do not change at their selected cuts. Serialized donor states differ, while prompt logical K/V agree. Generated-prefix differences are not a unique attention attribution: numerical inputs to later computation may already differ. Continuous score changes and discrete argmax changes are separate observables.

Scope bits target prefill/continuation and draft prefill/continuation encode a finite candidate family. Passing masks 3/7/11/15 show that draft constraints are unnecessary for this panel. They do not show that every implementation can leave draft execution arbitrary without satisfying the usual verification/state/commit conditions. Mask 3's minimality is an inclusion relation in the tested switch family, not a theorem over all possible numerical transformations.

The expanded MBPP/229 wide-geometry cross flips the EOG decision with natural donor state under both tested layouts. It supplies a state-sensitive failure boundary for the fixed repair. The two layouts also change continuous values; absence of a separate argmax flip does not mean they are numerically equivalent. Two cap contexts, four shams and auxiliary probes are retained as repeated observations of one task.

For B570, the recipes include both microbatch and output-reservation differences. The /145 and /42 matrices support whole-recipe interaction, not isolated microbatch causality. /72 has identical current columns and is a state control. Six repeated cases are three tasks. No full counterfactual suffix from each crossed state is claimed. Full repaired requests have their own qualification matrix.

\section{Historical Baselines and Abandoned Directions}
Earlier RTX target-continuation interventions were predicted on 43 tasks but repaired one task while introducing another deviation, leaving aggregate reference agreement unchanged. The ordinary draft-free U2 bridge reproduces all 19 measured intervention outputs, with reference agreement 17/19. An offline intervention-selection study finds no measured advantage over tested simple alternatives. These negative findings concern the earlier predictor/selector candidates; they do not invalidate the later native attention-layout instance.

Early RTX heterogeneous and native costs, and a 14B configuration with output failures, remain source-specific historical observations. Unqualified speed cannot establish losslessness. No historical timing is paired with a later output trace to create a synthetic qualified speedup. Detailed older experiment exports remain in the versioned historical manuscript archive.

The M4 prospective 60-task study is an actual post-prefill campaign, distinct from earlier proxy timings. Always qualifies 180/180 and reaches 1.346894; Guard qualifies 180/180 and reaches 1.311386. Guard/Always latency is 1.027076 with descriptive 95\% interval[1.012956,1.043559]. A per-task whole-request oracle choosing only between target-only and Always leaves approximately 0.0691967\% further improvement relative to Always. This is not an intra-request controller ceiling.

On 358H, measured CPU/NPU drafting yields 0.733915/0.351663 with 90/90 reference agreement each. Available conditional overhead-removal ceilings remain below parity. The historical NPU full-prefix replay explains an implementation cost, while incomplete tracing prevents a universal component model. M4 and 358H support cost conclusions under their own contracts; they do not inherit the late natural-state evidence.

\section{Reproducibility and Remaining Gaps}
Revision v0.12.1 changes exposition and figures while preserving the v0.12.0 experimental exports byte-for-byte. The portable source builds the main manuscript and this supplement with the retained official style dependencies. The evidence verifier checks the public cost exports, task/repetition keys, median-before-ratio aggregation, bootstrap, and the two-baseline multiplicative identities. It never launches a runtime, reads model weights or calls a GPU service. Build reproducibility means matching extracted text from clean builds; it is not a promise of identical PDF metadata bytes.

The main conclusions depend on public, source-bound derived exports and inherited original-host verification. The integration and editorial revision independently recompute public arithmetic and check document claims. The earlier integration rechecked 4,320 numeric entries and all 12 comparison summaries; the current build additionally validates the plotted state cells, timing ratios and bootstrap endpoints. Fully independent replay of private archives, new hardware measurements, direct implementation comparisons to nearest deterministic methods, different model families, stochastic sampling, and concurrent throughput remain outside this baseline. These gaps materially constrain method novelty and generality even when the present artifact is internally consistent.
