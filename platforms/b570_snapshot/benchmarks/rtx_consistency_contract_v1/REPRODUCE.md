# Reproduction and provenance

This directory is a private HeteroSpec experiment, not a contribution to upstream llama.cpp. It extends main e87291d, draft diagnostic plan #57 and efficiency pilot #58. The original RTX source/assets/results must already have been prepared by `scripts/platform/rtx_target_verification_intervention_v1`; this experiment deliberately reuses their pinned customized source, parser, prompts and immutable native references. A clean upstream checkout alone is insufficient.

Set `HETEROSPEC_ASSET_ROOT` to the existing asset root (default `D:/HeteroSpec-PC`) and `HETEROSPEC_RTX_STUDY_ROOT` to the historical intervention workspace (default `D:/HeteroSpec-RTX-Target-V1`). Python3.11, the existing Zig/CMake/Ninja setup and released b10839 CUDA DLLs are required. No weights/toolchains are installed by these scripts. Model/runtime hashes are in SOURCE_BINDINGS and ASSET_CHECK files. Windows/cmd wrappers for Zig archiving remain assets of the prior workspace. Do not overwrite historical results or run incomplete directories again.

`generated/` and `runs/` are ignored. Inputs/results contain historical absolute paths as provenance; `run.py prepare` and `run_cost.py prepare` can regenerate input contracts against a relocated historical workspace before freezing a new replication. All source commits recorded in results are commits in the original isolated experiment Git repository, not commits of the HeteroSpec paper repository. FROZEN_SOURCE_INDEX records their file hashes; the local content-addressed archive includes a complete Git bundle, all run bytes, private binaries and the exact generated source. Large model weights and released runtime DLLs are excluded from both GitHub and the archive.

## Replication sequence

Use a fresh work directory and commit each implementation/configuration before inference. The original execution ledger records stage-specific source versions and binaries; latest source alone is not a claim to reconstruct every earlier build byte-for-byte. Engineering used the pre-formal capture version; the unused-logit restoration correction only affected the subsequently executed fork branch. Use the Git bundle for an exact source checkout of any historical stage.

1. Prepare fixed contracts with `python run.py prepare`, then `python build.py`. Original graph patches must be absent for the causal matrix. Freeze implementation, execute `python run.py engineering` (12 complete trajectories) and, after qualification, `python run.py formal` (24 donors/48 forks). Run `python analyze.py`. Capture/sham must preserve full historical arrays and the source context. Same-path fork decisions must match naturally reached native decisions. Fresh forks use the exact cache and sampler plus carried pending ID; previous logits are not serialized or consumed.
2. Apply `python attention_patch.py --max-queries 2` to the isolated generated source, rebuild CLI with `python build.py`, and build server using the configured CMake `--build generated/build --target llama-server -j 4`. Freeze, execute `python run_attention.py`, prepare cost inputs using `python run_cost.py prepare`, freeze again and run `python run_cost.py run`. Analyze with `python analyze_cost.py k2`. The original incomplete `runs/cost/` contains a zero-model preparation failure; the complete panel is `runs/cost-v2/`.
3. In that isolated source, apply `python attention_patch.py --max-queries 4` followed by `python query_batch_patch.py`, rebuild CLI/server, freeze and execute `python run_wide.py qualification`. Keep both predeclared candidates and failures. After qualification and a frozen ordinary-k3/four-condition cost protocol, run `python run_wide.py cost` and `python analyze_cost.py k3`. The ordinary baseline's timing is diagnostic when it fails the output gate.
4. Preserve wide binaries with `python disable_observer_patch.py` (one-time operation), rebuild CLI/server, freeze and run `python run_matched.py qualification`. Capture is disabled. Only after both modes match all four original probes, freeze and run `python run_matched.py cost`, then `python analyze_cost.py matched`. Target-only and speculation share UB4 and query-batch prefill; speculation alone adds the0.6B drafter. This is the primary incremental-speculation cost panel.
5. Run `python audit.py` only after all panels complete and resident measurement has stopped. It verifies recorded hashes/IDs/source versions, repeats, warmups, model/runtime immutability, commands and available logs. Detailed service-loader layer/UB values are suppressed at default verbosity; CLI qualification parses these separately. This limitation is explicit in the audit.

The scripts retain every attempt and fail rather than retry an incomplete directory. Full-request durations exclude resident model startup/teardown and the declared warmups; native generation durations are elapsed intervals, not isolated target-kernel sums. Aggregate speedups are geometric means of19 per-task ratios of repetition medians. The client sends only prompts and sampling/cap settings; reference IDs and diagnostic proposal tapes remain offline scoring inputs.

## Scope and audit correction

Both target and draft Qwen3 graphs are constrained, including prefill and continuation. Projection/FFN/output layers retain batch widths. This is not a target-only operator ablation or a universal bitwise-invariance proof. All19 tasks were exposed before this experiment. No functional HumanEval accuracy, reserved Stage C holdout, cross-stack transfer or production release is claimed.

In the original wide panel, `*_COMMAND.json` has a coarse `attention_constraint=true` boolean even for `ordinary_k3`. The frozen runner sanitizes inherited HS variables and sets neither attention flag for that condition. Its condition label, exact command and frozen runner define the actual unpatched baseline. Original bytes are retained, with this correction in POST_AUDIT; future matched-panel records use explicit attention mode fields.
