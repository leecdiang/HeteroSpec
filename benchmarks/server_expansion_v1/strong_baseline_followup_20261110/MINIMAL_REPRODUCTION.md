# 单一最小复现入口与本轮收口

此文件是**实现交付的验收合同**，不是声称运行器已经完成。当前可执行的只有本目录CPU结构检查与测试；backend-loop、native执行器、真实统计/转换器与下面的GPU入口尚未实现。不能拿 `design_checks.py` 通过代替它们。

## 1. 让后来者不必追几十个PR

后续实现/结果PR需提供一个稳定的顶层入口（建议名称 `REPRODUCE.md`，最终真实路径必须写回本README），通过一个manifest固定：

- 研究范围、选定graph政策、G/B/C源码与差异、pristine R独立性、模型准确文件身份/license；
- 可公开或明确可获取的源码包、依赖/toolchain版本、编译flag与取得步骤，全部SHA；
- 已授权者所需GPU/RAM/CPU/disk、预期时间、当前许可/窗口怎样填写，但不包含密码、私有UUID或个人信息；
- 输入数据快照/选择/暴露排除、确切roots与真实operand清单及各自身份；
- 一套参数化、仓库相对或环境变量指定的work/build/data/output目录，不硬编码上一轮私人目录；
- 原始receipt schema、完整资格与ledger、图政策决定、统计脚本、公开archive与private数值材料的边界；
- 从空目录依次复现的真实命令、每一步预期输出/exit code、已估算成本及失败停止条件。

固定源码/重建不能借用主卡旧ELF或oracle偷过独立性门禁。对不公开的文件，明确不可独立复算的层级，不能把公开hash清单写成“所有数值可公开重验”。最小路径只取本项需要的输入/参考与证明，不要求为了入门下载全部历史KV；历史证据仍可按固定链接追溯。

## 2. 在F0/F1之前实现并测试的部件

以下是必须提交的**实际程序及fixture**，不只是设计文字或一个 `passed:true`：

| 部件 | 输入→输出 | 至少需通过的fixture/负例 |
|---|---|---|

| native config echo | 完整job及解析后的实际runtime→同schema echo与实际module/dispatch/capture记录 | reserve8/32、UB、KV、FA、graph开关与实际复用不符；wrong backend、默默fallback拒绝 |
| 原始记录转换器 | 原始native、host、warm、ledger→每个逻辑operation的一行规范化记录 | 无序输入得到确定排序；重复/缺arm/缺round/缺warm、相邻warm输入不匹配、NaN/负/零duration、单位混淆拒绝；不同schema字段显式适配不静默填0 |
| S2描述分析 | 全四cell36测+36warm与counter→每次值/配对ratio/成本 | sum/geomean方向、host fence边界、工作量不同但数值合同相同；不得输出全模型服务预测 |

| 阈值/标签 | ratio与区间→范围明确的结论 | C至少1%须上界<0.99；B至少1%须C/B下界>1/0.99；跨1不称等价；1%不能被标为投稿门槛 |
| B2与第二卡分析 | 对应完整合同→独立描述表 | B2按process聚类；两卡相同根不能增加独立N或合池；主卡子集使用全部四轮 |

人工fixture必须标成synthetic，不当实验数据；真实旧fixture只验证读者能读，不转成新模型/新设备数值资格。检查器用显式异常而非可被 `python -O` 去除的assert承载科学门禁，普通模式与 `-O` 都跑。

冻结顺序：这些代码的完整源码、fixture和expected outputs先通过CPU测试；F0固定所有可能执行/分析分支；S1独立R与资格；最终graph决定/完整资格；F1全部回读；才有S2 clean。S3根选择、jobs和统计在其任何模型输出前F2冻结。转换器/统计后修正时保存旧版与全部失败，离线重检所有保存数据并披露时点，不追写“事前已通过”。

## 3. 实现入口应提供的安全分层

入口必须把以下能力分成显式模式，最终真实命令随实现给出，本文件不虚构现有命令：

1. CPU inspect/verify：只验证字节、配置、顺序、成本，0 CUDA/模型。
2. prepare/build：新目录构建、输出未资格manifest，不自动启动GPU。
3. qualify：必须有对应阶段的最新授权/窗口/资源与完整job账本，独立R优先。
4. run-one-registered-phase：只消费已资格、已回读的固定清单，没有自动下一阶段、可选B2或第二卡启动。
5. analyze/replay：纯已存数据操作，允许在无GPU机器独立复算；对不完整panel标partial。

干净重建验收可先在同卡新目录执行最小路径；第二卡复测是可选增强，并非“入口可用”唯一的证明。任何模型执行都需另行获准，不因为doctor/build成功自动启动。

## 4. 结题标准与贡献表述

满足三项即可关闭本轮，不继续为了空卡或好看的正号追加实验：

1. **三实现关系有可审计回答。** 合格三臂完整比较可报告正/零/负/不确定；B不能实现则报告确切阻碍并缩小声明。只有局部S2时，不称新根部署收益；需要部署主张才按条件完成S3。
2. **能力、机制、应用收益分开。** 独立参考兼容与mixed-type迁移是能力；局部操作/trace是机制；完整service是应用收益。G→B/C及B→C实现包差额不能自动命名成纯图/纯kernel原因。若强B吸收原group增量，诚实收缩group效率贡献，不能仅重命名B为框架组成部分声称原创新不受影响。
3. **最小入口真正可用。** 冻结实现能在干净目录获得必要构建/资格/记录，公开字节与统计可由入口重算；不可访问部分及失败/成本明示。

B2和第二卡可以DEFER且不阻塞以上三项。未做S3意味着相应部署主张缺失，不意味着必须无限补实验。实现尚未完成时也不能提前宣布本轮实验已结题。

附件的投稿概率只是审稿者主观判断，不写为本实验成功概率或验收指标；没有核验近邻工作的全部原文，本PR不添加新颖性/优先权断言。文献定位、主稿重构与投稿需另外的写作审查与用户授权，不通过实验设计PR自动修改论文。
