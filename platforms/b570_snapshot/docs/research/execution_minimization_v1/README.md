# HeteroSpec 下一步投入：执行简化的等价边界

**建议：只投入一轮有明确停止条件的“执行简化与机制辨别”研究。暂不继续自动修复选择器，也不把它称为已成立的新预测方法。**

本 PR 交付的是有证据绑定的研究决策、CPU 重算和待执行方案。机制实验、迁移验证及成本测量均未执行。本 PR 不编辑论文正文、已有结论或历史记录，便于与正在进行的论文整合并行审查。

## 具体问题和用途

**何时可以删除 live draft，以较小的执行复现原生 speculative decoding 输出；失败时，必须保留的是当前目标调用路径，还是已经形成的续算状态？**

这里的实际用途是复现和定位已有原生执行的行为，包括参考不一致行为。普通参考回退可以提供参考输出，却不能回答原生路径为什么产生不同输出。普通 U2 是第一基线；完整原生重执行是第二基线。保留 speculative execution 的理由是研究其已有故障，不是未经测量的生产加速需求。

预期贡献若成立，应是经过验证的执行简化条件和反例，而不是“再运行一个程序能够得到答案”。条件必须能由规定的执行合同和观测取得，不能包含未知的最终 token 答案；任何需付费取得的状态、proposal 或调用记录，都必须计入准备成本。

## 为什么选择这个方向

- RTX19 的 ordinary U2 完整复现 N1：19/19 任务，57/57 次重复观察；U2/N0 为17/19、51/57。同一个简单执行只能覆盖部分原生条件，形成真实的等价边界问题。
- B570 的 T0/T1 删除 draft 后分别复现 N0/N1，各72/72。这是两个手工、固定栈的成功实例；不能与 RTX 拼成共同实验矩阵，也不是一个跨平台规则。
- RTX /15 修复、/25 回退，/18 输出不变且仍偏离参考。复现原生输出和恢复参考需要分别评价。
- 当前 N0/N1 所选案例的初始 pending state/logits 相等，后续目标图占用不同；但后续相同真实前缀的 live state、U2 实时内部状态均缺失。这给出可以辨别的解释，不给出已经确认的原因。
- #56 已说明参考恢复选择器没有区别于简单枚举、U2 或参考回退的已测能力。此研究改变的是问题和用途，不撤销该 NO-GO。

67 是三个研究上下文的任务数之和；不同上下文分开报告，不能当作一个统一迁移样本。1005 个数组记录含重复与复用，不是本 PR 新运行。

## 投入顺序

1. **本 PR：**从封存数据重算等价关系，固定已知与未知字段，比较最近工作，给出实验合同、预算和退出条件。
2. **第一轮：**先完成状态导出/恢复和观测无扰动的资格检查，再在 /15、/25、/18、/31 上做真实共同前缀的状态 × 当前验证路径对照。它们是已暴露诊断任务。
3. **第二轮仅在门槛满足后：**冻结一个不读取未来答案的简化配方，在未参与规则形成的8个任务、一个新配置 k=3 上验证。不是“全平台普世规律”验证。
4. **用途评估：**与 ordinary U2、完整原生重执行、已有 H 程序及带 proposal 记录的目标重放比较。移除 draft 进程、数值工作减少和同边界时间收益是不同指标。

第一轮上限为36次新完整运行和48次短续算分支；第二轮另设上限78次完整运行，当前不执行。具体计费与定义见 [STUDY_PLAN.md](STUDY_PLAN.md)。这是投入上限，不是预定必须消耗的预算，也不是工期保证。

## 可以形成怎样的论文贡献

- **最好结果：**一个明确、可反驳的简化条件，在新配置上预测完整等价/不等价，并比 U2 的适用范围更准确；同时给出辨别状态和当前调用路径的机制证据。
- **次好结果：**条件只在一个明确区域成立，但得到非平凡反例与可复用诊断合同，可增强系统实证论文。
- **停止结果：**结果只重复“KV 影响续算”或“形状影响数值”，或者必须保留完整 live draft+target 数值执行且没有新增定位/复现用途。此时停止新方法路线，保留负结果。

最近工作已有固定形状验证、KV 修复、live/fresh replay 差异和双向状态交换。**在 Q8_0/CUDA 上重复这些现象本身不构成充分创新。**见 [RELATED_WORK.md](RELATED_WORK.md)。此方向只值得有限试探，不能承诺解决当前投稿竞争力问题。
