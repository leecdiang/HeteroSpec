# One coordinator, one ledger, multiple worker processes

`AccountingBroker` owns one `DurableMockBudget` for the complete operation manifest. Individual workers use `NativeAccountingClient`; they do not create a new ledger, STATE or allowance. The current broker mode is explicitly CPU_MOCK_ONLY. Its ACK means ACCOUNTING_ONLY_NOT_NATIVE_AUTHORITY. Every real native entry still requires the separate concrete `ProductionGate`, which permanently denies this build. No actual native worker was launched to test the broker.

The coordinator is bounded by a fixed manifest/run identity, finite client policies, at most1,000,000 commands, finite idle/overall timeouts and the durable budget's original fixed deadline. Commands reserve exact requests, rows, backend initialization, model loads, context creation and placements against the same aggregate counters. Worker request and deployment IDs are explicitly assigned; another process cannot reset totals or claim another worker's request IDs. Every client ID is accepted once. The broker must remain a single server-side process across all eight workers and two probes; a later approved controller must bind that one canonical ledger/socket/run/manifest in every worker configuration.

The protocol uses a four-byte bounded length and at most64KiB of TSV/hex data. Handshake and every ACK bind the same run and manifest fingerprint. Sequence numbers prevent duplicated/reordered commands. A worker receives ACK only after the corresponding durable pre-reservation is committed. These are **reserved** costs, not evidence of a native call having executed. Losing an ACK retains the reservation conservatively and stops; it does not refund work or permit a repeat.

Positive short transport writes can finish the same bounded frame; no command is replayed. Unknown/partial frames, EOF, lost or malformed ACK, identity mismatch, exhausted budget/deadline, duplicate/reconnected client or abandoned active request poison the attempt. Clients close and cannot reconnect or retry. The coordinator preserves ledger/STATE/uncertainty and stops instead of accepting a successor under another directory. Normal worker shutdown is an explicit CLOSE only after every assigned request has completed and the global active request is empty.

Sockets use a short private absolute path (Linux sun_path limit), owned0700 parent, owned0600 socket, no symlink traversal/overwrite, and actual Linux SO_PEERCRED UID verification in both directions. The ledger can retain its longer canonical path; its fingerprint/run identity is carried by the private socket handshake. This is local IPC, not an external service or a message to other users. Temporary mock socket names are not deployment credentials. An owned socket may be removed after shutdown only if its device/inode still matches the broker's socket; STATE and evidence files remain.

## Reserve before native ELF exec

A GPU-linked executable can have initialization arrays that run before main. A check only inside the model factory cannot account for those earlier effects. A later approved controller must be a separate CPU-only executable and must reserve a deployment before any native worker/probe fork/exec. Putting the launcher inside an already GPU-linked executable does not solve this ordering problem.

`launch_gate.hpp` provides `guarded_native_launch`: the concrete production gate is tested before connecting IPC, then a LAUNCH_ONLY client durably reserves placement, closes successfully, and only then may the caller's exec callback run. The current gate throws before IPC or callback; CPU tests verify the callback count remains zero. The helper is source preparation, not an authorized launcher.

Broker policies distinguish:

- LAUNCH_ONLY: only pre-exec placements and clean close; no requests/model/context/backend calls. Close fails unless every registered placement is already durable.
- WORKER: handshake requires its unique launch client to have completed with the required reservation. Its `before_placement` verifies and journals the existing reservation; it does not charge placement a second time. Backend/model/context/request/row counts still use the same global ledger. One launch client cannot cover two worker process execs, and two workers cannot reuse one deployment identity.
- CPU_MOCK_ONLY: explicitly synthetic fixtures that exercise ordinary counter sharing without a native ELF. This role is not an allowed substitute for a native launch policy.

For the proposed ten deployment actions (eight workers plus two probes), the intended native policy has ten launch handshakes and ten worker/probe handshakes; the cost remains ten placements, ten backend/model/context ceilings, not twenty charged placements. Finite socket clients/commands are control costs and must be included in the prospective operation/resource manifest. No such plan or GPU allowance is approved by this code.

The broker enforces accounting and launch escrow, not numerical qualification or study-stage order. The external controller must still enforce reference freeze, repeat-R qualification, cold-canonical bridge, single outstanding launch/quiet resources, exact source/configuration identities, and the stop rules. An accounting ACK must never be read as permission to start the next stage. Future native admission requires separately reviewed authority and truthful execution receipts.

## Bounded journal and recovery

Journal inspection streams8KiB chunks and lines capped at64KiB; it does not allocate the entire journal in RAM. New reservations are rejected and the attempt poisoned before the journal can exceed512MiB. A successful sealed ledger therefore remains within the reader's supported total-byte bound. The command/identifier limit alone is not a complete disk estimate; the explicit journal byte ceiling is part of resource planning. CPU tests include a provided synthetic valid hash chain larger than64MiB and verify inspection remains nonauthorizing. Those appended fixture records are parser input, not claims that real operations happened.

A new complete space proposal must retain the global journal, its archive and strict restore. At the512MiB journal ceiling, adding it to the earlier conditional capture calculation increases required space by1,621,350,154 bytes, giving553,094,505,923 bytes before any further actual-layout changes. This is a new unapproved bound, not an edit to the frozen earlier proposal. Extra opaque/canonical state duplicates, controller logs, actual build sizes and metadata file layout still need their own measured/bounded accounting before admission.

The std-only mock suite tests aggregate sharing across processes, row/context ceilings, partial/lost ACK, server crash after reservation, no reentry/reconnect, manifest mismatch, request scope, private paths/peer UID, finite idle expiry, pre-exec escrow and a zero native-exec callback. It never links llama, GGML or a GPU library. Actual model creation, vocabulary-only model creation, backend initialization, native contexts, placements and forwards remain zero.

`broker_cli.cpp` is a separate standard-only coordinator entrypoint. `--validate-cpu-mock CPU_MOCK_CONFIG.tsv.example` checks bounded mock syntax/identity without creating a ledger/socket. The source `--serve-cpu-mock CONFIG.tsv FRESH_LEDGER PRIVATE_SOCKET` path is finite, accounting-only and cannot start workers; actual server logic is exercised only by the synthetic private-socket fixtures. The example has a literal mock source digest and is not a granted study configuration. Native workers must not create this ledger themselves. No actual experiment JOB was served by this preparation.
