# Agent authority and repair policy

The user approved this bounded experiment and explicitly asked the agent to repair problems and continue. **Do not ask again after every successful stage.** Asset discovery, the pinned target download, building, the stated no-token capacity probes, E0/E1/E2 and evidence delivery are authorized when their guards pass.

## Repair freely, while preserving history

Paths, archive extraction, compiler/link commands, Windows API binding, JSON I/O, platform process monitoring, source-name parsing, audit metadata extraction, interrupted downloads and packaging may be repaired. Use minimal diffs, retain error logs, run the relevant tests and document before/after identities. Prefer read-only re-audit of already saved raw data to another native request. A failed command is not a new scientific result; an observed changed output is.

Before any generated output, the agent may correct generic 40-head/40-layer metadata and resource admission wiring. It may reduce offload according to the frozen24/20/16 capacity ladder. It may make one capacity/source-pool amendment based on pre-outcome facts and record it. Do not turn this into performance autotuning.

The authoring container has no RTX GPU or Windows toolchain; native compilation and true mixed-placement behavior are explicitly untested. This is expected host work, not a reason to request a new authorization. Generated worker uses existing sequence-state APIs; confirm the pinned headers' signatures. If serialization contains irrelevant padding, canonicalization requires an explicit schema and repeatability control before E1, never arbitrary byte dropping.

## Freeze boundaries

The runner intentionally refuses altered code/assets/inputs in place. For a CPU-only parsing/receipt repair, preserve the original FREEZE/audit under an immutable amendment directory, publish the exact diff and new test receipt, and bind the successor host-code hashes. Re-audit the identical raw files. Refreshing a freeze does **not** authorize modifying native arithmetic, inputs, endpoints, timer or statistical rule. If a completed native unit exists but the wrapper died afterwards, reconstruct its original receipts and use complete-unit recovery, not another measurement.

If a technical change requires a native rebuild after pilot, create a fresh epoch with new binary identity and include previous ledgers in `prior_ledgers`; rerun only the needed pilot controls within the64-request reserve. Formal inputs remain unexposed until E1. After formal outputs have been observed, a native mathematical change cannot silently reuse them as a confirmatory unseen panel. Stop this study with the original outcome; propose a separately identified confirmation only if it is scientifically necessary.

The formal estimator/panel/reference and native acceptance, rejection and position handling are not adjustable to rescue results. Genuine reference failure, nonfinite logits, unsafe memory pressure or unverified cleanup stops the affected stage. The agent may investigate the retained evidence, but may not widen the model/precision/context matrix or start a new optimizer search.

## Accountability without bureaucracy

Record each repair in AMENDMENTS.md: trigger, changed files, why scientific semantics are unchanged, tests, new hashes, extra native requests, and remaining budget. Compilation and raw reanalysis do not count as model requests, but still get process/time records. No hidden retry. Never remove a GPU lock until actual owned processes are confirmed gone. Never write to old experiment directories, old releases or old reference files.

A scientific negative or unresolved cost is an acceptable successful closeout. The task is to answer the fixed transfer question, not to obtain a positive percentage.
