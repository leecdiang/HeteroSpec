# Independent Linux deployment protocol

## Question and fixed scope

Does the frozen reference-compatible execution method survive a genuinely new
OS/toolchain/GPU deployment, and does it retain complete-service value against
simple same-contract controls? A company Ampere card is sufficient; eight cards
of one type are not eight independent algorithm replications. Start on one GPU.

Primary family: existing Qwen3-8B/0.6B Q8_0, C1024, F16 K/V, greedy, single dense
seq0, no FlashAttention, k3. Existing Smol1.7B/135M provides finite structural
transfer, not a mandatory second natural profitability sweep. D4 means draft
physical prefill UB4, not k4. No new model, quantization, router, cache architecture,
MMA or multi-sequence serving is introduced in this study.

## L0: authorization and read-only inventory

Record actual allocation and tool availability before source/build work or GPU
initialization. Default read-only `inspect` never selects or uses a device.
Only after an explicit UUID allocation may an agent initialize CUDA/model work.
Respect company/scheduler policy, existing services, storage and CPU limits. A
single-GPU UUID is forwarded through CUDA_VISIBLE_DEVICES (inside it is ordinal0).
An application on another GPU must be left untouched. A foreign task on the
selected GPU makes timing unsuitable: stop OUR worker and retain the attempt.

## L1: source rebuild, not binary translation

Fetch the authenticated pinned source kit and exact pristine upstream commit.
Reference and candidate cores are separate; all numerical modules are compiled
from source under the observed Linux toolkit and explicit architecture. Static
internal linking is an intentionally declared Linux build arrangement, shared
fairly across roles; system CUDA/driver libraries remain actual ELF dependencies.
No Wine, no Windows DLL, no numerical-module substitution, no implicit latest tag.

The provided source adaptation covers reviewed module enumeration/clock bootstrap
and explicitly disables the Windows-only optional profiler. Finish additional
normal POSIX/ABI adaptations if the authenticated snapshot needs them. Preserve
before/after source manifests and classify changes as portability, instrumentation
or arithmetic. Arithmetic changes require new qualification and disqualify a
claim of unchanged arithmetic migration; they are not automatically forbidden
research, but cannot be hidden inside a successful port.

Capture generated files, compiler transitive dependencies, compile/link commands,
response files, actual static archives, tool versions and ELF modules. Missing
source/SDK/compiler dependencies are engineering issues: fix them transparently.
CPU-only builds and fixture tests do not replace a complete CUDA build.

## L2: freeze independent R_Linux first

The provided independent driver is built against pristine upstream and never
calls a candidate policy switch. It sends the whole prompt caller through physical
UB1 with last-only output; subsequent known/generated tokens are evaluated singly.
Target-only reference resource residency is explicit. Thread count/context/output
reservation and all defaults are bound by source/runtime receipts.

Before any candidate outputs, compare repeated R vectors and committed state on
exposed inputs including the retained boundary witness. Inspect the original
Windows configuration for producer/default differences and disclose all intended
Linux settings before this freeze; do not retroactively choose an R that makes a
candidate pass. The same model files and token IDs are necessary but do not imply
cross-hardware bits. Old Windows R is immutable and is not replaced by R_Linux.

Independent reference jobs may receive candidate token IDs for forced-prefix
checks, never candidate logits/KV as the reference value. Free-reference endpoint
jobs receive only the original prompt. Reconstruct separate prefixes as necessary
to compare post-rejection state; don't trust a candidate's own history as truth.

## L3: finite native qualification

Reuse existing original-host trace/state readers and finite case design, adapting
paths/ABI only. The independent reference driver and `compare.py` supply a simple
source-rebuilt oracle and exact capture comparisons. Verify actual capture schema
and layer identity. Serialization metadata is not permission to ignore tensor
values. If whole serialized bytes differ for proven non-value fields, retain both
files and use the reviewed canonical active-KV extractor with a new version; never
weaken to text/top1 equality or an unregistered floating tolerance.

Cover: original producer/frontier; q1/4/8/32 inside/crossing/tail; originally
requested full vectors (including rejected branches where requested); active
committed KV; first/later rejection; pending token and trim frontier; native EOG,
cap1/cap128 and reset; target-only without idle draft; clean versus heavy endpoints.
Observe actual occupied widths rather than logical caller size. Qualification is
finite and its exact observation boundaries must be stated, not a universal proof.

All four W_L4/W_P/L_L4/L_P paths and both W_L4-D4/L_P-D4 pass before formal use.
Qualify shared rules on Qwen then apply frozen rules to existing Smol geometry.
Keep unsupported cases; don't add per-model-name or per-input/position exceptions.
Native active-state observers remain outside clean timed paths. Clean execution
has no online R replay, whole-KV migration or heavy dump.

## L4: one bounded transfer panel

Use the sixteen fixed PR195 Qwen roots from the authenticated source kit and two
separate previously exposed primers. Reusing input identities isolates deployment
transfer but is NOT new unseen-input confirmation. No selection by acceptance,
geometry or speed. Record actual token/template binding, EOG and cap; no padding.

Six arms: W_L4-M, W_P-M, L_L4-M, L_P-M (all real target-only), W_L4-D4 and L_P-D4.
Four predeclared cyclic sessions; each arm/session has one worker, one model load,
two primers then sixteen distinct requests with context reset. Total384 measured
requests plus48 primers. Four cyclic rows are not a full six-arm Williams design.
All four M controls remain. A scientifically unsupported arm closes that version's
complete comparative panel; fix/requalify before opening a new version, not delete
its slow/failing test observations. Development/qualification proceeds independently
of whether a useful performance candidate ultimately remains.

Primary comparisons: L_P-D4 against each fixed target-only M, plus L_P-D4 against
W_L4-D4. Root-cluster10,000 PCG64 draws, five-comparison Bonferroni percentile
intervals, preserving the four sessions within each root. Report absolute totals,
per-root and per-session ratios and geometric sensitivity. Conditional inference
on these sessions; no posthoc minimum-M test or arbitrary cross-study pooling.

Actual resident service includes reset, planning, output ownership, target/draft,
sampling and required synchronization. Test burst/first complete response/startup/
worker wall are actual clocks, not setup divided by N. First response is NOT TTFT.
No network endpoint/QPS or unmeasured asynchronous device-time claim. Unknown and
partial nested costs remain null with measured/present/expected counts. Profiling
uses separately labelled jobs, not the clean clocks.

## L5: bounded decisions and cost

Default ceiling2,048 logical model requests/4,000,000 reserved decoded rows,
including all references, failures and warmups. The provided runner conservatively
reserves before starting and never refunds failures. These are caps, not targets.
Default2 CPU compile jobs, max4 only within allocation;900s worker timeout;1GiB
GPU,4GiB RAM,20GiB output-disk reserve. Actual settings and resource feasibility
must be recorded, not reduced to force a claim. No automatic budget extension.

Do not buy compute or use all GPUs. A hardware/source incompatibility is reported
with the actual boundary. Source packaging and CPU work can continue even when a
GPU branch is unavailable. No additional rounds to push an interval below1.

After successful transfer, a C4096 natural study can be proposed separately; it is
not silently appended here. Final outputs distinguish build, qualification,
clean confirmation and selected archive readback. Same-host fresh builds are not
third-party replication. Do not update the paper or merge the result PR automatically.
