## What causes the negative opportunity finding

At each user node, the actual template renders the complete supplied history. The declared hypothetical previous producer stream is previousgenerationprompt tokenIDs + separately tokenized supplied assistantbody + supplied EOG151645. Its final EOG is pending, so the predicted materialized head is length−1. These are provided/teacher-forced history predictions, not a native greedy chain, free session or observed cache head.

Before any state mutation, compare complete token-prefix identity against the next canonical full-template prompt. A mismatch requires the same predeclared full reset/rebuild for every method and charges it in full. Reuse would include the pending token exactly once. All native heads and physical cache observations remain null/unobserved.

The pinned nonthinking generation prompt appends an empty think stub. When the next user arrives, canonical rendering of the earlier assistant removes this stub. Independent reconstruction finds that **all1,127 first token differences are exactly at that four-token stub's start**: oldtoken151667 is<think> in every case; the next canonical token is never that token. Full supplied content and template suffixes were retained; this is not a string-LCP shortcut.

Consequently every capacity-admitted execution prediction is initial or common-rebuild prefill at head0.
