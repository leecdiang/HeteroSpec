# Windows V2 source and cost map

This explanatory map was written during the frozen panel, after inspecting the already compiled V2 source. It introduces no implementation, numerical, timer, input, order or statistical change. Exact source/objects/link dependencies are in `results_20261109/SOURCE_BINDINGS.json`; the actual compiled frontend is retained under `results_20261109/candidate_frontend_v2` and in the complete archive.

| Path and operation | Actual behavior and clock boundary |
| --- | --- |
| `resident_context.hpp:20`, `PhaseContext::decode` | Reads dense-cache append requirements and F16 K/V types; does not inspect token contents or move KV bytes. SIMPLE groups by actual extent up to32; LOCAL retains projection groups up to32 and uses the bound local-attention backend. Runtime reserve is explicitly8 for both k values; the header's default4 is overridden before context construction. |
| `resident_context.hpp:38` | `outputs.assign(ids.size(),{})` owns per-caller output storage. All wanted full-vocabulary rows are copied before a subsequent native group can overwrite logits. `requested_rows` contains caller-global indices, including after a SIMPLE split. This is the postprocessor repair's indexing contract. Storage clear/allocation and trace JSON work remain within service, not wholly attributed to `output_copy_s`. |
| `resident_context.hpp:47` | Target phase clock starts before `llama_decode`, includes batch free and explicit `llama_synchronize`, ends before owned-output copies. These are inclusive host clocks, not CUDA kernel timings. The independently instrumented native `process_ubatch` histogram, rather than caller width, supplies physical-width evidence. |
| `worker.cpp:91`, reset | Clears plan/output state, trace and phase counters, clears target/draft KV, requires empty sequence. Contexts remain resident. Graph cache reuse is checked from native counters. There is no per-request context recreation, state export/import or hidden reference replay in clean service. |
| `worker.cpp:130`, request | `service_seconds` begins before reset/setup and includes target/draft prompt prefill, greedy full-vector scans, all drafting (including eventual unconsumed proposals), synchronized target verification, required copies, acceptance/correction/bonus processing, KV trims, stop handling, trace/endpoint construction and recorded teardown. Resident model loading and context provisioning precede requests. |
| `worker.cpp:178–195`, lifecycle | Draft seed synchronization precedes k proposals. Target verifies seed+k and samples every requested row. A mismatch emits correction, full acceptance may emit bonus, cap/EOG stop immediately. Retained target KV is seed+accepted positions; pending token may remain unconsumed. Qualification independently reconstructs this convention and checks active committed KV/frontier. |
| `entry.cpp:102–126`, clean output | A returned service receipt is enriched with physical/planning/API counters, then its first-result timestamp is taken, receipt JSON is written, marker flushed and cumulative result JSON updated. Receipt-file I/O is outside that request's `service_seconds` but contributes to worker/burst windows. The marker contains a pre-record timestamp; observation latency is separately recorded. |
| `same_work.hpp:17–32`, setup | Prefix construction, initial frontier copy, sequence save/reset/import/synchronize and initial file export happen outside both primary operator timers. Save/restore are subsets of setup, not additive independent totals. Both target/draft models and contexts are resident, but no draft calls execute. |
| `same_work.hpp:34–44`, equal work | Both arms consume the same eight tokens. Operator time includes native synchronized decode and owned full-vocabulary materialization, including the extra external eight-row ownership layer on both sides. q4pair copies the first four rows before the second decode; q8 copies eight once. Required exact histograms are `{4:2}` and `{8:1}`. |
| `same_work.hpp:48–60`, post-timer | Clears temporary plan outputs, then checks/writes the eight externally owned vectors and exports final state. This validates lifetime after the second q4 and clear. All file/state export costs stay outside both primary timers and remain in separate post-timer elapsed cost. |

The target and draft phase clocks, setup/teardown, planning and owned-output-copy clocks have explicitly different scopes. `service − recorded components` is retained as an unassigned residual. It includes uninstrumented work and clock boundary effects; neither its sign nor size establishes logging, launch, allocation, kernel or graph costs. Cumulative wrapper/worker/load/setup/first-result/burst windows overlap and must not be added.

`m2_tapes.hpp` builds owned proposal vectors and position-indexed tapes outside timing. Live and replay use explicit permission/hash/prompt/seed guards. Full-vector ownership and negative-contract checks are qualification evidence, not formal speed observations. No profiling run was executed; graph build/reuse counters do not substitute for CUDA graph profiling.

The V1 and V2 frontend epochs are preserved separately. All clean diagnostic and live timing use V2. Original scalar R, the numerical static libraries, CUDA DLLs, model files and historical data remain immutable and separately hash-bound. The public text packet contains source and receipts; complete binary operands are retained in the local lossless archive. Public delivery and statistical recomputation do not establish qualification on a second machine.
