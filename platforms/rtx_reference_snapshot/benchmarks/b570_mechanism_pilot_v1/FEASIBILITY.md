The old `observer.move` performs three complete serialized state readbacks even in capture-off: source before, restored destination, source after. It creates a second context, synchronizes those readbacks, transfers state, and checks ownership, pending, clone metadata and equality. This is real online witness cost. Capture-off excludes writing those large witnesses, not the operations. Old whole/generation timers include online initialization, transfer, draft, rollback and terminal barriers. Cold model/session creation and session destruction have separate receipts. Explicit call counts are not operator durations, and internal runtime synchronizations, dispatch identity and board energy are unknown. Published cost ratios remain baseline/candidate, larger than one faster: shared R/N1 0.1885246521769912 generation / 0.17905546046949286 whole. T/N1 0.8040229271596392 / 0.6935408122196928. These do not establish that all lost time comes from witnesses.

New feasibility implementation captures real target and draft API states immediately before natural target verification, after the actual current proposal has been generated. It includes committed raw IDs/EOG, pending, positions/ownership, counters, sampler accept histories and real clone metadata, draft distributions, and explicit logical batches. No reference is available to the C++ forward process. Restored continuation starts with that saved actual batch, then generates all later proposals naturally. No KV reconstruction from answers and no future tape. Checkpoints are restricted to the frozen 17-length window preceding the retained divergence. Diagnostic capture-off still includes these bounded checkpoints; StageA timings are diagnostic only, never formal speed evidence.

The published sampler API has no serialization. Restoration replays only already-accepted actual token history into the identical effective greedy chain and clones it. No model decode is involved. The stochastic RNG cursor is not serialized; support is limited to temp0, identity penalties, empty grammar and unlimited reasoning. Source clone chain/history/seed checks plus full raw continuation shams are required; this does not certify opaque sampler byte equality or general stochastic restoration.

Two current recipes preserve the common parent batch IDs, positions, logits mask and sequence. UB and output reservation remain the parent's complete recipe. The /72 N1 and N0 continuation recipes coincide (UB1, k2/reservation3); this is a duplicate current-path control for state sensitivity, not a manufactured UB intervention.
