# Repair the execution path before scientific attempts

The PR112 v5 source accepts an event only after `allowed(path)` succeeds; rejected action/path/raw bytes are not durably recorded before the exception. CPU_TEST also permits direct children of storage roots whereas production does not. These are coverage/diagnostic gaps, NOT a proven identification of the original writer or a license to ignore notifications. Old v4/v5 remain invalid and terminal.

Use three disjoint roles: sealed source/assets, mutable per-run outputs, and bounded monitor/controller journals outside both. No runtime writes under source/results, including pycache, generated receipts, approval notes or logs. Set no-bytecode behavior explicitly and bind import paths. Freeze after compilation and all preparation receipts; authenticate the actual frozen snapshot. Separate output data from watcher evidence to avoid journal notification feedback.

Persist raw FILE_NOTIFY_INFORMATION bytes, action, relative path, reception monotonic time, watch identity and error/overflow BEFORE rejection in the external bounded journal. Do not claim the notification identifies a writing PID or exact operation time. A separate bounded CPU trace may attribute it where available. Do not blanket-ignore ancestor directory events, metadata changes or sealed writes; reproduce/resolve their classification under the actual topology. Notification loss remains a terminal integrity failure.

Use the SAME production decision function for CPU exercise and scientific jobs. A dummy CPU child may replace the executable, but it must not enable more permissive directory policy. Exercise the actual launcher/import/receipt order, prelaunch snapshot, normal output creation, post-exit archive boundary, and intentionally changed sealed files. Record expected negative tests; never mislabel their intentional errors as scientific retries.

Establish a valid source lease and baseline before native launch. During native lifetime use bounded active-output accounting, reserved worst-case output and periodic external owned-PID resource sampling; do not recursively scan all accumulated history for every100ms sample. Full immutable hashes occur at bounded pre/post boundaries; events cover the live interval. Validate the initial/terminal observation semantics with the real child lifecycle. A post-exit audit duration is not a live sampling gap.

External safety observer: nominal100ms, effective gap ceiling1000ms, actual timing retained. Old R's internal VRAM data remain checkpoints. Never relabel them as100ms periodic data. Bind the same external safety instrumentation for old/new actors where technically possible, and report its costs. No continuous-residency claim. Instrumentation-heavy numerical captures are separate from paid counts timings.

No weakening an old freeze, silently expanding writable roots, dropping pending notifications, deleting failures, or restarting a used registration. New implementation is separately frozen and tested. S0 has at most two integration revisions within its CPU/time limits. If a genuine monitor failure occurs during S1/S2/S3, stop the scientific stage and deliver evidence; do not loop into v6/v7 until it passes.
