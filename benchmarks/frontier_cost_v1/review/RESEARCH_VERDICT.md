# 独立研究判决：从 1–2% 走向约 5% 的剩余机会

**目前不能把结果包装成已经成立的新投机解码方法，也没有证据承诺普适的约 5% 完整请求收益。** 最有价值的下一步是辨别一种具体、可被否定的机制：在相同数值参考与终止状态下，合法执行计划能否减少真实共享开销或无用工作，且收益足够覆盖重新读取权重、同步、控制和状态收敛成本。

本判决重读了已封存的算法、强基线、文献与原始结果审稿；没有重新测 GPU，也没有把旧 hindsight 分析作为新的实验。本轮的离线 artifact 准入反例解决“什么证据能进入控制器”，不提供加速；新增的旧轨迹因果预测回放与 host 实现检查也各自保留其范围。

## 1. 应停止作为主要正向故事的方向

| 方向 | 判决 | 具体理由 |
|---|---|---|
| 最后一次 draft q1 延后、cap 截断 | 放入共同工程基线 | lazy-tail 已有主流实现先例；本项目完成有限 CPU 集成值得保留，但不能把对旧冗余实现的修复当作新方法独立收益。cap 截断也必须同等给比较器。 |
| 串行 drafter 先生成 k7，再固定 q4→q4 reveal | 降级，不再首推 | 在旧轨迹同等给予 cap 规则后，split-k7 为 3,520 calls / 13,960 rows，k3 为 3,504 / 13,944；前者还预付长 draft。它没有从调用/行数取得优势。此计数不证明任何硬件上绝对更慢，但已否定“更少 target 工作自然带来 5%”的解释。 |
| 仅把普通 adaptive-k 加硬件成本并改名 | 新颖性不成立 | 既有封存审查已包含 TurboSpec、PEARL、native adaptive verification 等直接先例；成本感知、分段、KV frontier 管理都不是单独的新点。 |
| N4 Rows2 的寄存器“优势” | 已被公平编译控制推翻 | 相同 launch-bounds 下双方 64 registers；无 bounds 时原生 48、候选 53。旧 64→53 不是可归因算法优势，且没有 GPU 速度证据。 |
| 将新 CPU q2 失败解释为 GPU 路线已不可能 | 不成立 | 失败确证了该 CPU fixture/shape 的完整向量与状态不兼容；算术原因未定位，更不能外推到另一后端。它要求先做资格，而非宣布所有细粒度执行没有机会。 |

证据见旧 `algorithm/README.md` §4–6、`literature/NOVELTY_REVIEW.md` §2/4/6，以及 PR221 的 `CPU_WIDTH_FAILURE.json` 与独立 raw 审计。文献先例判断来自既有固定版本审查，本轮没有追加未读论文或新的首创判断。

## 2. 旧计数真正允许什么推断

16 个独立 roots 的已展示、知道未来结果的路线，在共同 lazy-tail 后有以下计数：

| 路线 | Target calls | Target rows | q4 算术组 | 全部 draft q1 |
|---|---:|---:|---:|---:|
| 固定 k3 | 438 | 1,752 | 438 | 1,604 |
| hindsight 仅 k3/k7 | 287 | 1,752 | 438 | 1,604 |
| hindsight 扩展 k1…7 | 287 | 1,479 | 438 | 1,429 |

减少调用并不等于减少主导算术组。只允许历史 k3/k7 时，target rows 和总 draft q1 都没有减少；扩大 horizon 集合后，q4 groups 仍为 438。若目标执行成本主要由四行组决定，少 273 行不会自动成为等比例的 target 时间收益。新增小宽度和新物理前沿也尚未取得 GPU 参考资格。

旧完整服务代理在共享 lazy-tail 后以 180.178899 s 为分母；展示路线在额外 target 固定成本 A 与新增成本 H 均为零时，再省 3.575693 s，即 1.9845%。其模型为：

\[
T_{\mathrm{candidate}}=180.178899-3.575693-1208A+H.
\]

在**这个特定假设模型与路线**中，达到 5% 完整时间下降需要 `A ≳ 4.498 ms + H/1208`。A 没有被测得，不能用另一硬件或不同历史的 q8/q4 比率补进去；它也不是纯 CPU launch overhead。1,208 次 draft sync 和 192 次 proposal q1 已分开计价，不能再次塞入 A。

这不是所有策略的时延上界。某一展示路线没有余量不证明整个研究域无解；同样，hindsight 有余量也不证明因果策略能取回。旧两条简单历史规则已出现终态不合格，不能拿其有利成本路径单独报告收益。详见 `PREFIX_ORACLE_REVIEW.md` 与 `service_proxy_section.json`。

## 3. 仍有实质机会，但必须各自有证据

**同一候选工作的合法执行组合。** q8 相对 q4+q4 可能共享权重读取、kernel/graph 固定工作和同步，也可能因为更大形状、寄存器或 attention 路径变坏。机会来自实际执行差异，不能从 API 调用数直接推出。要保持原 R 而获得更便宜的合法细粒度计划，才可能形成体系结构贡献；严格 schema 或给已有阶段改名不构成这一机制。

本轮对旧 B2 原始公开摘要的独立算数复核显示：packed 两个 boundary 的局部点下降约 6.301% 和 5.243%，但在同样操作数、所有替换窗口都具有该比例、其余工作不变且无新开销的假设下，完整服务下降 5% 分别需要约 79.35% 和 95.36% 的基线时间覆盖率。loop4 两个点的条件覆盖率均超过 100%。这不是实际服务上界，更不是跨部署预测；不能把 B2 的局部比率与 RTX 的 phase 占比相乘。它说明局部 5% 已有先例，而独立服务 5% 仍取决于合法可替换工作的规模。复算见 `ECONOMICS_AUDIT.json`。

**有因果信息的短段继续决策。** 仅当先做短段后，条件性的 suffix 避免收益超过额外完整 target pass、控制与收敛成本时，分段才值得执行。对串行 drafter，应比较先 draft 短段、必要时继续的同等强基线；对一次生成整块的 proposer，已付草稿成本不同，是另一适用域。不能将两者的优势混用。

这里有已知但容易在新实现漏掉的状态义务：首段 `[seed,p1,p2,p3]` 的四行 logits 能判断 p1…p4，而 KV 只物化到 p3。若接受到 p4 并因 CAP/EOG 结束，仍须补齐被原契约保留的 p4 KV；继续路径则从 p4 开始下一段。目标与 draft 的补齐、trim、pending/bonus 状态都应计费。宏操作 `T(4+4)` 不能拆成两个凭空可用的 stage cost。

**跨请求异质分配。** 混合长度、物理 extent、graph bucket 或共享 KV 带来的同总工作量成本差，仍值得做有限诊断。但该问题需要至少两个并发请求，不能解释原单请求的 1–2%。已封存 PACE、DSpark 等邻近工作也限制其新颖性；有用的新证据应是 SD/reference 约束下确实存在且可利用的残余执行机制。

## 4. 哪个下一观测会改变判断

| 下一观测 | 会支持什么 | 否定/停止条件 |
|---|---|---|
| 原模型、已分配 GPU、同一历史下各候选相对明确原 R 的全向量/状态/continuation 资格 | 建立该部署的合法动作集合 | 任一失败动作不进成本表；CPU失败不代替这个结论。q1 诊断参考尚未桥接到历史 R，不应因它的 q2 失败封杀另一种 q4↔q8 合法候选。 |
| 同一合法状态、同输出义务下 q8 与 q4+q4 的干净配对成本，以及原生长期 graph 状态 | 确认实际组合收益是否值得进入控制研究 | 收益只来自首次建图、state export 或未共同给基线的配置，则不支持在线收益。现有 capture-conditioned probe 不是这张干净成本表。 |
| 每个分段接受/拒绝/终止 outcome 的完整收敛成本与共同终点 | 允许因果控制器计算有效动作价值 | 缺 p4-terminal 补齐、draft catch-up、另一分支或终态资格，控制器应 abstain。 |
| 同强基线、完整请求窗口下冻结策略的收益 | 判断能否超越 1–2%，而不是只优化小窗口 | 不允许事后删失败、用未来 accepted、未知 bit 当接受或把多次 session 当独立任务。 |
| 未参与校准的模型/任务/长度/硬件负载，包括不利配置 | 支持明确适用域内的可迁移性 | 只有一种 extent discontinuity 或特定 offload 成立，应按该适用域命名，不能宣称普适 5%。 |

应先做能判别瓶颈的成本与资格实验，再投入训练复杂控制器。若合法计划之间没有足够净差异，预测再准也不能制造收益。若差异存在但新增同步/状态处理吃掉它，应转向执行层；若剩余收益稳定存在而简单固定策略拿不到，才更有理由投入控制算法。

**我的当前研究判断：工程基线修复已有可靠进展；普通两段 reveal 与泛化的 adaptive-k 叙事已不足以支撑目标。仍可追的是原参考约束下、真实架构成本驱动的合法执行组合，但目前既没有生产动作资格，也没有干净 stage 成本。新版 controller 的正确当前行为是 abstain；这使后续实验可信，不能被写成已经达到约 5%。**
