\paragraph{Evidence and ordering.}
B570 is an exposed-cohort intervention following target-only discovery and reserved prediction. Its local prediction seals precede native execution in retained process records. RTX freezes implementation commit, protocol, cohort, queue and source hashes, generates 258 H predictions and proposal tapes, records remote readback, then starts the native paths. Server readback supports the reported ordering but does not authenticate an independent absolute experiment clock. The two seal modes are not equivalent external time certification.

The RTX audit reconstructs the main 24-part archive in a clean directory, checks the compressed bytes and digest, verifies the CAS manifest and logical-file reconstruction, and independently parses selected complete attempts. Its pre-archive report snapshot and later Git delivery receipts are distinct time cuts. No requirement that a final receipt hash itself exist in the older archive is imposed. Weight and external/new runtime binary omissions retain identities; this offline review does not rehash omitted bytes or independently execute the models.

\paragraph{State handoff and shams.}
The first pending token is sampled and accepted once in the source. The handoff retains checked KV, pending logits, positions, caller grouping and post-accept sampler clone witnesses. Opaque sampler bytes cannot be serialized, so no byte-equality claim is made. Same-boundary unchanged-capacity shams test the transfer path. RTX's overwritten random draft draw is not the final ordered proposal: the behavioral comparison uses realized proposals/decisions and output, while excluded observer fields remain available for inspection. This does not assert every raw field is identical.

Historical native outputs used default 12 threads despite an older 24-thread description. \subsection{Constructing and testing the descriptions}
These are manually written candidate programs for fixed stacks, not an automatic extraction procedure. B570 removes draft execution: the target program prefills at the condition's capacity, samples and accepts the first pending token once, carries checked state into UB1 continuation, and greedily emits the endpoint-bounded sequence. Its successful equality establishes a draft-free reproducer on this cohort; it does not prove that draft work cannot affect other configurations.

RTX preserves live proposal feedback. Separate proposal and target processes initialize from the prompt. At each round the proposal worker receives the current pending token and position and generates up to two proposals from its own state. The target worker checks its own pending token, verifies pending-plus-proposal IDs and computes correction/bonus decisions. The coordinator commits visible IDs, updates the proposal context and reconciles inconsistent suffix state. Prediction records include chained proposal requests and their past-prefix hashes. Native CLI receives its own prompt/assets/parameters and runs its own draft; it does not read those records. The changed condition transfers the target context at the declared post-prefill boundary while retaining caller grouping. Shared numerical routines remain essential components of the description: matching these outputs is not evidence of numerical-implementation independence or execution compression.

For MBPP/304, the sealed baseline and intervention programs respectively forecast 488 and 481 at index 33; their complete 47-ID EOS arrays match the corresponding native paths. Both differ from the reference. This is a concrete prospective output prediction, not a claim that the prediction algorithm is cheaper than native execution. The ordinary reference gate already suffices to reject the recovery candidate; the description adds the predicted trajectory and a testable reproduction contract. Historical target-only and proposal-conditioned candidates remain separate earlier hypothesis tests (Sections J, M, N and S).
