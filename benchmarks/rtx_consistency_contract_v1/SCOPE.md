# Interpretation boundaries

The causal crossing changes only the current TARGET verification capacity while carrying real target donor state and the same recorded proposal input. Its state/current-call conclusions are limited to the four fixed natural checkpoints, three repetitions and this numerical stack. Logical K/V comparisons are decoded from the pinned architecture/memory serialization and cover every byte; unused previous logits and actual sampler clones are handled separately.

The optimization prototypes are a different, subsequent experiment. The opt-in `llm_graph_context::build_attn_mha` guards select Qwen3 graphs, FA off, one physical KV stream and at most2/4 queries. They apply to BOTH the 8B target and 0.6B draft graphs because both use that architecture. Prefill and continuation receive the same attention constraint; projection/FFN/output operations keep their batch widths. This is a whole-path candidate, not an isolated target-attention ablation. Target-only versus draft-only application, unique-operation attribution and minimal-constraint sufficiency are NOT_EXECUTED.

Moving query columns to a batch axis changes the eligible existing numerical path and layout. Views and broadcasts preserve the mathematical attention/mask operands, but kernel dispatch, cache-padding boundary equivalence, all-logit equality and engine-wide bitwise invariance are not proved by generated-ID agreement. The finite complete-output gate must not be relabeled a universal losslessness theorem. First-layer K/V equality in donor comparisons motivates the candidate; it does not uniquely identify attention as the only possible source.

Cost results use the same private frontend within each panel. Metadata capture, live forks and state exports are disabled. In the k2 and initial k3 panels, the inherited observer wrapper still creates decode metadata and synchronizes even when emission is disabled; sampling/first-pending hooks also remain. Those costs are included consistently and can interact with different call counts. The subsequently frozen matched-prefill panel bypasses this metadata/synchronization work when capture is disabled and gives target-only the same UB4/query-batch prefill as the speculative candidate. Cheap disabled hooks remain; this is an observation-disabled private frontend, not an independently verified byte-identical released frontend. Actual full-request and native generation-timer results are distinct; prefill savings alone do not establish decode acceleration. Default service logs suppress detailed loader placement/UB messages; argv/source and CUDA enumeration are audited, and separate CLI qualifiers parse full placement/UB logs.

All19 HumanEval tasks are already exposed; the four qualification tasks and the k3 configuration follow-up are not a reserved new-task evaluation. Caps128 compare committed token IDs/EOG boundaries, not functional code success. No energy, multi-request throughput, confidence interval, cross-model/backend transfer, automatic diagnosis, production release, new causal kernel proof, first/unique novelty or venue success is established here. The existing LLM-42 and batch-invariant-inference literature remains an explicit baseline.
