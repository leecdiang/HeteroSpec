状态：仅方案，尚未执行。完整英文协议以 [PLAN.md](PLAN.md) 为准。该 PR 只增加文档，不改任何已有代码、基线、结果或论文。

## 研究问题

M2 的 q8 指验证宽度 8，不是权重量化格式。已有结果证明 q8 能正确执行，但 k7 在四个已暴露输入上比 k3 慢约 14%–15%。本轮不是预设它应当获胜，而是核实是否有可修复的实现开销，以及修复后是否改变宽度选择。

## 给执行者的 prompt

请先阅读本目录 PLAN.md 及固定来源 PR #209，不要立即启动 GPU。

1. 先做零 GPU 的代码与现有记录审查：闭合模板、变换脚本、生成代码和实际编译产物的关系；核对输出所有权、分配、同步、计时边界、最后一轮 draft 和 cap 行为。重算阶段耗时，未测量的部分明确写未知，不把 residual 当作日志开销。
2. 如果仍需实验，准备执行 manifest 和资源准入报告。当前历史预算为 1826/2048 请求，只有快照余量 222；必须读取最新累计账本。预算不能因创建新目录而重置。缺少实际服务器授权、窗口、GPU UUID、参考资格、精确任务或行数预算时停止，不抢占公司服务。
3. 优先做同初态、同八个 token、同八个完整输出的两次 q4 对一次 q8 诊断。分别固定 loop4 和 packed，覆盖真实 256-token extent 内与跨界。先验证独立 R、全部向量及状态，再测量。不能用接受率不同的两条生成轨迹冒充等工作量。
4. 只有发现实测热点才做一版共同优化。k3/k7 都用同一新版实现；保持全向量输出和所有权。末次 draft 前向删除、cap-aware proposal 等涉及状态语义的改动不在本轮快速优化范围内，不得直接当死代码删除。
5. 资格通过后，使用同一时段的旧/新实现 × k3/k7 四臂 LOCAL-packed 小 pilot，包含 32 测量和 16 primers。不得只优化 k7 然后与历史 k3 相比。所有输入已经暴露，结果只作描述，不给总体优越性结论。
6. 任一阶段可以因没有收益机会、预算不足或资格失败而正常结束。不能为了让 k7 获胜自动追加配置、输入或轮次。
7. 32B 是独立条件分支，本协议给它零 GPU 预算。已有 UB32/reserve4 smoke 不是 UB1/reserve1 的独立 R。先厘清混合 Q4 类型和算术支持，另行批准资格方案；不阻塞论文重构，不自动跑计时。
8. 保留所有失败、源版本、原始与派生哈希和累计成本，输出可回读的结果或停止报告。禁止改旧基线、合并 PR、Release、删数据或提交论文。

## 交付判断

- 代码没有足以改变选择的问题：保留 k3，解释额外工作成本。
- 共同优化有帮助但 k3 仍优：报告工程收益，不硬凑 q8 胜利。
- 有限 pilot 中选择改变：只描述这个配置与这四个输入。
- 资格/资源不足：明确没有得出新性能结论。

本轮设计以不分散主线为优先级。论文现有主张可先重构；32B 和 q8 获胜不是进入写作的门槛。
