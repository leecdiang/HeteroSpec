# B570：Llama 显存边界后的前瞻性补测

状态：**设计与静态核验；没有执行本轮 B570 加载、生成或性能实验。**

本方案基于 [PR #86](https://github.com/leecdiang/HeteroSpec/pull/86) 的真实零 forward 记录，回答两个问题：较低余量是否足以让 Q8 目标完成严格验证，以及更适合 10 GB 显存的 Q6 目标能否补齐 Llama 家族证据。它是独立的新研究，不把 #85/#86 的 512 MiB 门槛改判为通过。RTX #84 和此前结果保持各自的合同。

**主路线 STANDARD_Q6**：Llama-3.1-8B-Instruct Q6_K 目标，Llama-3.2-1B-Instruct Q8_0 / Q4_K_M 草稿，保留 512 MiB 余量。**补充路线 TIGHT_Q8**：同一 8B 的 Q8_0 目标，仅 Q4_K_M 草稿，新门槛 128 MiB。二者均先通过实际工作进程的加载、工程峰值、完整提交输出及内存驻留范围核验，再做两个新会话的确认。128 MiB 是受控试验参数，并非 Vulkan 的安全保证；不继续降到 64/0 MiB 寻找能启动的阈值。

Q6 文件比 Q8 文件小 1,944,764,416 bytes（约 1.81 GiB），因此更有机会留下运行空间；这是文件尺寸差，**不是已测 GPU 余量**。目标量化改变普通输出，所以 Q6 的 R/M/C 全部使用同一个 Q6 文件。它可支持“Llama 家族在这个量化和 B570 合同下”的结论，不能证明 Q8/Q6 等输出、全精度等价或所有家族普遍加速。

两条路线在任何新 forward 前共同登记。候选选择只使用曝光工程题；正式确认不要求先观察到正收益。候选合格但较慢也完成确认并公开，避免只有正向配置留下独立会话证据。全部失败、缺失、OOM、时间及搜索成本保留，正式不补跑。

阅读 [事实与研究依据](RESEARCH.md)、[执行协议](PROTOCOL.md)、[POLICY.json](POLICY.json)、[资产 pins](ASSETS.json) 和 [交给 B570 的提示词](EXECUTION_PROMPT.md)。[静态审计工具](../../../scripts/platform/b570_memory_followup_v1/audit.py) 仅复算历史加载余量和检查本方案；不启动模型，不授权生成，不代替 native 实现审核。

本轮以 Llama 为范围，不再次消耗 Qwen 优化预算；Qwen 503.47 MiB 的近门槛观察保留在研究依据中。B570 可独立开始本方案，无需等待 RTX，但须在冻结题目时排除 RTX 已预留题目，并使用 B570 自己的程序、计时和证据。
