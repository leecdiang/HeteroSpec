# 主线重构：从局部布局优化到参考保持的适用边界

**这是论证架构与研究取舍，不是待粘贴进论文的正文。** 来源标识 Sxx/Pxx 见 SOURCE_LOCK/PRIOR_ART。证据截止 2026-10-14 指定提交；E2 最终结果与 E1 均不预设成功。

## 1. 先承认基线已经做到什么

PR102 不是只罗列调试日志。它已经明确：既有 ordinary recipe 定义参考；QB 将 `(d,q,h,1)` 改为 `(d,1,h,q)` 并同步 mask；K/V 共享而非复制为独立序列；phase guard 和 graph reuse 是实现的一部分；PQ/QB、GS/QB、M/C 分开比较；Vulkan 的前沿可能早于 attention。[S01–S06]

因此以下内容**不能列为本轮新贡献**：参考契约、精确算术索引等价、固定输入 replay、phase mask、图缓存身份、局部成本与 draft 收益分离、整份 KV 可改变后缀。这些或已在基线，或已有强近邻研究。

真正新增的是：更好的小效应重现设计及阶段证据；条件性状态子集与同前缀数值证据；坐标重复的实际字节审查；以及将上述证据转化为可验证的适用域，而不是继续将一块 GPU 的成功当成普适。

## 2. 推荐的总问题

> **在必须保持一个已经部署的 greedy 参考、又不能任意改权重/精度/底层 kernel 的条件下，怎样限制必要的局部执行几何，保留其余 batching；这种局部修复在什么状态条件下有效，经济上又何时值得？**

这个问题包含三个需要分别回答的对象：

- **实现对象**：序列内 attention query 的图表示；不是多请求 serving 的统一 padding，也不是新增 draft 算法。
- **适用对象**：进入受控区域的逻辑输入和继承状态；不是把“attention”当成每个后端固定的根因位置。
- **价值对象**：完整、同参考的请求成本；不是 kernel proxy、acceptance、或对不合格参考的速度比。

建议主标题方向：**Preserving a Deployed Reference with Query Layouts: Costs and State-Formation Limits**。另一更简洁的研究问题标题：**When Is Local Numerical Repair Sufficient for Speculative Decoding?** 标题仅供取舍，本 PR 不替换现有标题。

不要命名为“通用确定性引擎”“自动最小修复”“跨硬件一致推理”。这会把论文推入目前尚无实现和证据的竞争领域。

## 3. 三条路线的取舍

| 候选路线 | 正面价值 | 最强审稿挑战 | 判断 |
|---|---|---|---|
| A. QB 实现优化论文 | 干预明确、最接近对照清楚、代码可复用 | PQ→QB 只是小幅图表示优化？ | 保留为技术核心，不能是全部故事 |
| B. KV 干预/机制论文 | 小子集、非单调端点与数值四格有解释力 | Stage-Replay、activation patching 已覆盖大概念；输入只有四个 | 作为支撑，不将论文改成通用 mechanistic interpretability |
| C. 局部修复＋状态条件＋经济性 | 同一设计问题组织 CUDA 正面实现与 Vulkan 状态边界；给出可迁移条件 | 是否只是 A+B 拼接？是否有预测而非事后解释？ | **推荐**；必须用同一干预/状态模型和前瞻验证路线连接 |

C 的实质性来自证据之间的逻辑关系，不是把两篇小故事放在一起：QB 保留外围 batched projection，因此上游 state producer 的数值敏感性恰好决定其边界。B570 不是“另一块卡也成功”，而是说明消费者局部约束不能被假定会修复所有已形成的状态差异。[S03,S05,S09–S12]

## 4. 三项贡献应如何分工

### C1. 可移植的图表示设计，而非新的 arithmetic kernel

保留完整 Q/mask 地址映射、GQA/head mapping、共享 K/V、recombination、counts-off phase guard、graph-cache 拓扑身份，以及拒绝域。把“图表示如何影响数值组织”讲具体；不要仅展示一个 reshape。

**相对外部近邻的差异**：CoRun 控制请求级 prefill/decode 形状；LLM-42 采用额外 verifier/rollback；本方法直接约束量化 target 内部的局部 attention 表示，并保留普通 speculative verification。不同目标/契约并不自动证明我们的速度更好。[P01–P03]

**相对 PR102 的新增证据**：PR104 以新进程短 block 和分离时间块检查 PQ/QB；现有 30 个 session 对比均大于1，但六 session 终值被锁定。E1 完成后才能扩展有限层/phase/q 的数值对应范围。[S08]

### C2. 局部修复与状态形成的条件性关系

将 B570 放进“相同 token 前缀不等于相同可替换状态”的上下文，但明确这个大概念并非首次。新增证据落在固定 Q6_K/F16 KV、实际分段条件下的完整矩阵：小子集足够；扩大子集不保证保留 donor 端点；稳定自然端点的混合状态可能产生第三轨迹；共同前缀的联合分数与可加预测不同。[S09–S11,P05,P07]

将形成前沿、进入 continuation 的状态、决策前沿分开。形成前沿不是已识别的唯一 kernel；数值四格是经过后续计算的净作用，不是自然间接效应分解。

**可验证推论**：移植局部修复前必须检查状态输入及其 producer recipe，而非只看设备名称或输出是否曾经一致。完整的前瞻适用域选择器尚未实现；具体方法见 GENERALIZATION，而不是在贡献中写成已经交付的系统。

### C3. 参考资格、修复成本和 draft 净收益共同决定可部署性

将三组对照固定分工：

| 对照 | 唯一主要职责 |
|---|---|
| PQ/QB | QB 相对另一局部实现的独立增量 |
| GS/PQ 或 GS/QB | 局部约束相对 target 全局串行化保留 batching 的价值 |
| 同一布局 M/C | 完整 draft 协议是否带来净收益 |

PR98 已完成数据可重组为 `D_L=M_L/C_L`。Qwen3 和 Llama 在 GS 下小于1，而 PQ/QB 下大于1；SmolLM2 三者都小于1。这是此前 10月14日审稿已给出的派生结果，本轮只重算与纳入主线，不冒充新发现。[S07]

| 家族 | D_GS | D_PQ | D_QB |
|---|---:|---:|---:|
| Qwen3 | 0.709722 | 1.125119 | 1.143749 |
| SmolLM2 | 0.592110 | 0.616360 | 0.633948 |
| Llama | 0.724339 | 1.107396 | 1.116620 |

PQ 也跨过盈亏边界，不能把该大变化全部归给 QB。由单次成本表的等权对数比恒等式得出，不是 stage time 的因果分解。报告比值的舍入区间也不是统计置信区间。

## 5. 本轮值得新增的三个分析落点

### 5.1 “变化幅度小”不能代替端点资格

PR105 给出的 full-KV 相对 L2（以 A 为参考）排序是：

`1248:0.006488689（自然A/B端点不同） < 1249:0.006748138（相同） < 1011:0.006887112（相同） < 831:0.010452955（不同）`。[S10]

因此，任何“范数超过单一阈值则分歧”的单调二分类规则，都不能完美解释这四个观测。reanalysis.py 枚举了全部五种排序切分。这个反例不需要新 GPU，也不建立一个新风险预测器。它推动解释从总误差大小转向**误差方向、共同前缀下的响应，以及该位置的实际竞争余量**。由于输入有限、既已暴露，不将这条排序结论推广成普遍性能定律。

### 5.2 端点非单调已得到一个真实分数四格的支持

`/1248 B→A, t47, r=220,u=832`：EMPTY/K/V/KV 的分数差分别为 `−0.06651496887207031 / −0.006771087646484375 / +0.021633148193359375 / −0.05448722839355469`。可加 joint 预测 `+0.08137702941894531`，实际 joint 为负，残差 `−0.1358642578125`；全词表 argmax 为 `220/220/832/220`。[S10,S11]

这区分了“离散阈值可能制造端点非单调”和“本四格实际存在净分数非加性”。不能定位残差由哪个 downstream operation 产生。

### 5.3 解释数量必须按依赖去重

44 个历史 repeat-level 四格中，POSITION 有24个定向行，配成12组方向对、覆盖6个 task×position 条件（各两次原进程重复）；另20个 L0 行对应10个定向条件。因此，在原机已通过状态/向量字节映射审查的范围内，规范化后是**16个逻辑四格条件**，而不是44个独立机制发现。仍只有4个独立输入，不能把16作为总体统计样本量。[S11]

`/1248 POSITION t47` 两方向完整残差相同；同一 pair `(220,832)` 下均为 `−0.09655952453613281`。反号来自 token pair 坐标换位，而不是“反方向协同变拮抗”。L0 的 recipient 背景不同，不套用这条去重规则。

## 7. 面向最强反方的回答

**“只是 reshape 优化。”** 用实现义务与公平 PQ 比较回答；若最终效应小，承认它是小但具体的表示增量。不要用对 GS 的大比值转移问题。

**“CoRun 已经做了 phase-specific shape control。”** 同意大概念已被覆盖。差异放在序列内 query/mask 变换、同一量化原栈与原参考、无需新增数值恢复 verifier；未测同契约外部成本，不能声称胜出。

**“Vosti 的保证更强。”** 它对自身 engine 的 schedule invariance 有正式证明。本文不竞争证明强度，而研究保留已有部署参考的低侵入局部实现和实测边界。强不变性不自动蕴含与任意旧 kernel reference 相等；反过来有限 reference equality 也不等于 Vosti 的保证。[P03]

**“B570 和 CUDA 没有真正联起来。”** 这是当前最重要的剩余风险。用统一的局部输入/producer/consumer边界组织现有证据；要主张具有预测力的迁移原则，必须做独立未见条件验证，而不是用旧四个输入重新定义规则再宣布成功。

**“四格非加性已有很多论文。”** 同意。重点是量化部署变化、保持同 token 前缀、连续分数与离散端点的区分、对局部修复边界的具体约束；不是首次发现非线性或 activation patching。[P07,P08]

**“样本很多为何泛化还弱？”** 请求、进程、session、输入和backend不是同一单位。保留4个状态干预输入、2个真实后端但仅1个QB成功实现、6个计划时间块这些事实。资料归档质量不能兑换独立样本量。
