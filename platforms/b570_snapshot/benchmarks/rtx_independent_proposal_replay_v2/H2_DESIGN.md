# Separate P, R and original native L

`engine.py` starts `P.exe` and `R.exe` as separate processes. Both are compiled from worker.cpp with mutually exclusive compile-time role branches. Each loads exactly one model through the original released llama.dll C API. P refuses target role/model; R refuses proposer role/model. The worker rejects unknown input keys, including answer/future-prefix fields. `R_ONLY` starts only R and streams one sealed request at a time. R computes its own pending token, position, accepted prefix, correction and bonus; it does not receive predicted/reference/live arrays. P consumes only the input, its own proposals and the already-produced H2 acceptance feedback. No native speculative CLI invocation occurs in H2.

P prefill keeps the original `draft-simple::process` semantics: logits=nullptr implies last-token output under pinned llama_batch_allocr. Each round resets the top-k-10 draft sampler, decodes the pending token and at most one additional proposal, selects the sorted highest-probability candidate, then deletes generated draft suffix. After R verification, P processes the exact pending/proposal batch with last-row output and deletes the suffix after the retained accepted prefix. It never recomputes the whole prefix. Zero-width rounds perform no draft forward. Native confidence threshold is zero; minimum width zero; requested width is min(2, remaining_budget-1), with adequate context capacity for these inputs.

R performs UB2 prefill and returns the initial greedy target token. The explicit verification batch contains pending plus zero/one/two proposals, consecutive positions, sequence 0 and every logits mask enabled. It samples rows in order, accepts equal proposals, stops at first mismatch or samples a bonus after all acceptance, removes KV after retained count, and saves the last sampled token as pending. Commitment stops at inclusive EOG or 128; sampling/rollback may have computed a longer speculative result before commitment, matching the native process_token boundary. R reference mode uses UB1 and empty proposals.

The orchestration durably appends a digest-linked current P response and fixed target request before R receives that request. Native IPC records include a persisted request event before input is sent and a response event after decode. Full H2 tape and output close before fresh R_ONLY; the independent native L starts after both. Formal reserved L additionally requires remote F2 acknowledgement and sealed-content retrieval.

| Component | Independent implementation | Shared implementation |
|---|---|---|
| Input | Explicit no-tools Qwen3 formatted bytes, one CLI terminal LF removal, empirical native prompt-ID comparisons | Original model vocabulary and C tokenizer |
| P | Separate process, reset/proposal/refresh/rollback orchestration; no target weights/logits/answers | Original model loader, CUDA kernels, C sampler top-k and dist |
| R | Separate process, fixed batch boundary, acceptance/correction/bonus and suffix state machine | Original target model loader, C API decode, temperature-zero and dist sampler |
| R_ONLY | Fresh R context, past-prefix checks, one-row sequential tape consumption | Same R executable and low-level runtime |
| L | Original unmodified CLI/server draft-simple run, no tape import | Entire original released CLI/DLL stack |
| Verification | Independently parses native commits, events, tapes, prefix/rollback and chronology | Standard-library JSON/SHA256 and declared wire serialization only |

R uses the effective CLI greedy sampler. Penalties (repeat=1, frequency/presence=0), DRY multiplier=0, top-n-sigma=-1, top-k=0, typical-p=1, top-p=1, min-p=0 and XTC probability=0 are identities and omitted in R; native suppression IDs are applied, followed by temp=0 and dist seed123. There is no grammar, reasoning budget, user bias or backend target sampler. Both selected IDs and raw top1/top2/proposal scores are retained. The verifier checks selected raw maxima on observed qualification/formal rows; it does not silently assume this when a row differs. The original CLI full printed sampler configuration is retained in native logs. P follows the actual draft-simple sampler (top-k10, default-seed dist, sorted highest probability); the target seed123 is not falsely presented as the draft sampler seed.

Effective context parameters: ctx4096, logical batch2048, target/draft UB2, one sequence, kv_unified=false, 24 generation and batch threads, F16 K/V caches, FA off, full CUDA0 target37/37 and draft29/29 offload, no cross-run prompt cache. R reference UB1. The original common CLI may execute internal context-removal capability probes before the fresh request; new workers do not copy those probes. Qualified equality is empirical on the frozen sample and does not prove all mathematical histories equivalent.

`LLAMA_BATCH_DEBUG=1` is an existing observational upstream switch, with unchanged original CLI/DLL bytes. It records actual tokenizer IDs, logical masks, positions/sequence IDs and physical ubatch splits. Four exposed original on/off pairs establish output semantics for this observation. Worker graph callbacks inspect output and first-layer input dimensions and request no tensor reads. Recorded UB2 output dimensions are actual runtime observations, including [2,1] when present, not an assumed universal partition.

Isolation evidence comprises compiler role separation, explicit allowed input fields, actual model-loader API boundary, successful single-model native offload logs, process commands/PIDs, IPC request history and loaded-module snapshots. These are application/API access records, not an OS-wide filesystem trace or proof against a malicious driver. Every dynamic call is to pinned released DLLs; the experiment does not replace CUDA operators or independently discover a numerical mechanism. Full logits are hashed at sampled rows, but their bytes are omitted; offline score checks cannot authenticate those omitted logits or explore other samplers. Native L full target logits are not published. Limitations are retained even on a matching result.
