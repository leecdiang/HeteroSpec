# Independent acceptance-threshold review: frozen HeteroSpec v0.8.9

**Internal simulated judgment: 4/6 (weak accept). Confidence: 4/5.** This is an independent assessment, not a real committee vote. The paper meets an acceptance threshold for a bounded empirical systems diagnosis. I found no demonstrated P0 validity error in the written central claims. The main reservation is contribution significance and the strength of the tested alternatives, rather than invalid arithmetic or a missing prerequisite to the currently bounded conclusions. I would not give strong acceptance on the present evidence.

The acceptance judgment was formed from the complete current main text (10 body pages plus 2 references), complete 16-page supplement, selected consequential renders, and retained scientific records. I did not read earlier reviewers, meta-review, author closeout conclusions or a global review readout. No manuscript edits, models, GPU experiments, historical capsule downloads or blanket verifier reruns occurred. Visual checking sampled main pages 5 and 7; this is not a full layout audit. The supplied manuscript hashes and revision are in `FIXED_PACKET.json`.

## What supports acceptance

The paper asks a useful question that ordinary correctness gates do not answer: whether a program fixed before native live execution can forecast a complete native output that remains incompatible with a declared reference. It then keeps that question separate from qualification and complete cost. This separation produces actual engineering decisions, rather than making a cheap component or an accurate replay stand in for a speedup.

The most informative B570 evidence is not 72 ostensibly independent successes. It is **24 repeat-stable reserved prompts**, of which **four complete capped trajectories diverge from reference yet are predicted by a draft-free UB1 program**. Three repetitions confirm repeat stability; they do not triple population evidence. The reference reproducer, exposed discovery, deterministic exposure exclusion, hypothesis freeze before reserved inference, and separate array freeze before live collectively support a finite prospective test. Both PDF and appendix make the endpoint and chronology limits visible. Independent array inspection confirms all 72 prediction/live arrays agree. On each of the four distinctive prompts, every aligned ID from the first difference through the 128-ID cap differs from reference. That is a substantial bounded forecast, not merely a repeated first-difference signature.

RTX V4 remedies a real comparison weakness of the earlier V2 study: all five candidate/live conditions now use the same 19 remaining exposure-audited prompts. Equal 51/57 aggregate scores do not hide the fact that UB2 and reference fail on different tasks. Independent array comparisons reproduce both counts and the three-task cross-failure table; replay matches 57/57. Fresh R_ONLY checks target decisions from sealed proposal requests using its own prefix/state rather than copying future live IDs. The manuscript appropriately describes shared numerical routines and application/API separation. This supports a reproducible richer execution description and rejection of the specified capacity-level target-only competitor.

The cost conclusions use separate qualification gates and complete stated timer boundaries. Independent calculations from the retained native QPC fields reproduce RTX serialization's 0.6773510334 GM, 57/57 qualification, 0/19 faster prompts and batched 51/57 failure. The selected cohort, balanced condition order and fresh B executions matter. The conclusion concerns this instrumented post-prefill request boundary, which explicitly includes related logging; it does not claim logging-free production latency.

The 358H accounting adds a decision beyond observing slowdown: under fixed measured progress, target work and baseline totals, even eliminating draft and residual costs cannot reach total-time parity. The original 180 retained processed rows are exactly field-identical to the pinned canonical processed CSV. Independent recomputation reproduces total-time bounds 0.8274529834 CPU and 0.8351858524 NPU, and the original prompt-GM point estimates. A stronger prompt-estimator bound can also be derived from these same records, as described below.

M4's incremental baseline is honest. From all 540 retained held-out timing rows, I reproduce Guard/Always=1.027076022 and Always/two-fixed-mode-oracle=1.000691967. Only 2/60 prompt medians favor target-only over Always. Thus Guard beating target-only does not establish an advantage from control, and frequent fallback does not establish benefit. The paper explicitly labels the incremental contrast and fixed-mode opportunity as post-study, and does not claim that this two-mode oracle bounds arbitrary switching policies.

## Why this does not merit strong acceptance

The distinguishing phenomenon is narrow: four B570 capped reference-divergent prompts on one stack and two RTX reference-divergent prompts within a heavily exposure-conditioned 19-task cohort, with jointly varying backend, OS, hardware and numerical conditions. The experiments are careful, but the contribution is mainly finite predictive discrimination and cost diagnosis, not a portable predictor, repaired decoder or demonstrated improvement.

The successful B570 predictor is a target-only configuration close to the serialized target execution it predicts. RTX's rejected target-only UB2 capacity label is a weaker alternative than a program matched to actual occupied forward shapes and state transitions. Shared replay reproducing native behavior is useful, yet provides limited independence and no minimal representation. The manuscript acknowledges these facts; they still constrain how much scientific explanation the reader gains. A numerical mechanism, stronger candidate family, cross-session/model reach, or an independently implemented predictive description could elevate significance, but these are additional research rather than necessary repairs to today's claims.

The system implications are useful but conditional. RTX cannot support logging-free latency. 358H cannot evaluate altered target execution or measured persistence savings. M4 leaves little fixed-mode opportunity in its measured workload and does not demonstrate control benefit. Consequently I see sufficient evidence for a modest diagnosis paper, not a strong general systems advance.

## Top three changes supported by existing records

**1. Add a prompt-estimator 358H ceiling, explicitly post-study.** For each original prompt/repetition, let B be its matched baseline and T its complete target work. With fixed B, T, progress and nonnegative remaining cost, speedup is at most B/T. Since the median and GM are monotone, the original prompt estimator is bounded by `GM_prompt median_3(B/T)`. The 30-prompt ceilings are **CPU 0.8372192092** and **NPU 0.8448401086**. Zero of the 30 prompt medians per path reaches one. This sharpens the system decision under the same conditions and connects it directly to the headline estimator. The NPU maximum prompt ceiling is 0.9999089575; one individual NPU repetition is above one, so do not claim a uniform per-run margin. No new CI or measurement follows. Inputs: the 180 canonical Phase-3 processed rows; derivation and every prompt bound are preserved in the diagnostic notes/JSON. **Necessary for current claims? No.** Existing total-time arithmetic is correct and accurately scoped. This is the most useful optional addition and could materially strengthen the finite inference.

**2. Quantify the B570 forecast extent on the four distinctive trajectories.** The four first differences leave 40, 55, 25 and 35 IDs through cap, respectively. All these aligned positions differ from reference while predictor equals live: **155 distinct non-reference predicted positions, including 151 strictly later than the first differing ID**. Present this as extent on four capped prompt trajectories; retain 24 prompt units and three repeat-stability runs, rather than a token-level or 72-independent-sample inference. Inputs: complete original H1 reference/prediction/live arrays and the fixed cap. **Necessary for current claims? No.** The complete-array claim is already supported. This addition makes the advantage over a first-difference signature concrete and its capped reach easy to judge.

**3. Make RTX failure extent as explicit as failure membership.** Retained arrays show /25 is a one-ID UB2 failure followed by reconvergence; /15 has identical UB1/UB2 arrays that both miss live, including a 28-versus-25 endpoint; /18 matches UB2 but not the 72-ID reference versus 69-ID live. A retrospective choice between the two already measured target-only full arrays covers 18/19 prompts, still missing /15. This is a compact stronger statement about these two candidates, not an implementable predictor or proof that all target-only programs fail. Inputs: all 285 V4 A condition arrays and inclusive endpoint lengths; no cohort changes. **Necessary for current claims? No.** Table 2's same-set count/cross-failure conclusions are already valid. This characterization helps readers assess how much the richer description adds and avoids treating all complete-array failures as equally extensive.

Reasonable record analysis can therefore improve precision and strengthen the conditional 358H inference. It cannot identify a unique kernel cause, turn a persistent continuation into a single-block intervention, estimate instrumentation-free cost, prove arbitrary history necessity, or demonstrate unmeasured persistence/policy gains. Those would require new experimental contrasts. I would not condition acceptance on those extensions.
