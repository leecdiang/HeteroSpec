## What the study currently establishes

The latest manuscript anchor is PR222 at
`e8a4981ef7db8f05cff7144fd4edc6e5a4109343`, read after the user's new review.
Its scientific line is reference-compatible parallel execution for quantized
inference. PR218 still exposes the earlier S3 preparation head, without a new
completed public S3 result. The follow-up priorities are now explicit: close
that strong service comparison, specify recipe/guard evidence, then measure
same-panel costs and length-stratified opportunities before broad model sweeps.

The mainline manuscript already separates a reference-compatible speculative
application from the small incremental effects of packing and local cuts. At
k3, four-row verification does not enter wide Q8 packing. Ordinary longer
drafting changes both target and draft work, so an equal-work q8 advantage is
not a live-request advantage.

The remaining research candidate is **reference-compatible frontier scheduling**:
choose between genuinely legal, reachable execution frontiers using causal
observations and complete execution/reconciliation costs. The name is a working
description. A Bellman model, a cost table, adaptive length, or stronger evidence
admission alone is not a novel decoding mechanism.

Recomputed historical B2 data contain local q8 reductions of about 0.96%,
2.19%, 6.30% and 5.24% in the four cells. Under a fixed-operation, representative
ratio, unchanged-other-work and zero-overhead illustration, the two packed
cells would require 79.35% and 95.36% coverage of baseline service to produce a
5% service reduction. These are conditional arithmetic, not observed coverage,
forecasts or transferable GPU costs. The same analysis retains the old RTX
phase fractions separately. See [the replay](research/economic_review.py),
[results](research/EXPOSED_PANEL_ECONOMICS.json), and
[independent arithmetic audit](review/ECONOMICS_AUDIT.json).

## What is actually implemented

### Cost admission and causal control

The old raw replay helper is preserved as a diagnostic tool. Five deliberately
modified copies of its genuine q1 CPU evidence demonstrate why that PASS must
not be promoted to controller admission: altered history, failed RUN, altered
model identity, incomplete repeats and missing actual modules. No wide costs or
new measurements were fabricated.

The new [cost reader](controller/cost_admission_v2.py) requires a trusted external
RUN pin, complete record coverage, successful execution, explicit source/model/
binary/library assets and actual loaded-module agreement. It validates the
original CPU run as a diagnostic while refusing it as deployment cost.

Even a future valid old-profile CUDA measurement is typed as a capture-conditioned
**target-operation macro**, not a clean resident stage cost. The new
[causal policy](controller/causal_policy.py) consequently admits no real stage
catalog and abstains. Its nontrivial decisions are tested with an explicitly
synthetic provider. The prototype accounts for first rejection and censored
suffixes, terminal materialization, state convergence, paid draft work and
controller overhead. It is a finite-episode surrogate, not a whole-request
optimality claim.

A new predict-before-observe diagnostic also replays 287 actual logged k7 cycles
from sixteen exposed roots. Its position-wise Beta first-four-match forecast
has Brier 0.25757 versus 0.25185 for a simpler past-only first-four-frequency
control on the same 281 observed labels; six terminal suffixes are censored.
This fixed diagnostic does not favor the position model. It evaluates neither
new requests nor alternative actions and makes no latency claim. The recurrence
also assumes equal logical frontiers have converged to equal cost-relevant
states; actual graph/cache equivalence is not certified by this synthetic
model. See the [controller notes](controller/README.md) for the evidence and
remaining model assumptions.

The q1 reference in the old width probe is a diagnostic reference. It has not
been bridged to the historical paper R. Its CPU q2 failure does not rule out
every q4/q8 transformation; future stage qualification must start from the
declared original reference's actual deployed path.

### Original production entry

The new module compiles the original guarded M2 entry with eager/deferred arms.
Two clean binaries match the previously built original-entry binaries byte for
byte. Two additional capture binaries use read-only link observers for the
otherwise missing draft sequence/geometry observations. The numerical source
and original entry/worker remain unchanged.

All four binaries were linked locally and **none was executed**. The new
production plan is two full original prompts, k7, cap16, one capture pair and
two clean pairs. Its ceiling is six processes, twelve requests and twelve
context creations, with target/draft API and physical work separately bounded.
It is a finite implementation diagnostic, not the old cap96 panel or a new
performance confirmation set. Complete budgets and commands are in the module
README.

Historical-R qualification and the full-vector/state bridge from capture to
clean execution remain open. `performance_admitted` stays false, including
when an offline diagnostic or clean endpoint check succeeds.

## What was not measured

This continuation made **zero new model executions and zero GPU executions**.
Local work consists of source-bound compilation, host-only protocol/policy
tests, offline replay of existing evidence, adversarial copies, and independent
historical arithmetic. No real resident stage cost is available. No approximately
5% service gain, broad generality, stochastic-decoding guarantee or new-method
novelty is claimed.

The new source is an isolated research addition. The original paper, S3 plan,
past raw evidence and existing 45 files are preserved. The next GPU experiments
require their own committed run identity, the fixed real model files, and an
assigned idle physical non-GPU0 device. This release has no remote host endpoint
and did not launch work on another person's device.

## Decision after the next measurements

First determine whether legal alternative frontiers have enough net cost
difference after state repair and control. If not, stop this single-request
controller direction. If the difference exists, compare against short lazy
drafting and ordinary cost-aware adaptation with the same engineering fixes.
Only then freeze a causal policy for new inputs and run the controller × executor
attribution study.

The target is a reduction of about 5% in the complete resident worker request
window relative to a development-selected strong baseline. The confirmatory
panel must retain fallback, failures and negative configurations. New model
families and hardware/backend configurations require their own qualification;
they cannot inherit numerical legality from a different deployment.
