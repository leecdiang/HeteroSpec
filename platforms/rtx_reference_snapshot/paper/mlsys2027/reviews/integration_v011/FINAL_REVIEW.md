2026-10-05。审阅对象：覆盖 PR #53–56、承接既有历史结果的匿名 v0.11.0 主文和附录。主文 10 页正文 + 2 页参考文献，附录 27 页。作者侧单一审阅，包括正文逻辑、数值复算、引用与视觉检查；不是独立外部同行评审。

**结论：这是一篇完整且更可信的系统实证论文，但仅靠本版本的贡献，MLSys 方法创新门槛仍难通过。** 内部六档总体判断约为 3/6（weak reject），用于说明当前证据与贡献之间的差距，不是实际评审分数或接受概率。该判断不覆盖新出现的 #59/#60 方法候选，详见 [最新研究评估](LATEST_RESEARCH_REVIEW.md)。用户要求暂停后续合并，因此本稿仅作为可复核的基线 Draft。

## 论文现在实际支持什么

完整轨迹和端点应先于性能比较；受控干预可以验证一个有限程序对原生输出的预测，但“复现自己的路径”不代表恢复共同参考；普通原生重执行可能完成复杂预测器的输出目标；没有恢复与成本优势的离线选择器不能升级为通用诊断方法。历史 RTX、358H、M4 的负结果分别保留各自数值合同、任务和计时边界。

B570 四个偏离任务恢复且20控制保留，支持暴露任务上的成功干预；RTX /15 恢复、/25 新偏离、/18 仍偏离，拒绝了恢复且无新回归的主张。新 bridge 的普通 U2 在 19/19 任务与干预 N1 完整输出和边界一致，但与历史参考仅17/19一致。离线 selector 没有提供已测成本优势；MBPP U2 仍是未知项。这个叙事比把每个成功复现都包装成新方法更清楚。

## 主要优点

- 比较目标和端点明确，包含完整 ID 数组、EOS/上限、未提交样本及 B570 原始 cap 后缀的区别。
- 既报告恢复，也报告新偏差、不恢复和选择失败。没有把三次稳定重复当作三倍任务样本，也没有把重叠的两个1005分母相加。
- 将新的干预与旧成本分开。没有用 historical serialization 的时间给 bridge 或 selector 定价。
- 匿名证据包保留旧包的确切字节，CPU 验证原算术、完整 exports、收费查询策略和10项已有测试；文档可从 portable ZIP 独立重建。
- 新的 bridge 图直接呈现参考、基线和普通方法的关系，正文移除重复表，复杂任务级证据放附录。

## 仍会导致拒稿的关键问题

1. **独立新颖性偏弱。** 受控执行描述、预测/原生一致、简单 baseline 反证和成本负结果组合有实证价值，但尚未产生可迁移的新推断/修复方法。数值非结合、batch 几何与确定性之间的关系已有接近工作。
2. **任务和配置有限。** 主要诊断都是暴露的任务；有限 greedy、Q8_0、单上下文结果不支持跨模型/后端无损性，也不支持 logits 位级等价。
3. **历史子研究不能形成一张统一收益表。** RTX 的 post-prefill、358H 的假设上界、M4 的固定机会不对应同一 estimand。正文已解释，但读者仍需理解多份合同，贡献密度会受影响。
4. **可复核范围有限。** exports 和 source hashes 有价值，仍不能认证未包含的模型/runtime bytes、独立绝对时间或把本地 seal chronology 升级成可信第三方时间戳。这里没有重做 GPU 或取回所有 raw archive。
5. **普通基线消解了预测器必要性。** bridge 上 U2=N1，离线查询结果没有证明泛化选择器优于直接验证；不能继续把这些结果当作更便宜的 execution minimization。

## 需要避免的审稿误读

“lossless”须指明对哪个参考以及哪个端点；同路径 reproduction 与 reference repair 要分开。“causal”最多限于所测干预和自然对齐控制，不写唯一 kernel 根因。单次全轨迹相同不能证明下一配置也相同。速度比必须明确先算逐任务中位数比再取 GM，不能拿 pooled throughput 替换。M4 Guard 的相对 Always-Spec 收益不成立，不写成控制器改进。

本稿已经将三种合同比较、普通 baseline、失败 gate 与 unknown 项纳入主文。没有值得为了包装而隐藏的负结果。真正提高下一版预期，应依赖 #59/#60 后续固定配方的迁移与强对照，而不是继续扩写本稿动机。
