# Prospective host wiring and numerical boundary

Design: PR141 head `03cc11662f0ff21514efd40e9a09d4c7e1d2c672`.
Reference: PR134 `51febaddcf49bb18565e568cf964a6e5c78876c9`.
Request implementation: PR135 attempt2 at `e44c4df04c895b55ef734ee7b0659189158f95ab`.

`closeout.cpp` derives from the actual qualified attempt2 host. The request algorithm, context parameters, target layout selection, numerical DLLs, synchronized decode helper, native sampling, pending seed, KV trimming, output cap and stop logic are retained. `bulk_prefill` is selected before constructing each fresh context. Only SUBMIT sets it. BASE_A and BASE_B call the same QB/thread8 branch. R creates only a target context while both model weights remain resident. No target prefill change, CPU1, shader rebuild or persistent context is introduced.

The intervention already present in PR135 is the single `bulk_prefill` conditional: one logical prompt decode instead of one decode plus synchronization per token. Draft physical n_ubatch stays 1; final-token logits only, consecutive positions and sequence 0 are unchanged. All five copied numerical DLLs must match PR134 and PR135 bytes. Models are rehashed, including tokenizer metadata inside the original GGUF files; the native startup also compares vocabulary text/EOG semantics across both models.

`request_observer_diff.patch` is the complete change to the inherited request prefix. It adds capture-only ordered QK source/shape observations, mask tensor metadata, prefill KV endpoints and an exact prompt_length * 28 layer count. Every consumed draft QK MUL_MAT must have query axis 1 equal to 1. E0/E1 require BASE and SUBMIT's full ordered metadata sequence to match. The current mask values are not copied from GPU memory: unchanged causal mask construction is checked in the retained source, input positions are explicit, mask/key shapes and state endpoints are compared, and all applicable historical full logits remain a mandatory byte gate. This is finite executed-path evidence, not a proof for untested inputs or every possible internal mask value.

The new main implements only the registered E0/E1/E2 matrix and historical comparisons. E0 uses the original /42 cap16 bridge, BASE/SUBMIT capture/count. E1 runs R/BASE/SUBMIT capture/count for each original cap64 input. E2 consumes the unchanged PR141 toolkit order: 4 processes, 4 inputs, 4 arms, each with an immediately preceding arm/input-matched warmup. The numerical body cannot switch policy under an existing context or graph cache. No automatic retry is implemented.

Primary service starts before the inherited request call and ends after its local contexts are destroyed. This includes its environment selection, fresh context/graph reservation, both prefills, generation, native sampling, cycle JSON construction, state handling, synchronization and teardown. Model load is separate. Reference/byte comparison and result-file output follow the timer. Per-decode clocks/synchronization are inherited and charged identically. The callback and raw file output are installed only for capture, never count/warmup/measured requests. The record explicitly reports observer installation.

`run.py` rehashes frozen inputs before every worker, rejects concurrent known model workers and reused destinations, records STARTING/RUNNING before waiting, and contains the native executable in a Windows kill-on-close Job Object with one active process and a finite memory limit. It retains actual wall charge, exit/cleanup status and a fixed whole-process timeout. The compiled host contains no child-process launch. An unknown identity, drift, safety/resource pressure or any native failure ends the study without repair. `audit.py` independently reads raw records and vectors, checks full endpoint/cycle equality and physical-q evidence, then independently reconstructs the full normalized panel and cross-checks PR141's estimator.

All native work remains unstarted at the code/manifest freeze. The source/manifest freeze commit precedes the finalized registration commit, avoiding a self-referential Git hash. Every process receipt binds the final registration-containing commit supplied as `--freeze`; the registration also points to its prior source/manifest checkpoint. Frozen hashes bind the exact external executable and assets; executable/DLL/model bytes are not committed.

Historical accounting is preserved rather than repaired: PR135 attempt2 time-0 has a complete receipt; time-1 contains 3 warmups and 2 measured records but no exit/process receipt. Its full parent wall charge and cleanup remain unknown. New UUID, budgets, slots and costs do not complete or pool with that history. The known 81.3101785 seconds of partial service is a lower-bound window, not an inferred process charge.
