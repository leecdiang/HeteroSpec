JSA 首投：代码与数据审稿访问方案
2026-10-13；对应论文 v0.15.3；暂按 Chengzhan Li 单作者准备。

当前状态
仓库 leecdiang/HeteroSpec 已核实为 private，已按作者授权添加自有代码 MIT、自有数据 CC BY 4.0 及第三方范围说明。作者授权创建 Zenodo 未公开草稿供只读审稿，未授权公开。草稿访问不代表已完成 JSA 数据政策。发布状态与实际包清点见 review_access/ACCESS_STATUS.json。

准备的交付层次

A. 无 GPU 的复核包：output/JSA_v0153_review_core.zip
包括正文/补充 PDF、图表数据与可编辑图源、论点和证据对应表、来自固定提交的原报告和以独立文件保存在仓库中的实验脚本、离线校验入口。审稿人拿到包后可直接读文件及复算报告中的值，不需要访问私有 GitHub。报告复算不能替代原始记录审计。

B. 固定版本原生源码包：output/JSA_v0153_native_source.zip
从 PR98 的 SOURCE_RUNTIME_V02 胶囊按 SHA256 校验后提取 native/source，保留上游版权/许可证；不把预编译程序、GPU DLL 或模型权重混入该源码包。包含本轮逐文件校验清单。该包可用于审查实现，完整硬件复现实验仍需记录的运行栈与模型。

C. 完整原始证据与运行胶囊
SOURCE_ACCESS_INVENTORY.json 逐文件记录固定提交、原路径、字节数和 Git blob 身份，区分实际已获取与仅清点的文件。核心来源是 PR91/94、PR98、PR92/93、PR97、PR99、PR101。六组原始档共 1,646,803,532 字节、638 个分片，已全部恢复并校验 52,925 个逻辑文件路径；总数包含继承副本。PR101 的 675,012,404 字节归档也已完成原始记录复算。逐组结果及边界见 RAW_RESTORE_VERIFICATION.json、RAW_SCIENTIFIC_AUDIT.json 和 RAW_RESTORATION_REPORT_ZH.txt。未重跑 GPU 或重算外部模型权重；大档仍与轻量复核包分开保留，按已确认方案上传至未公开数据草稿。

D. 模型与第三方材料
提供 MODEL_ACCESS.json：精确 GGUF 名称、文件长度、SHA256、可查的发布者固定版本、获取地址及待补项。审稿人从原发布方取得权重并遵守其条款；不能用同名或重新量化的文件冒充所测字节。官方基础模型到第三方转换产物的完整谱系未被原记录认证，这一边界保留。

建议的存放方案
优先把经过权利确认的代码与支撑数据整理为独立版本存档，使用 Zenodo 等适当研究仓库，分别记录代码许可和数据许可，不公开整个工作仓库历史。正式发布后取得真实版本 DOI，回填论文的数据/代码声明及引用。JSA 的保存指南采用 Option C：存档并引用/链接；无法共享时说明真实原因。

按作者已确认的方案，在 Zenodo 草稿中上传并创建 Can preview draft 链接，供编辑/审稿人读文件。这个链接须在未登录状态实际验证；不能用作者自己的 GitHub 访问成功作为验收。草稿访问是评审阶段安排，不自动等于 Option C 已完成或 DOI 已注册。若要保留限制，需要有真实理由并确认期刊接受该安排。

链接权限应只读，不授予编辑权限，建议在评审期间不自动失效。Zenodo 的分享权限覆盖同一记录的当前及后续版本，因此每次更新都应重新检查范围；把访问令牌只放投稿系统的保密栏，不写进将公开的稿件或 GitHub。已发布记录的元数据公开，即使文件受限；草稿和发布是不同状态。

完成顺序与验收
1. 已确认 MIT / CC BY 4.0、Zenodo 未公开草稿和只读访问。第三方原许可保留；机构/公司确有具体限制时由作者补充。
2. 六组主要原始归档及其内嵌源/运行材料已完成恢复和核验；发布前按实际许可复查要分享的范围，保留失败控制与完整来源映射。
3. 在存档记录中上传固定版本文件，填写作者、标题、版本、说明、许可和与论文的关联，生成真实访问方式。
4. 从未登录环境下载两个核心包及选定原始档，核对下载哈希，执行离线复核；记录访问日期、是否需要账号及所有限制。
5. 用实际可访问的位置更新论文声明与数据引用，再核对提交系统。没有实际地址之前，DATA_AVAILABILITY_DRAFT.txt 保持待启用文本，不替换成已存档的完成式声明。

许可证、平台和当前访问方式已确认；个人声明仍待补充，模型/文件版本等能从记录查到的事项由我们整理，不要求作者重新查一遍。

本地材料重建入口（作者侧，需已有私有 GitHub 读取权限）
先运行 scripts/prepare_review_access.py --fetch 获取报告和源文本，再运行 scripts/prepare_native_review_source.py --download 校验并提取固定源码胶囊，最后运行 scripts/package_review_access.py 生成两个包并做解压验证。这些步骤不会发布、发送、下载模型或运行 GPU 实验；原始大档需另按 RAW_ARCHIVE_ACCESS.json 获取。审稿人的离线入口在各包内，不需要作者的 GitHub 凭据。
