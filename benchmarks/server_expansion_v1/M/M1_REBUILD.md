`build_native.py` verifies the complete predecessor compiler dependency closures
and both source trees, copies the original frontend into a new directory, adds
`native/capability.hpp`, and compiles/links one new frontend per projection. The
numerical static archives are reused read-only from the original complete CUDA
builds. Every inherited source/object/archive and new frontend/header/object/link
map remains in the new dependency closure. No numerical or transaction arithmetic
is edited; M1 still has reserve4, k3 and draft UB4. This is explicitly an observer
relink, not a claim that CUDA was compiled again for M1.

The native gate hashes both actual model files, inspects real context parameters,
model structure and per-layer/output GPU placement, and binds the compiled
projection role and runtime cut. It compares the entire versioned capability
request before any input request. Unknown top-level fields and mismatched or
extra capability fields fail. Requested masks and physical rows are subsequently
checked from actual per-call execution records and full-vector/transaction proofs.
Native hashing is startup work and is included in worker/burst startup clocks;
it is outside resident request service. Supervisor preflight hashing is captured
by M1's separate inclusive `adapter_run_inclusive_s` clock.

are generated by that same frozen independent R in fresh M1 paths. Candidate
values are never used as reference. These are finite checks, not a general proof.
